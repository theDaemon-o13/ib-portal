# ADR-0046. Файл письма .eml: тип message/rfc822 только от сервера

Дата: 06.11.2026. Статус: принято (релиз 1.12.0; план — `docs/plans/release-1.12.0.md`, раздел 6).

## Контекст

В «Рассылках» нужно доказательство: какое письмо отправили. Типа `.eml` нет среди разрешённых (CLAUDE.md, 3.7). Альтернатива — хранить только sha256 и пересобирать файл из замороженного письма. Она не работает: макет и «Оформление писем» меняются, и пересборка не даст тех же байтов.

## Решение

- Хранить сам файл. Тип `message/rfc822` допускается в `files` (ограничение `files_mime_check`, миграция `awareness_eml_mime`), но создаёт такие файлы **только сервер**: выгрузка письма и отметка «Отправлено». `POST /files` `.eml` не принимает — список типов для загрузки (`lib/file-type.ts`) не меняется.
- Выдача — общий маршрут `/files/:id/content`: всегда `attachment`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`. Предпросмотра у этого типа нет.
- Доступ — по ссылкам на файл: поле «Файл письма» записи «Рассылок» и выгрузка письма — только с `ib.work`. Служебная учётная запись — 403, читатель документов — 404.
- «Отметить отправленным» берёт последнюю выгрузку этой версии с этими языками или собирает файл в момент отметки. Тот же файл привязывается к записи «Рассылок» и к событию `sent`.
- Повторная выгрузка отправленного письма на языке отправки отдаёт отправленный файл.

## Последствия

- Отправленное письмо — неизменный файл с sha256, видимый в «Рассылках» и выгрузке Excel (имя и sha256).
- Откат на 1.11.0: такие файлы отдаются как любые — вложением, без предпросмотра.
