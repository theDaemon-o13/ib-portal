# ADR-0021. Журнал и история — просмотр по правам

Дата: 29.10.2026. Статус: принято (релиз 1.2.0, этапы А3 и А4).

## Контекст
До 1.2.0 журнал аудита был виден по частям всем сотрудникам ИБ: история в карточках задач, записей, доказательств и документов, «Настройки → Журнал изменений». Владелец решил: журналы и историю видят только те, кому это поручено, а все действия пользователей собраны в одном разделе.

## Решение
- Два раздельных права: **`audit.view`** — раздел «Журнал» (все действия всех пользователей, входы, IP); **`history.view`** — история изменений в карточках одного объекта. Руководителю группы может быть нужна история задач без журнала входов.
- **Раздел «Журнал»** (`/audit`, пункт меню по `audit.view`, `ib.work` не нужен): `GET /api/v1/audit` с фильтрами — период, пользователь (включая «Система»), действие, раздел (несколько `entity` через запятую; «Настройки — всё» заменяет прежнюю вкладку), IP (начало адреса), поиск по фразе, логину, ФИО и ID объекта; курсор по `id`, новые сверху. `GET /audit/facets` — значения для фильтров из самого журнала. Без права — 403, пункта меню нет, прямой адрес уводит в доступный раздел.
- **Переход к объекту**: задача, запись реестра, документ, доказательство, поле, значение списка, автоматизация, справочник — ссылка на карточку или вкладку; удалённый объект — без ссылки, «объект удалён»; пользователи, роли, календарь, шаблоны, слайды, дашборд — ссылка на страницу раздела.
- **Выгрузка в Excel** (`GET /audit/export`): те же фильтры, до 100 000 строк; больше — отказ «По фильтру N записей… Сузьте период» (409 `TOO_MANY_ROWS`), без молчаливой обрезки. Время — в часовом поясе банка. Сама выгрузка пишется в журнал (`audit.exported`, фильтр и число строк).
- **Подписи** действий и разделов — `modules/audit/labels.ts` (русские названия, род согласуется); коды в `audit_log` не меняются, неизвестный код показывается как есть. Тест проверяет подписи для всех кодов, которые пишет код.
- **Журнал не меняется** (CLAUDE.md, раздел 3.5): раздел только читает. Паролей и хешей в журнале нет — проверено тестом на создании пользователя, первом входе, смене, неудачных входе и смене, сбросе; дополнительно ключи `password*`, `*hash*`, `token`, `secret` вырезаются из подробностей при выдаче.
- **История в карточках** — по `history.view` (этап А4). Комментарии к задаче и комментарии переходов статуса — не история, их видят все, кто видит задачу. В документе блок «кто какой этап согласовал» видят все, кто видит документ; подробная история — по `history.view`. Замечание последнего возврата показанной версии — часть текущего состояния маршрута, а не история: блок «Возвращён на доработку» (кто, когда, с какого этапа, замечание) видят все, кто видит документ, иначе автор без права не узнал бы причину возврата. Журналы автоматизаций в конструкторе реестров — рабочие таблицы правил, остаются по `registers.manage`.
- `GET /settings/journal` оставлен для совместимости, право — `audit.view`; вкладка в настройках убрана, `/settings/journal` ведёт в «Журнал».

## Последствия
- Миграция `audit_log_user_index`: индекс `(user_id, at)` для фильтра по пользователю.
- Сотрудники ИБ без `history.view` перестают видеть историю карточек (решение владельца: по умолчанию её видят «Начальник ИБ» и «Супер-администратор»).
- Поиск по фразе — `ILIKE` по `diff->>'summary'`; при росте журнала до миллионов строк понадобится полнотекстовый индекс.
