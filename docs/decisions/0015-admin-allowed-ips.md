# ADR-0015. Вход администраторов только с рабочих мест (ADMIN_ALLOWED_IPS)

Дата: 28.10.2026. Статус: принято (подготовка к выкладке 1.0.0).

## Контекст
MFA для привилегированных учётных записей отклонена (ADR-0006, решение владельца проекта 28.10.2026: портал работает только во внутренней сети). Инструкция банка по парольной защите требует MFA для привилегированных УЗ, поэтому нужна компенсирующая мера: украденный пароль администратора не должен открывать администрирование с любого компьютера сети.

## Решение
- Привилегированные учётные записи — пользователи с правом `settings.manage` или `users.manage` (`ADMIN_PERMISSIONS` в `lib/permissions.ts`), от любой из ролей.
- Переменная `ADMIN_ALLOWED_IPS` — IP-адреса и подсети через запятую (тот же разбор, что у `MONITOR_ALLOWED_IPS`, `net.BlockList`). Ошибка в списке останавливает backend при старте. **Пусто — без ограничения.**
- **Вход:** пароль проверяется как обычно; если пользователь привилегированный, а адрес не из списка — отказ во входе целиком (не вход с урезанными правами). Ответ — как на неверный пароль: иначе с любого ПК можно проверять, верен ли пароль администратора. Счётчик неудачных попыток не растёт (пароль верный). В журнал аудита — `auth.login_failed`, причина `admin_ip_denied`.
- **Каждый запрос:** права пересчитываются из ролей на каждом запросе. Если у пользователя сессии есть привилегированное право, а адрес не из списка — сессия закрывается насовсем, в журнал `auth.admin_ip_denied`. Так закрывается и случай, когда права администратора выдали уже вошедшему пользователю с другого компьютера.
- Адрес клиента — тот же, что для киоска: `X-Forwarded-For` принимается только от `TRUSTED_PROXY_IPS` (nginx), подделка заголовка с ПК не помогает (ADR-0012).
- **Восстановление:** `create-admin` запускается из консоли сервера (`docker compose run --rm backend node dist/scripts/create-admin.js`) и не проверяет адреса — так заводится администратор, если доступ потерян. Входить новый администратор будет тоже с адресов из списка; если ошибся сам список — исправить `ADMIN_ALLOWED_IPS` в `.env` (или очистить) и выполнить `docker compose up -d backend`. Оба способа требуют доступа к консоли сервера, то есть остаются у DevOps.

## Последствия
- Новая переменная `.env` и строка в `deploy/docker-compose.yml` (согласовано 28.10.2026). При выкладке 1.0.0 DevOps заполняет её адресами рабочих мест администраторов портала; пустое значение допустимо, но тогда компенсирующей меры нет — это отмечается в форме «Парольная защита».
- Настенный монитор не затронут: у него только `monitor.kiosk` (ADR-0012).
- Если у администратора меняется адрес рабочего места (DHCP), он не войдёт до правки списка: рабочим местам администраторов нужны постоянные адреса или выделенная подсеть.
