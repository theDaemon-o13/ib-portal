# ADR-0044. Макет письма в коде, содержимое в базе

Дата: 06.11.2026. Статус: принято (релиз 1.12.0; план — `docs/plans/release-1.12.0.md`; задание — `docs/tasks/1.12.0-awareness.md`).

## Контекст

Учебное письмо уходит одним письмом на двух языках. У каждой части своя карточка: тёмно-синяя шапка с логотипом, заголовок, метка, обращение, абзацы, выделенные блоки, подпись, подвал. До 1.12.0 письмо собирали вручную в Outlook (Word-вёрстка). Выгрузка 1.9.0 давала «RU, затем TJ с разделителем» без оформления. Почтовые клиенты (Outlook на движке Word, веб-почта WorldClient, телефоны) понимают только таблицы и inline-стили.

## Решение

- **Оформление — код backend** (`modules/awareness-letters/export/layout.ts`, `content.ts`, `mail.ts`). Письмо и шаблон хранят только содержимое (HTML редактора после санитайзера) и простые поля шапки: «Заголовок», «Метка» RU/TJ, «Тема общая». Макет накладывается при предпросмотре, выгрузке `.eml` и «Скопировать с оформлением» — одной функцией. Поэтому предпросмотр показывает ровно то, что уйдёт в файл.
- **Вёрстка — по эталону `docs/email/layout-reference.html`.**
    - Карточка 600 px (`width`, `max-width`, условная таблица для Outlook), до 620 px — на всю ширину. Arial 15/23.
    - Выделенный блок — таблица с полосой 4 px.
    - Логотип — один Content-ID на обе карточки, скрытый прехедер.
    - Отклонения: отступы — `margin`/`padding` вместо строк-распорок `&nbsp;`; в предпросмотре и буфере изображения `data:`.
- **«Оформление писем»** — одна строка `awareness_layout`: логотип (внешний ключ на `files`, его учитывает `file_active_refs()`), название отдела, адрес ИБ, прощание, подвал, метки по типу письма, подсказка о таджикском тексте. Меняют `settings.manage` + `ib.work`. Seed — заглушки без данных банка.
- **Подпись макета** выводится всегда. Исключения, чтобы письма 1.9.0 не получили двойную подпись:
    - в тексте есть блок «Подпись ИБ» (или подпись, подставленная при отправке с пометкой `signature-sent`);
    - это отправленная версия 1.9.0.
- **Смена макета** в будущих релизах меняет вид только неотправленных писем. Отправленное письмо хранит отправленный файл `.eml` (ADR-0046).
- **Предпросмотр** — отдельный документ от backend со своим CSP: `sandbox; default-src 'none'; img-src data:; style-src 'unsafe-inline'; frame-ancestors 'self'`. Он показывается в `iframe sandbox` портала. `srcdoc` и `blob:` не подходят: они наследуют CSP страницы портала (`style-src 'self'`), и стили письма не применились бы. Несохранённое содержимое передаётся одноразовым ключом в памяти backend: 10 минут, только тот же пользователь.

## Последствия

- Вид писем меняется релизом и проверяется тестами (снимок результата, обе карточки, логотип), без правки данных.
- Ручные правки вёрстки в письме невозможны: в редакторе только белый список санитайзера и выделенный блок.
- Проверку в реальных клиентах (Outlook классический и новый, WorldClient, тёмная тема) владелец делает по чек-листу руководства.
