# ADR-0033. Мягкое удаление реестров, групп и узлов уязвимостей, записей; корзина

Дата: 02.11.2026. Статус: принято (релиз 1.6.1, `docs/plans/release-1.6.1.md`, раздел 2).

## Контекст
После переноса записей владелец не может убрать временную группу «Без группы». Ненужные группы, типы систем, записи и реестры тоже не удаляются. Удаления групп и узлов не было (ADR-0029), реестр можно было только отправить в архив. Записи удалялись мягко, но без причины и без возможности восстановления.

Данные банка важнее удобства (CLAUDE.md, раздел 3). Поэтому физического удаления и каскадного стирания нет. Связанные сканы, файлы, история и продления остаются в базе.

## Решение
- **Удаление — событие.** Строка `deletions` хранит, что удалено (реестр, группа, узел или записи), кто и когда удалил, причину и `counts` — сколько скрыто. Для записей уязвимостей добавляется `snapshot`: статус, «открыта ли», итоговый срок и узел каждой записи на момент удаления. Событие не меняется (триггер `deletions_guard`), строку нельзя удалить. Отметка о восстановлении ставится один раз.
- **Всё скрытое удалением получает `deletion_id`** события: `registers`, `vuln_groups`, `vuln_nodes` (у них появились `deleted_at` и `deletion_id`), `register_records` и `register_automations` (у них только `deletion_id`). Восстановление снимает отметку ровно с этих строк. То, что удалили раньше и отдельно, остаётся удалённым. Сканы не меняются (их защищает триггер), они скрыты вместе с узлом.
- **Название удалённого не занято.** Уникальные индексы названий реестров и групп, а также «тип в группе», теперь частичные: `WHERE deleted_at IS NULL`. Системные реестр, группа и узел не удаляются, это закреплено CHECK в базе.
- **Право `data.delete` «Удаление данных»** — на реестры, группы, типы систем и записи уязвимостей. Удаление открытой записи снимает её с просрочек и эскалаций п. 7.4, поэтому для этого нужно отдельное право. Никому не выдаётся автоматически. Записи остальных реестров удаляются по `records.delete`, как раньше.
- **Условия удаления:**
    - группа и узел — только без открытых записей (не закрытый статус и не архив); иначе 409 со списком узлов;
    - реестр — только пользовательский и только если на него не ссылаются поля-связи других реестров;
    - для реестра и группы название вводится для подтверждения;
    - причина обязательна: у объектов — текстом, у записей — из списка («Ошибочный импорт», «Ложное срабатывание» — только у уязвимостей, «Дубль», «Другое» с текстом).
- **Удаление реестра, группы или узла не проверяет зависимости каждой записи.** Задачи автоматизаций остаются с пометкой «реестр удалён». Удаление записей сохраняет правило 1.1.0: запись с зависимостями уходит в архив, а не удаляется.
- **Массовое удаление — одно событие с одной причиной.** Оно создаётся до пакетов по окончательному составу (зависимости перепроверяются заранее), чтобы событие оставалось неизменным.
- **Ключ записи уязвимости.** Удалённая запись (одна, массово или вместе с узлом) освобождает ключ в узле. При восстановлении ключ возвращается из значений «Пакет» и «Идентификатор». Если ключ занят новой записью — отказ. Когда ключ снова приходит в скане узла, запись попадает в группу предпросмотра «Были удалены (причина)» и по умолчанию не выбрана. Если её выбрать, заводится новая запись.
- **«Без группы»** не удаляется: на неё опирается seed при `migrate` и откате. Пока в ней нет неархивных записей, API отдаёт её с `hidden`, а интерфейс не показывает её в дереве и на «Все группы». Её сканы открываются ссылкой «Архив сканов прежнего реестра».
- **Корзина** («Настройки → Корзина»). Просмотр — `ib.work`, только чтение. Восстановление — системная роль «Супер-администратор» (`requireSuperAdmin`, как «Параметры портала»). Восстанавливается только целое событие. Отказы при восстановлении:
    - название занято — можно ввести новое;
    - тип снова добавлен в группу;
    - родитель удалён;
    - ключ записи занят.
- **Прозрачность.** «Удалено записей» за период по причинам показывается на «Все группы», в группе и узле, со ссылкой на корзину. В сверке активов — проверка `vulns.deleted_open` (5.3): записи, удалённые открытыми, за 12 месяцев.

## Последствия
- Миграция только добавляет таблицу, колонки и проверки. Существующие строки не меняются.
- Откат на 1.6.0 совместим: старый backend новые колонки не читает. Ограничение принято владельцем: удалённые в 1.6.1 реестры, группы и узлы после отката видны снова, но пустые, потому что их записи у 1.6.0 тоже скрыты по `deleted_at`.
- Удалённое до 1.6.1 в корзину не попадает: у него нет события. Сведения о нём остаются в журнале.
- Каждый запрос, который читает группы, узлы, сканы и реестры, исключает удалённые: раздел, сверка, дашборд, монитор, «Параметры портала», автоматизации. `loadRegister` для удалённого реестра отвечает 404, а карточка задачи читает реестр напрямую.
