# ADR-0028. Проверяющий по задаче

Дата: 30.10.2026. Статус: принято (релиз 1.4.0). Меняет ADR-0022 в части «кто принимает задачу» и ADR-0023 в части «ждёт проверки».

## Контекст
С 1.2.0 задачу «На проверке» принимал любой с `tasks.review`, если он автор задачи или старший над исполнителем, а у исполнителя без руководителя — любой с правом. Проверяющих было несколько, «ждёт проверки» уходило всем, и не было видно, кто именно должен проверить. Владелец решил: проверяет один человек — руководитель исполнителя, и он виден на доске.

## Решение
- **Проверяющий** — ближний по цепочке руководитель исполнителя (ADR-0020), активный и с `ib.work`; отключённые пропускаются вверх по цепочке (`reviewerFor` в `lib/hierarchy.ts`). Фиксируется при отправке «На проверке» в `tasks.reviewer_id` и в переходе `task_transitions.reviewer_id`; смена руководителя после отправки его не меняет. Уход из «На проверке» снимает `tasks.reviewer_id`, история остаётся в переходах.
- **Кнопки.** «Отправить на проверку» — исполнитель, у которого есть проверяющий; нет — 409 `NO_REVIEWER`. «Завершить» (`complete`, «В работе» → «Выполнено») — исполнитель без проверяющего; есть — 409 `REVIEW_REQUIRED`. «Принять» и «Вернуть в работу» — только проверяющий (403 `NOT_REVIEWER`), автор и старшие выше — нет.
- **Видно**: «Проверяет: <ФИО>» на карточке доски и в карточке задачи; в ленте комментариев переход «В работе → На проверке → <ФИО>»; в истории — «… («В работе» → «На проверке» → <ФИО>)» и строка «Проверяющий».
- **Свободная смена статуса** (`tasks.status.override`): из «На проверке» переносит только проверяющий (403 `NOT_REVIEWER`); в «Выполнено» из любой другой колонки — только у исполнителя без проверяющего (409 `REVIEW_REQUIRED`; решение владельца после шага 3: и из «Поставленные», и из своих колонок); перенос в «На проверке» вычисляет проверяющего, некому — 409 `NO_REVIEWER`. Ошибка переноса из окна «Комментарий к переходу» показывается в самом окне. Отменить ненужную задачу — «В архив» (любой с `ib.work`) или удаление (`tasks.delete`): задача уходит с доски, «Выполнено» и `completed_at` не ставятся, в отчёте она не выполнена. Отдельного статуса «Отменена» в портале нет.
- **«Заменить проверяющего»** — `POST /tasks/:id/reviewer`, право `tasks.status.override`: задача «На проверке», новый — активный сотрудник ИБ, не исполнитель и не текущий. Переход «На проверке» → «На проверке» (`override`) с `reviewer_id`, журнал `task.reviewer_replaced`, уведомление новому.
- **Проверяющего отключили** (`users.setActive`, та же транзакция): его задачи «На проверке» переходят к следующему по цепочке исполнителя — переход `system`, журнал «проверяющий заменён — <ФИО> отключён → <ФИО>», уведомление новому. Выше никого — проверяющий снимается, в ленте «назначьте проверяющего», задача на правилах до 1.4.0.
- **Уведомления**: «ждёт вашей проверки» (`task_submitted`) — только проверяющему (отправка, перенос, замена); «Завершить» — `task_completed` автору. Остальные — как в ADR-0023.
- **Задачи, уже стоящие «На проверке»** — однократный шаг seed `tasks.reviewer.v1_4`: проверяющий по текущей цепочке, переход `migration` с комментарием «Проверяющий назначен при обновлении на 1.4.0: <ФИО>»; в выводе `migrate` — число и номера, отдельной строкой id; в журнале — `tasks.reviewers_assigned`. Без цепочки задача остаётся на старых правилах (`tasks.review`), пока держатель override не назначит проверяющего. Повтор ничего не меняет.
- **Право `tasks.review`** («расширить → перенести → сузить», как `docs.approve.head` в ADR-0027): в 1.4.0 код остаётся в матрице с пометкой «Не используется с 1.4.0»; действует только для задач, отправленных до 1.4.0 без проверяющего. Строки `role_permissions` не трогаются — backend 1.3.0 после отката проверяет по нему. Убрать из матрицы — следующим релизом после согласия владельца; удалить строки — ещё позже.

## Последствия
- Миграция `task_reviewer` только расширяет схему (две пустые колонки). Откат на 1.3.0 без отката базы: колонки не читаются, задачи принимаются по `tasks.review`. Задачи, отправленные на 1.3.0 после отката, при повторной выкладке 1.4.0 остаются без проверяющего (шаг seed однократный) — их проверяют по старым правилам или назначают проверяющего вручную; `check-integrity` пишет их число.
- `check-integrity`: проверяющий задачи на проверке активен и не исполнитель.
- Роль руководителя без `tasks.status.override` не может перетаскивать: принимает кнопками.
