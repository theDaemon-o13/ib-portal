# ADR-0032. Адаптеры импорта: отчёты KSC и реестр сервисов

Дата: 02.11.2026. Статус: принято (релиз 1.6.0, `docs/specs/assets.md`, разделы 3–4).

## Контекст
Обычный импорт конструктора не загружает файлы владельца.
- **Реестр сервисов.** Заголовки в строке 6. В колонке «IP:порт» адрес и порт вместе. Шкала старая. «Класификация» на деле означает статус. Продукт определяется по команде.
- **Отчёт KSC.** Это XML Spreadsheet 2003 (`.xls`), а не `.xlsx`. Сводка и детали — на двух листах. Детальная часть по умолчанию обрезана до 1000 строк. Одна машина бывает двумя записями.

Второй конвейер импорта не нужен: предпросмотр, применение одной транзакцией, проверка версий и «Нет в файле» уже есть.

## Решение
- **Адаптер** читает файл и строит лист с колонками по названиям полей, плюс сведения для предпросмотра. Дальше работает общий конвейер (`excel.service.ts`). Адаптер выбирается явно: `POST /registers/:id/imports?adapter=services|ksc`. Каждый адаптер работает только со своим реестром: «Компоненты» или «Хосты».
- **Формат определяется по содержимому.** Принимаются и SpreadsheetML, и `.xlsx`.
- **Разбор XML** — `saxes` 5.0.1, прямая зависимость (та же версия, что приходит с exceljs). Файл с `<!DOCTYPE` или `<!ENTITY` отклоняется до разбора, внешние сущности не читаются. Учитываются `ss:Index` и `ss:MergeAcross`, типы String, Number, DateTime. Лимиты — как у импорта: 25 МБ, 20 000 строк.
- **Расширения конвейера**, не зависящие от активов:
    - служебные поля, которые ставит адаптер;
    - поля «только у новой записи» (имя, тип, источник), у найденной записи они не перезаписываются;
    - область «Нет в файле» или его отключение;
    - новые значения списков;
    - записи других реестров, которые создаются при применении до строк;
    - блоки предпросмотра, необязательные можно снять (`skip` при применении).

  Предпросмотр ничего не создаёт. Всё запланированное создаётся в транзакции применения, отмена ничего не оставляет.
- **Сведения об источнике** хранятся в `register_imports.summary.source`, без миграции: тип отчёта, итог сводки, число строк, дубли. По ним сверка находит последний применённый отчёт о развёртывании.
- **KSC: обрезанный отчёт.**
    - Отчёты о развёртывании и о статусе баз сверяют итог сводки (сумма «Количество устройств») с числом строк деталей. Не сошлось — импорт блокируется с инструкцией поднять лимит.
    - У отчёта о версиях программ итог однозначно не посчитать. Ровно 1000, 5000, 10 000 или 100 000 строк — предупреждение, «Нет в файле» не строится.
- **KSC: каждый отчёт обновляет только свои поля**, пустое значение не стирает поле. «Нет в файле» строит только отчёт о развёртывании и только среди хостов «В KSC = Да»: хосты из реестра сервисов и сканера туда не попадают.
- **KSC: дубли внутри отчёта.** Ключ — имя без регистра и домена. В хост записывается самая свежая строка, остальные показываются блоком «Дубли в KSC». Если имя совпало с хостом другого источника, поля Kaspersky записываются в него же, потому что ключ импорта один. В предпросмотре об этом предупреждение.
- **Реестр сервисов:**
    - ключ компонента — «Компонент / Продукт» без регистра;
    - продукт по таблице «команды → продукты»; команды нет в таблице — продукт с её именем;
    - недостающие продукты создаются всегда, хосты по IP — блоком, который можно снять;
    - статус компонента ставится только у новой записи: ручной вывод из эксплуатации повторный импорт не отменяет.

## Последствия
- Прежняя ошибка конвейера исправлена попутно. Применение считало архивные поля изменившимися, поэтому импорт в реестр с архивным полем не проходил никогда.
- Применение без тела запроса работает как раньше: `skip` необязателен.
- Замер (сгенерированные файлы, dev, `docs/specs/assets.md`, раздел 9): 5000 устройств — предпросмотр 1,3 с, применение 10 с.
