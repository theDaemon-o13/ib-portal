# ADR-0045. Выгрузка готового письма: .eml вместо .msg

Дата: 06.11.2026. Статус: принято (релиз 1.12.0; план — `docs/plans/release-1.12.0.md`).

## Контекст

Портал писем не отправляет (внешних интеграций нет). Письмо должно открываться в Outlook готовым к отправке: остаётся вставить адреса. Формат `.msg` (составной документ OLE) требует отдельной библиотеки — новой зависимости.

## Решение

- «Скачать для Outlook (.eml)»: `multipart/alternative` → `text/plain` и `multipart/related` (HTML макета, логотип и изображения по Content-ID).
- Заголовки: Subject по RFC 2047, `X-Unsent: 1`, `Content-Language`. From, To, Cc и Date нет: Outlook открывает файл как новое письмо от учётной записи пользователя. Сохранить как `.msg` можно средствами Outlook.
- Языки RU+TJ / RU / TJ. Тема RU+TJ — «Тема общая» или «тема RU | тема TJ».
- Имя файла «<Тема RU>_<RU-TJ|RU|TJ>_<ГГГГ-ММ-ДД>.eml», запрещённые в Windows символы — «_».
- Разделители частей — из sha256 содержимого: одинаковое письмо даёт одинаковый файл.
- Лимит письма из «Параметров портала» считается по готовому файлу (413).
- Каждая выгрузка сохраняется (файл `message/rfc822` и строка `awareness_letter_exports`) и пишется в журнал с языками и sha256. Отправкой не считается: запись «Рассылок» появляется только при «Отметить отправленным».

## Последствия

- Без новых зависимостей. «Скопировать с оформлением» для WorldClient остаётся: изображения — `data:`, логотип клиент может убрать (руководство).
