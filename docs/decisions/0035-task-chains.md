# ADR-0035. Цепочки задач: группировка по теме, подсказка вместо склейки

Дата: 04.11.2026. Статус: принято (релиз 1.7.0, план — `docs/plans/release-1.7.0.md`).

## Контекст

Обсуждение продолжается в нескольких задачах с похожим заголовком — в почте это «RE: тема». Задачи нужно собирать в цепочку. Склеивать автоматически нельзя: одинаковые заголовки бывают у разных дел, а ошибка незаметна. Задание готовилось под 1.4.1. С тех пор появились общие задачи (1.6.4) и задачи этапов документов (1.6.3) с шаблонными заголовками.

## Решение

### Модель
- Таблица `task_chains`:
    - `number`, название и `title_key` — нормализованный ключ, не уникален;
    - ответственный (необязательно), статус `open` или `closed`, срок, сводка;
    - кто создал, даты создания и закрытия, `deleted_at`, `version`.
- `tasks.chain_id` — необязательная ссылка на цепочку.
- Частичные индексы: по ключу открытых цепочек, по ключу и дате закрытых, по составу (`chain_id IS NOT NULL`).
- Миграция только добавляет. Старые задачи ею не трогаются.

### Ключ заголовка
`lib/title-key.ts`:
1. NFKC, нижний регистр, «ё» → «е», пробелы схлопываются.
2. Снимаются повторяющиеся префиксы:
    - «RE», «Re[2]», «FW», «Fwd», «Отв», «Ответ», «ВО», «Пересл», «AW», «WG», «SV», «VS», «TR», «RV»;
    - метки «[EXT]», «[External]», «(EXT)», «[Внешнее]».
3. По краям обрезается пунктуация.

Без двоеточия снимаются только латинские «RE», «FW», «Fwd» и только если дальше есть текст: «Во вторник», «Ответственный за…» и «TR-069» не режутся. Пустой остаток — ключа нет, подсказки нет.

`mail-parse` берёт то же снятие префиксов для названия новой задачи из письма. Существующие задачи не меняются, тема в «Исходном письме» хранится как есть.

### Подсказка — человек решает одним щелчком
Не больше 5 вариантов, в таком порядке:
1. Открытые цепочки с тем же ключом — независимо от статусов задач.
2. Закрытые с тем же ключом, где остались незавершённые задачи, — без ограничения по сроку.
3. Открытые с похожим ключом.
4. Закрытые с тем же ключом за `closedDays` дней.
5. Задачи без цепочки с тем же ключом — «Создать цепочку из этих задач».

Похожесть — коэффициент Жаккара по словам от трёх букв, плюс минимум общих слов. Предлоги «к», «в», «на» не считаются: «Доступ к VPN Иванов» и «Доступ к VPN Петров» не похожи.

Порог, минимум общих слов и срок лежат в `app_settings` `tasks.chainSuggest` — «Параметры портала», без релиза. По умолчанию: 0,6, два слова, 30 дней.

**Отбор кандидатов:**
- Цепочки сравниваются в приложении со всеми, без предварительного отбора: ключ цепочки и ключи её видимых задач. Переименованная цепочка находится по старым «RE: …», а похожая не выпадает из-за другого самого длинного слова.
- Задачи без цепочки отбираются в SQL по самому длинному слову ключа (`ILIKE`, «е» → любой символ). Сравнение там точное, ничего не теряется.
- `pg_trgm` не используется.

**Где появляется:** в быстрой строке над доской, в «Задаче из письма» (по теме письма) и в карточке задачи. При создании выбор уходит вместе с задачей — параметр `chain` у `POST /tasks`, одна транзакция.

**Системные задачи** (документы, автоматизации, доказательства) с шаблонными заголовками в подсказках и поиске не участвуют. Вручную из карточки их привязать можно.

### Видимость
Одна функция `visibleTasksWhere(actor)`. Сейчас: все неудалённые задачи тем, у кого `ib.work`, иначе ни одной. Через неё считаются:
- состав цепочки и счётчики;
- подсказка;
- поиск среди старых задач;
- глобальный поиск.

Цепочка без видимых задач не показывается. Если у задач появятся свои правила видимости, их место — в этой функции.

### Права (без новых кодов)
- Привязать, отвязать, перенести — любой с `ib.work`, в том числе выполненную и архивную задачу. Меняется только `chain_id` и версия задачи; статус и архив не трогаются.
- Править, закрывать, открывать заново, удалять — создатель цепочки, ответственный или `tasks.assign`.
- «Найти цепочки среди старых задач» — `tasks.assign` или `settings.manage`: разовая операция администратора с предпросмотром и подтверждением. С разделением полномочий не конфликтует — процесс задач и согласование документов не затрагиваются; цепочки поиска записываются на запустившего (он их создатель).

### Связь с процессом
Цепочка только группирует:
- Исполнитель, проверяющий (ADR-0028), колонки и ограничения переноса у каждой задачи свои.
- Код процесса о цепочках не знает.
- Статус цепочки от статусов задач не зависит. Когда все задачи выполнены, интерфейс предлагает «Закрыть цепочку», но сам портал её не закрывает.
- Закрыть цепочку с незавершёнными задачами можно, с предупреждением. Такая цепочка остаётся в подсказке второй группой.
- Индикаторы, уведомления, дашборд, отчёт и статистика не меняются. Единственный след — запись «добавлена в цепочку» в истории задачи.

### Удаление
Мягкое (`deleted_at`). Задачи отвязываются, каждая получает запись в истории, сами задачи остаются. Восстановления в интерфейсе нет. Перед удалением — диалог «Задачи (N) будут отвязаны от цепочки, сами задачи останутся». Для обычного завершения работы — «Закрыть».

### Старые задачи
«Найти цепочки среди старых задач»:
- предпросмотр — группы от двух задач по точному ключу, включая выполненные и архивные; если есть открытая цепочка с тем же ключом, группа добавляется в неё;
- применение — после подтверждения, одной транзакцией;
- изменилось после предпросмотра — 409 `BULK_CHANGED`;
- повторный запуск безопасен: задачи с цепочкой в поиск не попадают.

### Доска
- В колонке, где у цепочки две и больше задач, — своя свёрнутая карточка «название · N задач, M выполнено · здесь K». Она раскрывается задачами этой колонки, и перетаскиваются отдельные задачи. Одна задача цепочки в колонке не сворачивается: обычная карточка с меткой цепочки, метка открывает панель цепочки (решение владельца перед выпуском).
- Одна карточка в «первой» колонке скрыла бы задачи остальных колонок. Полоса поперёк доски ломает вертикальную прокрутку колонок.
- Группировку можно выключить; тогда на карточке задачи — метка цепочки.

## Последствия
- **Миграция `task_chains`.** Влияние на данные: новая пустая таблица и пустая колонка, существующие строки не меняются.
- **Откат на 1.6.7 без отката базы совместим:** 1.6.7 выбирает колонки `tasks` явно и `task_chains` не читает. Новые задачи 1.6.7 создаёт с `chain_id = NULL`. Проверено на dev 04.11.2026: backend и frontend 1.6.7 из тега `v1.6.7` против dev-базы с миграцией — e2e задач 1.6.7 12/12; задачи цепочки на 1.6.7 правятся, комментируются, проходят шаги, уходят в архив и возвращаются; на 1.7.0 после этого цепочка цела, задача, созданная на 1.6.7, — без цепочки. E2E документов 1.6.7 при этом не запускались: они загружают файлы, а у backend вне контейнера свой каталог файлов.
- **Журнал:**
    - по задаче — `task.chain_linked`, `task.chain_unlinked`, `task.chain_moved` (видно в истории карточки);
    - по цепочке — `task_chain.created`, `.updated`, `.closed` (с числом незавершённых), `.reopened`, `.deleted` (со списком отвязанных), `.discovered`.
- **Глобальный поиск:** новый раздел «Цепочки задач».
- **Фаза 2:**
    - автоподстановка при точном ключе;
    - слияние цепочек;
    - комментарии на уровне цепочки;
    - `pg_trgm`;
    - хранимый ключ у задачи;
    - восстановление удалённой цепочки.
