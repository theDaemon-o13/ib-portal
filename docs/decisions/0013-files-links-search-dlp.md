# ADR-0013. Поля «Файл» и «Связь с записью», фиксация полей, поиск по тексту PDF, выгрузка для проверки

Дата: 27.10.2026. Статус: принято (этап 8б).

## Контекст

Этап 8б (CLAUDE.md, раздел 12; docs/concept.md, п. 10): разрешения на доступ и реестр агентов DLP. Владелец проекта ответил на открытые вопросы и утвердил план (27.10.2026):
- документы приходят в PDF; текстовый слой индексируется, сканы помечаются, OCR — отдельный шаг позже;
- разрешение выдаётся на устройство (имя хоста), сверка — по связи, не по ФИО; одно разрешение может покрывать несколько хостов;
- портал — основной электронный архив, бумажные оригиналы хранятся для регулятора;
- после статуса «Действует» документ и его реквизиты не меняются, «Устройства» — только с причиной; фиксация — общая настройка поля конструктора;
- «№ и дата документа» разделены на «№ документа» (текст) и «Дата документа» (дата);
- новые зависимости backend: `pdfjs-dist@6.4.299` (та же версия, что во frontend) без optional-зависимостей и `archiver@5.3.2` (уже был в дереве через exceljs) прямой зависимостью с локальным `.d.ts`.

## Решение

1. **Поле «Файл».** Ссылки на файлы — в таблице `register_record_files` (запись, поле, файл, кто и когда добавил, `removed_at`/`removed_by`), а не в `values`: так `file_active_refs()` видит их, и файл с действующей ссылкой не помечается удалённым (`files_guard`). Отвязка мягкая; строки не удаляются (`REVOKE DELETE`, триггер). Привязка и отвязка — отдельными маршрутами (`POST /register-records/:id/files`, `…/files/:linkId/remove`), меняют версию записи и пишутся в историю. В Excel — имена файлов, только чтение.
2. **Поле «Связь с записью».** `register_fields.link_register_id` (FK, CHECK: задан тогда и только тогда, когда тип `link`). Значение — массив id записей в `values` (`StoredValue` расширен массивом): история, версии, импорт и PATCH работают как у остальных полей. Обратные связи — по GIN-индексу `values jsonb_path_ops` (`values @> {"поле": ["id"]}`). В Excel — заголовки связанных записей через «;»; импорт ищет по «#номеру», ключу импорта или заголовку, неоднозначное — ошибка строки. Текст поиска записи включает заголовки связанных записей; смена заголовка пересчитывает поиск ссылающихся записей.
3. **Фиксация полей — настройка поля** `register_fields.settings.lock = { statusOptionIds, mode }`:
   - `locked` — заполненное значение не меняется и не очищается, файл не отвязывается и второй не добавляется; пустое можно заполнить один раз;
   - `reason` — значение меняется только с причиной (`PATCH … { reason }`), причина — в истории и журнале;
   - пока статус записи фиксирующий: запись не удаляется (ни мягко, ни физически), статус меняется только на другой фиксирующий.

   Сервис отвечает 422 (`FIELD_LOCKED`, `REASON_REQUIRED`, `STATUS_LOCKED`, `RECORD_LOCKED`); то же держат триггеры `register_records_lock_guard` и `register_record_files_guard` через функцию `register_locked_fields()` (кроме причины — её проверяет только сервис). Ослабить фиксацию статуса, который уже есть у записей, нельзя (`LOCK_IN_USE`); поле статуса, на котором держится фиксация, не снимается; тип поля с настройками не меняется. Импорт Excel зафиксированное не меняет — ошибка строки.
4. **Ограничение даты** `settings.date = { notAfterYearEndOfFieldId, defaultEndOfYear }`: «не позже 31.12 года поля N» (форма и импорт) и значение по умолчанию «31.12 года поля N, иначе текущего года» у новой записи.
5. **Статус основания** — вычисляемое поле `calc_rule.kind = 'link_basis'`: канал записи (список и «закрытые» значения), реестр-источник, его поле связи, вид и подходящие значения, статус и «действующие» значения, «Действует до», номер документа. Вычисляется при чтении (`lib/link-basis.ts`): `closed`, `ok` (разрешение №, до), `expired`, `none`. Фильтр списка `f=<поле>:none,expired` и дашборд считают тем же кодом (в памяти). Правило настраивается в конструкторе; поле реестра-источника, на которое ссылается правило, не удаляется и не архивируется.
6. **Автоматизации:** условия `yearly` (ДД.ММ; сводное событие правила без записи, одна задача со списком открытых записей; догоняет неделю), `basis_missing` (канал без основания; ключ события — канал, состояние и разрешение), флаг `before.skipYearEnd`; действие `set_option` (поставить значение списка, если сейчас одно из `fromOptionIds`; событие сразу обработано, изменение — в истории от имени системы; изменение, запрещённое фиксацией, пропускается с записью в журнал); свой заголовок задачи `action.title` (`{год}` — следующий год). Для сводного события расширены CHECK `automation_events_subject_check`, `tasks_automation_check`, `automation_events_type_check` и добавлен уникальный индекс `(automation_id, trigger_key)` для событий без записи.
7. **Текст PDF и поиск.** При загрузке PDF получает строку `file_texts` (`pending`); фоновый прогон (`plugins/jobs.ts`, раз в 20 с) разбирает по одному файлу pdf.js (legacy-сборка) в отдельном потоке: 30 с, 256 МБ, 300 страниц, 1 млн символов, `isEvalSupported: false`. Меньше 20 непробельных символов — `no_text` («текст не распознан, поиск только по полям»); ошибка — до трёх попыток, затем `failed`. `file_texts.tsv` и `register_records.search_tsv` — вычисляемые колонки `to_tsvector('russian', …)` с GIN. `GET /search`: полнотекстовый поиск плюс подстрока (имена хостов, номера, имена файлов); с `ib.work` — записи, доказательства и приложенные файлы, без него — только PDF версий документов, которые пользователь видит. Счётчики файлов без текста и в очереди. OCR не делается.
8. **Выгрузка для проверки** `GET /registers/:id/export.zip?dateFieldId&from&to[&nameFieldId&linkFieldId]`: записи за период (с архивными) в Excel с листом «Файлы» (имя в архиве, исходное имя, sha256, дата загрузки) и файлы в `files/` с именами «<№ документа>_<хосты>.<расш.>» (`lib/zip-names.ts`: «_» между хостами, длиннее 120 символов — «<№>_<хост1>_и_ещё_N», недопустимые символы → «-», совпадения → «_2»). Архив собирается потоком (archiver), выгрузка пишется в журнал.
9. **Стартовые реестры** «Устройства DLP» и «Разрешения на доступ» создаёт seed один раз (`seed_markers`), с правилами, плитками (автор — система: `dashboard_tiles.created_by` стал необязательным), меткой «Разрешения DLP» и правилом почты «Разрешения» выше «Доступа». Статус «Оформляется» добавлен первым: новое разрешение не фиксируется, пока к нему прикладывают документ.
10. **`@napi-rs/canvas`** (optional-зависимость pdfjs-dist) для текста не нужен и в образ не попадает: стадия `deps` — `npm ci --omit=optional`, `npm prune --omit=dev --omit=optional`; в dev-стадии каталог удаляется после `npm ci` (там optional нужны esbuild и rollup); `make-release.sh` проверяет образ.

## Последствия

- Зафиксированное разрешение исправляется только новой записью; ошибки в документе до «Действует» правятся как обычно.
- Прежний backend не знает типов полей `file` и `link` и правила `link_basis`: откат после seed этапа 8б покажет стартовые реестры некорректно (портал ещё не выкладывался — RELEASE.template.md).
- Сканы без текстового слоя ищутся только по полям записи и имени файла до шага OCR.
