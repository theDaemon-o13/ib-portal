# ADR-0050. Домен вне итога: признак в методике

Дата: 11.11.2026. Статус: принято (релиз 1.13.10; задание — `docs/tasks/1.13.10-ai-domain.md`, план — `docs/plans/release-1.13.10.md`). Дополняет ADR-0025.

## Контекст

В чек-лист самооценки нужен 11-й домен «Контроль ИИ» (4 раздела). Итог КБ при этом должен остаться «N из 96» с прежними порогами: иначе новая оценка несравнима с прошлыми (эталон 07.07.2025 — 34 из 96). Владелец может позже решить включить ИИ в итог — это не должно требовать правки кода.

## Решение

- Новая версия методики `cyber-express-v2` = v1 без изменений + домен 11. Методика — строка `assessment_methodologies` (`content jsonb`), оценка держит снимок: схема БД не меняется.
- У домена в методике поле `inTotal` (по умолчанию `true`). У домена 11 — `false`.
- Итог, максимум и уровень (в том числе условие «Результативной КБ» по 1.2, 4.2, 10.1) считаются только по доменам с `inTotal ≠ false`. Заполненность, «предварительно» и фиксация — по всем разделам снимка: у v2 — 28 из 28.
- По доменам вне итога — отдельная строка: «Контроль ИИ: X из 16», средний балл, заполненность. Разрывы и план включают их разделы, «баллов к итогу» — нет.
- Seed создаёт каждую версию один раз и делает активной последнюю версию списка. Включить ИИ в итог — новая версия методики с `inTotal: true` (и, если нужно, новыми порогами), без правки расчёта.
- Черновик на v1 обновляется до активной методики кнопкой «Обновить методику до v2»: ответы сохраняются, новые разделы — пустые, запись в журнал. Зафиксированные и архивные оценки не меняются.

## Последствия

- Замороженные `result` оценок v1 без новых полей читаются с `inTotal: true` по умолчанию.
- Откат на версию до 1.13.10 требует вернуть активной v1 (`UPDATE assessment_methodologies SET is_active = (version = 1)`): прежний расчёт не знает `inTotal` и посчитал бы итог из 112.
