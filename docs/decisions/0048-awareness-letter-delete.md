# ADR-0048. Удаление учебных писем и право awareness.delete

Дата: 09.11.2026. Статус: принято (релиз 1.13.3; решение владельца 09.11.2026 — код права согласован).

## Контекст

С 1.9.0 учебное письмо физически не удаляется (триггер `awareness_letters_guard`), только уходит в архив (ADR-0039). Архив копит черновики, которые никто не отправлял: пробные письма, дубли, ошибочно созданные из шаблона. Владелец попросил удалять их, сохранив неизменность всего, что уже ушло сотрудникам банка.

## Решение

- **Что можно удалить:** только письмо в архиве, ни разу не отмеченное отправленным — нет события `sent`, записи «Рассылок» и файла отправки, письмо не заморожено. Иначе 409: `LETTER_SENT` (отправленное — ни из интерфейса, ни через API) или `LETTER_NOT_ARCHIVED`.
- **Как:** мягко — колонка `awareness_letters.deleted_at` (миграция `20261109120000_awareness_letter_deleted`, одна колонка, существующие строки не меняются). Версии и события письма остаются в базе. Триггер не менялся: у замороженного письма `deleted_at` не меняется — вторая линия к `LETTER_SENT`. Физического удаления по-прежнему нет.
- **Видимость:** удалённое — 404 в карточке и действиях, его нет в списках, поиске, выборе, ссылках «Рассылок», экспорте и «Ближайшей рассылке». Журнал — `awareness_letter.deleted` (кто, когда, название, версия). `check-integrity` — удалены только архивные и неотправленные.
- **Связи:** задача рассылки и запуск расписания остаются; в происхождении задачи `letter.deleted = true` — карточка показывает «письмо удалено», этапы не закрыты. Прогон расписания на удалённое письмо не опирается.
- **Право** `awareness.delete` («Осведомлённость: удаление писем»), по образцу `tasks.delete`: архивировать может любой сотрудник ИБ, удалять — держатель права (вместе с `ib.work`). Новые установки — в «Супер-администраторе» и «Начальнике ИБ»; обновление — шаг seed `rbac.permissions.v1_13_3` один раз (снятое администратором не возвращается).

## Последствия

- Откат на 1.13.1 без отката базы: колонку и код права 1.13.1 не читает (матрица ролей фильтрует права по кодам из кода), удалённые письма снова видны в архиве — ничего не теряется.
- Восстановления удалённого письма в интерфейсе нет (как у задач); при необходимости — `deleted_at = NULL` администратором БД по журналу.
