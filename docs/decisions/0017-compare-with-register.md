# ADR-0017. Сравнение с реестром: «Нет в файле», ключ сравнения, файл как доказательство

Дата: 29.10.2026. Статус: принято (релиз 1.1.0, задача 4, упрощённый план этапа Б).

## Контекст
После выгрузки устройств DLP или нового отчёта сканера нужно увидеть, какие открытые записи реестра в файл не попали (устройство выведено, уязвимость устранена), и проставить им статус. Новые и изменившиеся строки уже показывает предпросмотр импорта. Действовать по сравнению нужно осознанно: файл мог быть неполным.

## Решение
- **Ключ сравнения** — настройка реестра (`registers.compare_key_field_ids`, до 3 полей по порядку; пусто — по колонке ID), задаётся в конструкторе (`registers.manage`) и при сравнении только показывается. Это не ключ импорта: `is_import_key` уникален и нужен импорту без колонки ID, ключ сравнения может быть составным и неуникальным («CVE / БДУ + Пакет» — закрытые записи с той же парой бывают). Существующий ключ импорта переносится в ключ сравнения по умолчанию (миграция `register_compare_settings` и однократный шаг seed для установки с нуля).
- **Область обязательна**: значения поля из `registers.compare_scope_field_ids` или явный «Весь реестр» с предупреждением.
- **Результат — только «Нет в файле»**: открытые записи (не закрыты, не в архиве) области с заполненным ключом, которых нет в файле. Записи без ключа считаются, но не сопоставляются. Текст ключа нормализуется функцией БД `register_import_key()`; список, справочник, сотрудник — по id значения. Строки файла читаются тем же кодом, что и при импорте (`readFileRows`), отчёт сканера — его разбором.
- **«Неполный скан»**: для отчёта сканера сравниваются листы «Хосты» нового и прошлого отчёта (выбранного в области или последнего того же отдела). Связи «уязвимость → хост» в данных нет, поэтому предупреждение — на весь результат; статус при нём ставится только с подтверждением.
- **Действие — только статус**: свой у каждой записи или один у отмеченных. Порядок — как у массовых действий (ADR-0016): предпросмотр → применение с `expected` (409 `BULK_CHANGED`), пакетами, обычной правкой записи (фиксация, пересчёт, история карточки `via: compare`), плюс сводная запись журнала. Результат сравнения не хранится: при применении сервер заново сравнивает сохранённый файл с реестром.
- **Файл — доказательство**: при сравнении файл кладётся в `files` (sha256, кто загрузил), ссылка — `register_imports.file_id`; её учитывает `file_active_refs()`, поэтому уборка непривязанных файлов его не помечает удалённым. В diff журнала каждой изменённой записи — `importId`, `fileId`, sha256 и имя файла.
- Права — `records.edit` (сравнение и статус), новых прав нет.

## Дополнение — этап Б.2 (29.10.2026)
- **Отдел** из A1 листа «Хосты» хранится в записи уязвимости (системное поле «Отдел», шаг seed `v5.department`, без миграции схемы: поле — данные конструктора). Дубли отчёта — по «CVE + пакет + отдел», «Обнаружений» — из нового отчёта, по максимуму — только внутри файла (правило 6 раздела 7 CLAUDE.md изменено). Отдел сравнивается без регистра, пробелов и «ё»/«е» (`deptKey`), хранится как в отчёте.
- **Область** — набор условий по полям, все выполняются (`{ conditions: [...] }`); прежний вид `{ fieldId, values }` принимается. Для отчёта сканера по умолчанию — отдел отчёта и выбранная система; «Конкретный прошлый отчёт» — дополнительно. Подпись — «отдел «…», система «…»».
- **Подсказка** в окне отчёта — `GET /register-imports/:id/not-in-file`: число открытых записей области по умолчанию, не совпавших со строками отчёта (по совпадениям предпросмотра, без чтения файла).

## Изменение (релиз 1.5.0, ADR-0029)
Реестр уязвимостей больше не сравнивается здесь: отчёт сканера загружается в узел, «Пропали» и охват считает предпросмотр скана. Подсказка `not-in-file`, «неполный скан» и окно отчёта на странице «Реестры» убраны. Для остальных реестров всё остаётся.

## Последствия
- Две миграции: настройки сравнения в `registers` (+ перенос ключа импорта) и `register_imports.file_id` с обновлённой `file_active_refs()`.
- Выгрузка результата сравнения в Excel и «хост не сканировался» по записи — в «Запланировано».
