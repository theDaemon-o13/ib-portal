# ADR-0038. Сопоставление результатов с сотрудниками по ФИО

Дата: 05.11.2026. Статус: принято (релиз 1.8.0; спецификация — `docs/specs/awareness.md`, разделы 4.5 и 5).

## Контекст

В отчёте INDIGO нет табельного номера — только фамилия, имя и отчество. Выгрузка HR даёт сотрудников с табельным номером и ФИО. Однофамильцы с одинаковым ФИО в банке есть, отчества может не быть, «ё» пишут по-разному. Ошибочная связь незаметна и портит отчётность по подразделениям, поэтому неоднозначность нельзя решать автоматически.

## Решение

- **Нормализация** одна для адаптера, ключа попытки, пересчёта и текстового измерения: регистр, лишние пробелы, неразрывный пробел, «ё» → «е» (`normalizeDimensionText`).
- **У сотрудника** сравнивается поле «ФИО» (заголовок), а не части. Поэтому находятся и сотрудники с неразделённым ФИО.
- **«Точно»** — ставится только если выполнено всё сразу:
    - в отчёте есть фамилия, имя и отчество;
    - совпадение ровно одно;
    - сотрудник в статусе «Работает».

  Тогда — связь, «Сопоставление» = «Точно» и подразделение сотрудника.
- **Иначе «Не сопоставлен»** с причиной:
    - «однофамильцы: N»;
    - «нет отчества»;
    - «найден только уволенный»;
    - «не найден».

  Такая строка попадает в блок ручного выбора. Однофамильцы предложены, остальных находят поиском среди работающих. Выбранный — «Вручную», подразделение — из выбранного. При применении выбор проверяется заново: запись из «Сотрудников», не удалена, «Работает». Иначе `IMPORT_STALE`, и ничего не применяется.
- **Только у новой записи** ставятся «Сотрудник», «Сопоставление» и «Подразделение». Повторная загрузка не снимает ручное сопоставление.
- **«Сотрудник» правится в карточке**: «Вручную», а при очистке — «Не сопоставлен». Остальные поля результата служебные (409 `AWARENESS_SERVICE_FIELD`): результат исправляется загрузкой исправленного отчёта.
- **«Обновить по сотрудникам»** (решение 8) — только для записей «Не сопоставлен», по тем же правилам «Точно». В записи результата отчество отдельно не хранится, поэтому «полное ФИО» здесь — не меньше трёх слов. Это безопасно: всё равно нужно точное совпадение с единственным работающим. Применение — с `expected` (409 `BULK_CHANGED`). Подразделение у уже связанных не обновляется.
- **Связь на уволенного** показывается с меткой «(уволен)» — общее правило вывода связей, решение 7. Виджет «На пересдачу» исключает только живую связь на закрытую запись; несопоставленные считаются, ведь неизвестно, что человек уволен.

## Последствия

- Автоматически сопоставляется меньше, чем возможно, зато без ложных связей. Остальное разбирает человек при загрузке или позже кнопкой.
- `check-integrity` следит, что «Сопоставление» согласовано со связью.
- Обновление подразделения у уже связанных результатов (переход в другой отдел) — следующий шаг, если понадобится.
