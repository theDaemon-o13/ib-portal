# ADR-0049. Свой выпадающий список Select со скрытым нативным <select>

Дата: 09.11.2026. Статус: принято (релиз 1.13.4; задание — `docs/tasks/1.13.4-forms.md`, план — `docs/plans/release-1.13.4.md`).

## Контекст

Раскрытый нативный `<select>` рисует браузер и система: на Windows — светлая панель с голубым выделением в обеих темах, вне стиля «Океан» (ADR-0047). В портале 142 списка в 54 файлах, у 131 — обработчик `onChange` по событию; есть `required`, `disabled`, `form`. Новые npm-зависимости не добавляем.

## Решение

- Компонент `frontend/src/components/Select.tsx` с тем же API, что у `<select>` (свойства и `<option>` как есть); замена в разметке механическая (`<select>` → `<Select>`).
- **Внутри — скрытый нативный `<select>`** с прежними свойствами. Выбор в своём списке ставит ему значение setter'ом и посылает настоящее событие `change` — обработчики, валидация `required` и отправка формы не меняются; чтение `.value` и `.options` работает как раньше.
- Видимая часть — `<button role="combobox" aria-haspopup="listbox">` перед нативным (клик по подписи `<label>` открывает список), панель `role="listbox"` — в портале поверх окон, вверх у нижнего края. Клавиатура — WAI-ARIA APG (select-only combobox); больше 15 значений — поле поиска. Логика — `select-logic.ts` с unit-тестами.
- Открытый список забирает Esc у окна: окна, которые слушают Esc в фазе захвата, проверяют `selectListOpen()`.
- Обёртка — класс `ui-sel` (`.sel` уже помечает выбранную строку и карточку).
- Чекбоксы и radio — общий стиль с `appearance: none` (галочка — SVG-маска), вместо `accent-color`.

## Последствия

- e2e выбирают значение щелчком по списку и пункту (`ui.select`), как пользователь; проверки по `.value` и `.options` остались.
- Новые списки пишутся через `<Select>`; нативный `<select>` в разметке — только с обоснованием.
- Календарь поля даты остаётся системным (в цветах `color-scheme` темы на `<html>`).
