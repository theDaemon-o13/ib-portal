# ADR-0029. Узлы «группа × тип систем» при одной структуре полей

Дата: 30.10.2026. Статус: принято (релиз 1.5.0, `docs/specs/vulnerabilities.md`, план `docs/plans/release-1.5.0.md`). Меняет ADR-0017 в части реестра уязвимостей и правило 6 раздела 7 CLAUDE.md.

## Контекст
Уязвимости — один системный реестр конструктора (`registers.system_key = 'vulns'`). Нужна группировка по сервисам и подразделениям, а внутри — по типам систем (БД, серверы, рабочие станции …). Отчёт сканера относится к одному такому узлу; реестр узла — текущее состояние, сканы — история. Срок, правила п. 7.4, дашборд, монитор, фильтры и Excel уже считают срок одной функцией `calcValue` по `values` записи.

## Решение
- **Одна структура полей** — существующий реестр уязвимостей. Отдельных реестров конструктора на узел нет: иначе правила п. 7.4, ключ сравнения, виджеты и монитор пришлось бы размножать и синхронизировать.
- **Группа** — `vuln_groups` (название уникально без регистра, вид «Сервис» / «Подразделение»; системная «Без группы» — вид «Временная», `system_key = 'ungrouped'`). Переименование — `registers.manage`, с журналом; удаления нет.
- **Узел** — `vuln_nodes` = группа × значение справочника «Типы систем» (`system_types`, по id). В «Без группы» один узел «Из прежнего реестра» (`system_key = 'legacy'`, без типа). Создание группы и «Добавить тип» — `registers.manage`.
- **Запись узла** — `vuln_records` (1 : 1 с `register_records`): узел, нормализованный ключ «Пакет + Идентификатор» (`key_norm`, уникален в узле; в «Без группы» и у удалённых — NULL), скан, от которого идёт срок, первый и последний скан, цикл (растёт при повторном обнаружении), отметка «из прежнего реестра». Сканы записи — `vuln_record_scans` (только пополняется).
- **Скан** — `vuln_scans`: узел, дата, файл в `files` (sha256), охват (название и хосты), снимок строк с посчитанной Оценкой, результат сравнения, предыдущий скан, передача ИКТ. Не удаляется и не редактируется (триггер), кроме однократной передачи ИКТ. Отчёты прежнего реестра (`scan_reports`) показываются сканами «Без группы» через `legacy_report_id`, без снимка и сравнения: файл в 1.1.0 не хранился.
- **Импорт** — расширение `scan-import.service.ts`: предпросмотр раскладывает строки по пяти группам (новые, повторно обнаружены, изменились, без изменений, пропали), выбор по строкам, применение одной транзакцией с проверкой версий (`IMPORT_STALE`). Разбор — по содержимому листов. Файл хранится как доказательство. Импорт в «Без группы» запрещён. «Система» предзаполняется из прошлого импорта узла.
- **Страница «Реестры»** для реестра уязвимостей: создание записей, импорт отчёта сканера и «Сравнение с реестром» отключены (409 `VULN_USE_SECTION`); выгрузка и обратный импорт Excel по ID, массовые действия и аналитика остаются.
- **Перенос данных 1.1.0–1.4.0**: все записи — в «Без группы / Из прежнего реестра» (однократный шаг seed), отчёты — сканами этого узла; повторяемый шаг при каждом `migrate` подбирает записи и отчёты, созданные после отката. «Перенести» и «Перенести выбранные» — `records.edit`; ключ, который уже есть в узле, — отказ по строке.

## Последствия
- Две миграции только добавляют таблицы; поля реестра, справочник и «Без группы» — данные seed.
- Откат на 1.1.0–1.4.0 без отката базы: новые таблицы не читаются; записи, созданные старой версией, при повторном обновлении попадут в «Без группы».
- Поля и автоматизации на уровне узла, привязка находок к хостам, удаление групп и узлов — этап 2.
