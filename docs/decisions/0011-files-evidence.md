# ADR-0011. Файлы, доказательная база, решения другого отдела, итоговый PDF документа

Дата: 27.10.2026. Статус: принято (этап 7).

## Контекст

Этап 7 (CLAUDE.md, раздел 12): файлы в портале (раздел 3.7), риски ИБ с решениями ОУР, доказательная база. ADR-0007 оставил решения другого отдела без файла до этапа 7, ADR-0010 — заморозку текста документа итоговым PDF. Владелец проекта решил: PDF прикладывает автор при отправке на согласование, все этапы согласуют один файл, замена PDF в маршруте возвращает его к началу; задним числом PDF к утверждённым версиям не прикладывается; триггер «утверждение без PDF» — в релизе-«сужении»; проверяющий не принимает доказательство, загруженное им самим; «Реестр рисков ИБ» — системный; новый файл возвращает доказательство на проверку, файлы убираются только у доказательства на проверке; загрузка — только с `ib.work` или правом документов; непривязанные файлы через сутки помечаются удалёнными. Новая зависимость — только `pdfjs-dist` (согласована).

## Решение

1. **Хранение.** Содержимое — в томе `ibportal_files`, путь `FILES_DIR/<yyyy>/<mm>/<uuid>` (исходного имени в пути нет), запись атомарная: временный файл → `fsync` → `rename`. Метаданные — `files`: исходное имя, MIME по содержимому, размер, sha256, кто и когда загрузил. «К чему привязан» — не отдельная таблица, а внешние ключи: `register_decisions.file_id`, `document_versions.pdf_file_id`, `evidence_files`. Их же считает функция БД `file_active_refs()`.
2. **Загрузка** — `POST /files`, тело запроса как есть (`application/octet-stream`), имя в `X-File-Name`: без multipart, чтобы не добавлять `@fastify/multipart`. Несколько файлов — несколько запросов, затем объект ссылается на их id. Право — `requireAnyPerm(['ib.work', 'docs.manage', 'docs.approve.*'])`.
3. **Тип по содержимому** (`lib/file-type.ts`, без зависимостей): сигнатуры PDF, PNG (с IHDR), JPEG; docx/xlsx — центральный каталог zip и `[Content_Types].xml` (через `node:zlib`, с лимитом распаковки); текст — без NUL-байтов и без HTML/SVG/XML-разметки в начале, UTF-8 или Windows-1251. Расширение обязано совпадать с содержимым; офисные файлы с макросами (`vbaProject.bin`, `macroEnabled`) отклоняются. В БД пишется найденный MIME, а не присланный браузером. Лимит — 25 МБ (`bodyLimit` маршрута; nginx — `client_max_body_size 25m`), превышение — 413 `FILE_TOO_LARGE`.
4. **Выдача** — только `GET /files/:id/content`: всегда `Content-Disposition: attachment` (ASCII + `filename*=UTF-8''`), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'`, `Cache-Control: private, no-store`. Предпросмотр frontend строит из blob (`fetch`), inline-выдачи нет. Доступ — по ссылкам: доказательство и решение — `ib.work`; PDF версии документа — тот, кто видит эту версию (правила ADR-0010); файл без ссылок — только загрузивший. Остальным — 404 (не раскрываем, что файл есть). Выдача пишется в журнал (`file.downloaded`).
5. **Удаление только мягкое.** `files.deleted_at` ставится, когда ссылок не осталось (отвязка от доказательства, замена PDF) или файл никуда не приложили за сутки (часовой прогон, автор — система, `file.orphan_deleted`). Содержимое на диске остаётся: физического удаления в коде нет. Защита в БД: у `ibportal_app` нет `DELETE`, `TRUNCATE` на `files`, `evidence`, `evidence_files`; триггер `files_guard` запрещает `DELETE`, правку содержимого и метаданных и отметку «удалён» при живых ссылках; `file_ref_alive` не даёт сослаться на удалённый файл (`FOR SHARE` против гонки с очисткой); привязка блокирует строки файлов `FOR UPDATE`. Приложить можно только свой файл (`FILE_NOT_YOURS`) — чужой id не подставить.
6. **Решения другого отдела.** `register_decisions.file_id NOT NULL` с внешним ключом (таблица до этапа 7 пустая, миграция это проверяет), плюс `review_due`. `POST /register-records/:id/decisions` (`records.edit`) — решение, номер и дата документа, файл, необязательные «Пересмотр до» и номер в реестре другого отдела; первый вариант («Ожидает решения») не вносится; запись захватывается по `version` (409). Той же транзакцией: доказательство «Решение другого отдела» (сразу «принято», тот же файл), в «Реестре рисков ИБ» — системные поля «№ в реестре ОУР» и «Пересмотр до», запись в истории записи.
7. **«Реестр рисков ИБ»** — системный (`systemKey: risks`), seed однократно, без записей: Риск ИБ, Актив / система (справочник «Системы»), Уровень, Статус ИБ, № в реестре ОУР, Решение ОУР, Пересмотр до, Владелец риска; системные — «№ в реестре ОУР», «Решение ОУР», «Пересмотр до». Правила: за 30 дней до «Пересмотр до» — владельцу риска; просрочен — владельцу и «Начальнику ИБ». Правила прототипа «вернуть статус» и «напомнить ОУР письмом» движок не выполняет (только события → задачи; письма — этап 9). (Пересмотрено 27.10.2026: этап 9 не планируется — внешних интеграций нет, писем портал не отправляет.)
8. **Доказательства.** `evidence`: ровно один объект — запись реестра, документ или система (CHECK); вид — форма, решение, файл; статус проверки `pending | accepted | rejected`; «истекает» (≤ 30 дней) и «истекло» считаются при чтении. Форма хранит снимок полей шаблона и значений в `checks` (требование, значение, соответствие); триггер `evidence_guard` запрещает менять снимок, объект и автора. Все поля формы обязательны. Срок действия формы — дата загрузки + срок шаблона; у файла — по желанию. Файлы — `evidence_files`, отвязка — `removed_at`.
9. **Проверка** — `evidence.review`, но не своё: проверяющий не принимает доказательство, которое загрузил или к которому приложил файл (`SEPARATION_OF_DUTIES`). Отклонение — с комментарием и задачей загрузившему «Исправить и загрузить заново» (категория «Доказательства», 7 дней). Новый файл возвращает принятое или отклонённое на проверку; задача отклонения закрывается, когда приложен файл или загружена новая форма по тому же объекту и шаблону.
10. **Срок действия → задача** — через `automation_events.evidence_id` (как пересмотр документов, ADR-0010): событие уникально по `(evidence_id, trigger_key = дата окончания)`, создаётся и превращается в задачу ответственному в том же часовом прогоне под тем же advisory-lock; повтор — комментарий. Если форму уже заменила принятая новая — задача не ставится; принятие новой формы закрывает задачу по старой. Обработчики событий реестра берут только `document_id IS NULL AND evidence_id IS NULL`; CHECK `automation_events_subject_check` требует ровно один предмет.
11. **Итоговый PDF документа.** `document_versions.pdf_file_id`, `document_approvals.pdf_sha256`. Автор (владелец или `docs.manage`) прикладывает PDF при отправке (`submit`), без него — 400 `PDF_REQUIRED`; `sha256` пишется в каждое решение круга (отправил, согласовал, этап не требуется). `POST /documents/:id/pdf` на этапах 1–3 возвращает маршрут к началу: решение `returned` с причиной «Заменён итоговый PDF», новый круг, этап «Автор». Утверждение версии без PDF (ушла на согласование до этапа 7) — 409 `PDF_REQUIRED`. Утверждённая версия без PDF показывается «текст не зафиксирован», задним числом PDF не прикладывается (триггер неизменности утверждённых версий не ослабляется). Триггер в БД «утверждение без PDF запрещено» — в релизе-«сужении» перед первой выкладкой: в этом релизе он сломал бы утверждение после отката на предыдущий backend.
12. **Просмотр** во frontend: изображения — blob URL; PDF — `pdfjs-dist` 6.4.299 (отдельный чанк, worker из сборки; шрифты, CMap, ICC и JS-декодеры копируются в `dist/pdfjs/`, в dev раздаются из `node_modules`); `useWasm: false` — CSP портала WebAssembly не разрешает; XFA выключен; первые 10 страниц. Текст и CSV — первые 200 КБ, CSV таблицей. Worker собирается с расширением `.js`: в `mime.types` nginx нет `.mjs`.

## Последствия

- Файлы растут без физического удаления. Помеченные удалёнными остаются на диске до отдельного решения (очистка с резервной копией — по разделу 3.1). `check:integrity` сверяет файлы с метаданными (размер; `--sha` — ещё и sha256) и сообщает о файлах на диске без строки в БД.
- Антивирусной проверки загрузок нет: проверка через ICAP антивируса банка — запланирована, по согласованию с ДИКТ.
- `pdfjs-dist` тянет необязательную `@napi-rs/canvas` (нативная, только для Node): в сборку frontend она не попадает.
- Права не добавлены: загрузка — `ib.work` или права документов, доказательства — `ib.work`, проверка — `evidence.review`, решения — `records.edit`.
