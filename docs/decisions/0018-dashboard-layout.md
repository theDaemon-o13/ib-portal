# ADR-0018. Раскладка дашборда: своя → роли → системная

Дата: 29.10.2026. Статус: принято (релиз 1.1.0, задача 5).

## Контекст
Сотрудникам нужен свой дашборд: скрыть лишнее, поменять порядок и размер. Состав дашборда меняется сам (плитки добавляют и удаляют, поля помечают для аналитики), поэтому раскладка не должна ломаться и не должна жить только в браузере.

## Решение
- **Раскладка** — упорядоченный список `{ key, hidden, size }`; `key` — `kpi:<ключ>`, `tile:<id>`, `widget:<ключ>`; размер `s / m / l` (в сетке виджетов — треть, половина, вся ширина; плитки — 1, 2 ячейки, вся строка); KPI — всегда `s`. При чтении раскладка сливается с текущим набором элементов: неизвестные ключи пропускаются, новые элементы — в конец видимыми (`layout.ts`, `mergeLayout`).
- **Хранение** — таблица `dashboard_layouts`: строка пользователя или роли (ровно одно — CHECK). Действует своя; если её нет — раскладка первой роли пользователя, у которой она задана (по порядку создания ролей); иначе системная (порядок из кода). localStorage — только кэш последней раскладки для первой отрисовки.
- **Права**: своя раскладка — `ib.work` (правит только сам пользователь); раскладка роли по умолчанию — `settings.manage` (настройка интерфейса, как слайды мониторинга), для любой роли, кроме настенного монитора: роль без `ib.work` («Начальник ИБ») задаёт раскладку тем, кто видит дашборд через другую роль. У каждого элемента — требуемое право (сейчас у всех `ib.work`); элементы без права не отдаются.
- **«Сбросить»** физически удаляет строку раскладки (настройка интерфейса, не бизнес-данные); сохранение и сброс — в журнале аудита. Изменение — с `version` (409 при расхождении).
- Seed один раз задаёт раскладку «Начальника ИБ»: сначала просроченное и требующее решения, виджеты сроков — во всю ширину.

## Последствия
- Миграция `dashboard_layouts` (новая пустая таблица), шаг seed `dashboard.role-layouts.v1` (1 строка).
- Перетаскивание — pointer-события без новых зависимостей.
