# ADR-0006. MFA (TOTP) для привилегированных учётных записей — отклонено

Дата: 2026-10-26. Статус: **отклонено 28.10.2026: портал работает только во внутренней сети** (решение владельца проекта). Вместо MFA — ограничение входа администраторов по адресам, ADR-0015.

Исходный текст решения сохранён ниже как история.

## Контекст
Портал должен соответствовать инструкции по парольной защите. Её требования отражены в шаблоне формы «Подтверждение соответствия требованиям парольной защиты»: длина, классы символов, срок действия 90 дней, блокировка, история паролей — выполнены; MFA для привилегированных учётных записей — нет.

## Решение
- Привилегированные учётные записи — пользователи с правами `settings.manage` или `users.manage`.
- Второй фактор — TOTP (RFC 6238, приложение-аутентификатор), без внешних сервисов: подходит для закрытого контура.
- Реализуется отдельной задачей и отдельным ADR с деталями (хранение секрета, коды восстановления, сброс администратором, журнал). Новые зависимости — по согласованию.
- До реализации портал не выкладывается в рабочий контур.

## Последствия
- В CHANGELOG задача записана в разделе «Перед первой выкладкой» (до 27.10.2026 — в «Запланировано» этапа 2).
- Форма «Парольная защита» в доказательной базе до этого будет показывать несоответствие по полю «MFA для привилегированных УЗ».

## Отклонение (28.10.2026)
- Владелец проекта: портал доступен только из внутренней сети банка, MFA не делается и выкладку не блокирует.
- Компенсирующая мера — ADR-0015: вход с правами `settings.manage` или `users.manage` только с адресов `ADMIN_ALLOWED_IPS`.
- Шаблон формы «Парольная защита» не меняется: поле «MFA для привилегированных УЗ» — требование инструкции банка. В форме портала по этому полю указывается несоответствие и компенсирующая мера из ADR-0015.
