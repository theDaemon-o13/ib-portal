# ADR-0016. Массовые действия: предпросмотр, expected, 409, пакеты, журнал

Дата: 28.10.2026. Статус: принято (релиз 1.1.0, задача 1; тот же порядок — у задач автоматизаций в задаче 2).

## Контекст
Нужно удалять и архивировать много записей реестра сразу: выбранные, все по фильтру, все записи реестра. Ошибка здесь стоит дорого: данные банка важнее скорости (CLAUDE.md, раздел 3). Одиночные действия уже есть и пишут историю записи в `audit_log`; массовые должны вести себя так же и не обходить правила раздела 3.4.

## Решение
- **Два шага.** `…/preview` считает, что произойдёт: всего, удалится, уйдёт в архив, вернётся, уже в нужном состоянии, разбивка по причинам. `…/apply` получает те же числа в `expected`; сервер заново считает выборку и, если числа разошлись (кто-то добавил запись, отправил в архив, появилась задача), отвечает **409 `BULK_CHANGED`** с новыми числами в `details.preview` и ничего не меняет. Интерфейс показывает новые числа и просит подтвердить ещё раз.
- **Выборка** передаётся не только списком id: «все N по фильтру» — это условия списка (`q`, фильтр из адреса, архивные, «с задачами») и исключённые вручную id. Сервер применяет к ним тот же код, что и к списку (`selectRecordIds`), поэтому N в интерфейсе совпадает с N на сервере. Явный список id — не больше 5000.
- **Пакеты** по 200 записей, каждый в своей транзакции. Перед удалением пакета зависимости проверяются ещё раз внутри транзакции: запись, у которой зависимость появилась после предпросмотра, уходит в архив, а не удаляется.
- **Журнал:** по каждой записи — та же запись, что у одиночного действия (`register_record.deleted` со снимком значений, `.archived`, `.restored`), чтобы работала история карточки; плюс одна сводная `register_records.bulk_<действие>` на реестр: кто, сколько, id удалённых и архивированных, причины, выборка.
- **Удаление мягкое** (`deleted_at`). Зависимости записи — одно правило для одиночного и массового удаления (`modules/registers/dependencies.ts`): зафиксированные поля, решения другого отдела, доказательства, **открытые задачи по записи**, **ссылки из других неудалённых записей** (поле «Связь с записью»). Запись с зависимостями при массовом удалении уходит в архив, при одиночном — ошибка с причиной (`HAS_TASKS`, `HAS_LINKS` и прежние коды).
- **Права — на маршруте** (раздел 5: «маршрут без явного права не проходит ревью»): поэтому маршруты разделены по праву, а не по полю `action` в теле — `bulk-archive/*` (архив и возврат) — `records.edit`, `bulk-delete/*` и `delete-all/*` — `records.delete`.
- **«Удалить все записи»** — включая архивные; `apply` принимает `confirmName`, сервер сверяет его с названием реестра.

## Последствия
- Миграции нет.
- Одиночное удаление стало строже: запись с открытой задачей или со ссылкой из другого реестра раньше удалялась, теперь — только архив. Ответ с причиной говорит, что сделать («сначала закройте или удалите задачи»).
- Если пакет упал посередине (сбой БД), уже применённые пакеты остаются применёнными, каждый — с записями журнала; повторный предпросмотр покажет остаток. Откат удаления — только восстановлением из резервной копии: восстановления удалённых записей в интерфейсе нет (как и у одиночного удаления).
