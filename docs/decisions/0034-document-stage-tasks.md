# ADR-0034. Задачи по этапам маршрута документа

Дата: 03.11.2026. Статус: принято (релиз 1.6.3).

## Контекст
Маршрут документа (ADR-0024) сообщает, кто должен действовать, только уведомлением «ждёт вас» и строкой «Сейчас у» в реестре документов. Владелец хочет видеть всю работу отдела в разделе «Задачи»: на доске, в нагрузке, в отчёте и в просрочках. До 1.6.3 по документу ставились только задачи «Пересмотреть документ» и «Доработать документ».

## Решение
- **Кому задача.** Тот, кто действует на текущем этапе, получает задачу категории «Документы», причина `stage`. Кто действует, решает `stageHolders` — та же функция, что «Сейчас у» и «ждёт вас». Дополнительно:
  - на этапе 12 «Проверка сотрудниками» все активные сотрудники ИБ (`ib.work`), кроме владельца, получают задачу «Проверить документ» (решение владельца 03.11.2026);
  - на этапе 11 задача ставится только на первый драфт, если документ завёл за владельца другой человек; после возврата у автора остаётся задача «Доработать документ».
- **Синхронизация.** `syncStageTasks` приводит задачи к состоянию маршрута в той же транзакции, что и действие. Её вызывают: создание документа, переходы и возврат, подписание, отмена пересмотра, удаление, архив и возврат из архива, новая версия, смена владельца, изменения ответственных лиц и переводов, а также изменения пользователей — отметка начальника ИБ, отключение и смена ролей.
- **Состояние маршрута** хранится в `tasks.document_state`: «версия:круг:этап[:фаза перевода]».
  - Задача другого состояния или прежнего ответственного закрывается системой: «Выполнено» без проверки, с комментарием.
  - Одно состояние — одна задача на человека.
  - Задачу, которую закрыли вручную или удалили, портал по тому же состоянию не создаёт снова. Если задачу закрыла система, потому что ответственный сменился, а потом вернулся, задача создаётся снова.
- **Сроки:**
  - Этапы 11, 12, 13, 15 «переводы готовы» и 16 — рабочие дни из параметра портала `documents.stageDays`. По умолчанию 5, 3, 3, 3 и 5. Параметр меняет супер-администратор. Срок можно поправить в самой задаче, портал его не перетирает.
  - Этап 14 — ближайший срок ответственного лица, которое ещё не согласовало. Этап 15 «переводы» — ближайший срок языка без файла. Эти сроки задаются для каждого документа в его карточке. Срок задачи идёт за ними, каждое изменение — комментарий в ленте задачи.
- **Без ответственного.** Если у получателя нет `ib.work` или он отключён, задача остаётся без ответственного, с меткой, кому предназначалась. Если отметка начальника ИБ никому не поставлена — метка «Начальник ИБ (не назначен)».
- **Уведомления.** Отдельного уведомления «назначена задача» по таким задачам нет: о том же событии приходит «ждёт вас».
- **Где действие.** Само действие по маршруту выполняется в карточке документа: у маршрута свои проверки (файлы, блокеры, лица, переводы). Задача ссылается на документ. Если исполнитель закрыл задачу на доске, документ остаётся на этапе.

## Последствия
- Миграция `20261103105246_document_stage_tasks`: колонка `tasks.document_state`, в CHECK `tasks_document_check` добавлена причина `stage`. Существующие строки не меняются.
- **Откат на 1.6.2.** Backend 1.6.2 знает причины задач только `review` и `returned`, задача с причиной `stage` ломает ответ списка задач. Перед сменой версии выполняется `UPDATE tasks SET document_reason = 'returned', document_state = NULL WHERE document_reason = 'stage'`, после этого такие задачи для 1.6.2 — «доработка». Решение владельца 03.11.2026.
- На этапе 12 создаётся столько задач, сколько активных сотрудников ИБ. В dev-базе, где прогоны e2e оставляют сотни пользователей, доска показывает не все задачи. Поэтому e2e открывает карточку задачи по ссылке `?task=`.
