## 1. Причина в цифрах

### Что выполняется на каждую находку внутри транзакции «Загрузить» (`applyNodeScan`)

| Шаг | Запросов на запись | Где |
|---|---|---|
| Новое значение списка «Пакет» (у нового пакета) | 2: `aggregate` максимального порядка + `create` | `ensureOption('pkg')` в цикле создания |
| Новые значения «Уровень», «Эксплойт», «Вектор» (у нового текста) | 2 | `ensureOption` в цикле по выбранным строкам |
| Запись реестра | 1: `registerRecord.create` | цикл `toCreate` |
| Строка `audit_log` («создана запись #N из скана») | 1: `auditLog.create` | там же; история записи строится из неё |
| Повторно обнаружена | 3: `registerRecord.update`, `auditLog.create`, `vulnRecord.update` | цикл `reopened` |
| Изменилась (выбрана) | 2: `update` + `audit` | цикл `changed` |
| Пропала (выбрана) → «Устранена» | 3: `update`, `audit`, `vulnRecord.update` | цикл `gone` |
| Связь «запись — узел» и «встречалась в скане», снимок находок | 0: уже `createMany` и `updateMany` одним запросом | `vulnRecord.createMany`, `vulnRecordScan.createMany`, `vulnScan.create` |

Уведомлений и автоматизаций внутри транзакции импорта нет. После фиксации маршрут запускает прогон автоматизаций реестра (`runAutomations`, своя транзакция). Новые записи срока не имеют (срок — от передачи ИКТ), поэтому правила п. 7.4 на импорт не срабатывают: **уведомления владельцу системы на каждую новую запись сейчас нет**, сводное не нужно ★. Поле «Система» только записывается в значения: по нему правила п. 7.4 позже находят владельца.

## 2. Исправление записи

Общие помощники — `backend/src/lib/bulk.ts`:
- `chunkSize(columns)` = min(1000, ⌊65 535 / columns⌋) — лимит параметров одного запроса PostgreSQL;
- `insertAudits(tx, actor, entries)` — `auditLog.createMany` пачками; строки те же, что у `auditSettings` (поля, `summary`, `actorRoles`, `ip`), порядок тот же;
- `updateRecordValues(tx, rows)` — `UPDATE register_records … FROM jsonb_to_recordset($1)` пачками по 1000 строк: `values`, `search_text`, при необходимости `manual_field_ids`, `version + 1`, `updated_at`. Один параметр на пачку.

★ **Id новых строк — в приложении** (`randomUUID`) до вставки, затем `createMany`. Prisma 7.10.0 умеет `createManyAndReturn` для PostgreSQL, но порядок `RETURNING` в многострочном `INSERT` документацией не гарантирован; свои id дают точное соответствие «строка файла → запись» для журнала и сравнения. `createManyAndReturn` — только у задач, где нужен номер из автоинкремента (сопоставление по id).

Импорт скана (`applyNodeScan`):
- значения списков — одним проходом: новые подписи по полям собираются, один `aggregate` на поле, `createMany`; порядок `sort_order` тот же, что был (по первому появлению);
- поиск значения списка по подписи — по индексу (`Map`), не перебором (на 3390 пакетах перебор — миллионы сравнений и в предпросмотре);
- записи — `createMany` пачками, журнал — `insertAudits`; изменения («Повторно», «Изменились», «Пропали») — `updateRecordValues` + `insertAudits`, `vuln_records` — `UPDATE … WHERE record_id = ANY($1)` одним запросом на группу; порядок строк журнала прежний (созданные, повторно, изменились, пропали, итог скана);
- записи узла уже читаются одним запросом (`nodeRecords`, `FOR UPDATE`) — остаётся;
- атомарность прежняя: одна транзакция, всё или ничего;
- параллельный импорт в узел: `pg_try_advisory_xact_lock(<пространство>, hashtext(<id узла>))` в начале транзакции; занято — 409 `IMPORT_IN_PROGRESS` «В этот узел уже идёт импорт». ★ Вариант `try`, а не ожидание: ожидающий запрос всё равно получил бы `IMPORT_STALE`. Импорт с группы (узла ещё нет) — блокировка по «группа + тип».

`withTx(db, fn, opts?)` принимает `{ timeout, maxWait }`; глобальные 15 с не меняются. `BULK_TX = { timeout: 120_000, maxWait: 10_000 }` в `lib/db.ts` с комментарием: запас для массовых операций, не решение. Применяется: импорт скана, передача ИКТ, продление и отмена, перенос, применение импорта Excel, прогон автоматизаций.

Цель на dev: 3390 строк — меньше 10 с, 10 000 — меньше 30 с; число запросов ограничено сверху `a + b × пачки`.

**nginx:** `proxy_read_timeout 120s` (`frontend/nginx.conf`, не меняется). Совпадает с `BULK_TX`: если применение когда-нибудь подойдёт к 120 с, браузер получит 504, а транзакция может зафиксироваться. После исправления 10 000 строк должны идти в разы быстрее — фактическое время в отчёте.

★ Прогон автоматизаций в задании не назван, но найден по п. 1 (тот же цикл по записям в транзакции) и падает на тех же 3390 записях, когда их срок истечёт. Поведение (по задаче на запись) не меняется — меняется только способ записи. Сводные задачи по просрочке — отдельное решение владельца, в отчёт.

## 4. Сообщения об ошибке

- Ошибка применения импорта скана и импорта Excel, кроме ожидаемых `AppError` (409, 400…): ответ 500 `IMPORT_FAILED` «Импорт не завершён, ничего не записано. Сообщите администратору номер запроса <id>». Таймаут транзакции (P2028) — так же.
- В лог — `error` «импорт не выполнен»: узел, число строк, шаг (`progress.step`: «проверка», «значения списков», «новые записи», «журнал», «скан», «изменения», …), длительность, id запроса, текст ошибки.
- ★ Номер запроса: `genReqId` Fastify — 8 случайных шестнадцатеричных символов вместо «req-1, req-2…» (те повторяются после перезапуска); тот же `reqId` уже есть в каждой строке лога.
- Frontend: «Загрузить» неактивна, пока идёт запрос, на ней «Загружается…»; повторное нажатие не отправляет второй запрос (защита по `ref`, не только по состоянию).

## 5. Колонки отчёта Linux (Debian)

В `scan-parser.ts`, рядом с остальными синонимами (`HEADER_MATCH`):
- «Вектор» — как «Сетевой вектор»;
- заголовок, начинающийся с «Описание» («Описание (из CVE, англ.)»), — как «Краткое описание»;
- «Задача №» — `IGNORED_HEADERS`: в предпросмотре серой строкой «Колонка „Задача №“ не используется» (новое поле `info` сводки, не `warnings`);
- предупреждение о реально отсутствующих колонках («Обнаружений») остаётся.

Значения вектора (`OPTION_ALIASES.vector`), существующие в списке «Сетевой вектор» — «Удалённо (сеть)» (`remote`) и «Локально» (`local`):

| В файле Linux | В списке |
|---|---|
| Сеть | Удалённо (сеть) |
| Локально | Локально |
| Смежная сеть | нет такого — добавится новым значением «Смежная сеть» ★ |
