# План релиза 1.13.8 — Самооценка: домен «Контроль ИИ»

Задание: `docs/tasks/1.13.8-ai-domain.md` (текст владельца от 11.11.2026; номер 1.13.8 вместо 1.13.7 — решение владельца, см. шапку задания). От `v1.13.7`. **Схема БД не меняется**: методика — строка `assessment_methodologies` (код, версия, `content jsonb`, одна активная на код — частичный уникальный индекс `assessment_methodologies_active_uq`), оценка держит снимок методики в `methodology_snapshot`, ответы — строки `assessment_answers` по кодам разделов снимка (ADR-0025). Новая версия ложится без миграции. Новых переменных `.env`, прав и зависимостей нет. **Выкладка — замена backend и frontend и шаг `migrate`:** методика v2 попадает в базу через seed.

Решения «выбрано по умолчанию» помечены ★ — для отчёта.

## 1. Методика v2 (seed)

- `backend/prisma/seed/assessment-methodology-v2.json` — копия v1 (домены 1–10, шкала, уровни, правила без изменений) + домен 11 из задания с `"inTotal": false`. ★ Код `cyber-express-v2`, версия 2, название то же (по именованию владельца «cyber-express-v2»; v1 остаётся `cyber-express-v1`). Тест сверяет: v2 без домена 11 равна v1 до байта.
- `seed/assessment.ts`: список версий `[v1, v2]`; каждая создаётся один раз (как сейчас), содержимое не перезаписывается. **Активной назначается последняя версия списка** при каждом прогоне seed (идемпотентно): если активна не она — у остальных `is_active = false`, у неё `true`, запись `assessment.methodology_activated` в журнал. Так после отката на 1.13.7 с ручным возвратом v1 повторное обновление снова включит v2. Таблица только пополняется: удаления строк нет.
- `check:integrity`: активная методика ровно одна и это последняя версия из seed (предупреждение, не ошибка).

## 2. Расчёт (`lib/assessment-score.ts`)

- `MethodologyDomain.inTotal?: boolean` (нет поля — `true`). `DomainScore.inTotal`, `Gap.inTotal`.
- `total`, `max`, `level` (включая «Результативную КБ» и ключевые разделы) — только по доменам с `inTotal ≠ false`: у v2 — «N из 96», пороги прежние.
- `answered`, `sections`, `preliminary` — по всем разделам снимка: у v2 — «k из 28», фиксация только при 28 из 28.
- ★ `distribution` (кольцо «Распределение ответов») — по всем отвеченным разделам, включая 11.x: это распределение ответов, а не итог.
- `gaps` — все разделы (План и слабые места включают 11.x); `gapPoints` («баллов к итогу при достижении целей») — только разрывы доменов в итоге.
- Замороженные `result` оценок v1 без новых полей читаются через `normalizeScore` (`inTotal: true` по умолчанию) — ответ API всегда полный.
- `compareScores`: домен, которого нет в прошлой оценке, — `sum: null, avg: null` (уже так).

## 3. Сервис и API

- `POST /assessments/:id/upgrade-methodology` `{version}` — «Обновить методику»: только черновик (409 `NOT_DRAFT`), только если активная методика отличается от снимка по коду или версии (409 `SAME_METHODOLOGY`); одной транзакцией: новый снимок и `methodology_id`, строки ответов для новых кодов разделов (пустые), существующие ответы, цели и комментарии не трогаются, `version + 1`, журнал `assessment.methodology_upgraded` («… методика обновлена: cyber-express-v1 v1 → cyber-express-v2 v2, новых разделов 4»).
- `GET /assessments/:id`: `methodologyUpgrade: { code, version, name } | null` — куда можно обновить (черновик и активная отличается), иначе `null`.
- Новая оценка — на активной (v2); копия переносит ответы и цели по совпадающим кодам (уже так), 11.x пустые.
- `GET /assessments/compare`: у строк разделов `inA: boolean` — раздел есть в снимке первой оценки; у доменов `a: null`, когда домена нет в первой.
- Zod-схемы: `inTotal` у домена методики (optional), у `DomainScore` и `Gap` (обязательный), `methodologyUpgrade`, `inA`. `npm run openapi:export` → `gen:api`.

## 4. Excel

- Выгрузка: «Домены» и «Ответы» — колонка «В итоге» (да/нет) после «Домен»; «Оценки» — «ИИ: сумма», «ИИ: максимум», «ИИ: заполнено» (сумма по доменам вне итога; у v1 — пусто). ★ Лист «Методика» — из снимков оценок книги: по одной группе строк на каждую встретившуюся пару «код + версия», первые колонки «Методика», «Версия», затем «В итоге»; без оценок в книге — активная методика.
- Импорт листа «Чек-лист»: домен снимка, ни один раздел которого не найден в файле, — строка «Домен 11 «Контроль ИИ» в файле отсутствует — разделы остаются пустыми», его коды не повторяются в «Нет в файле: …». Лист «Ответы» принимает 11.1–11.4 автоматически (разделы — из снимка).

## 5. Экраны (frontend)

- Шапка раздела: текст без «10 доменов и 24 разделов». У черновика с `methodologyUpgrade` — кнопка «Обновить методику до v2» → окно подтверждения («ответы 1–10 сохранятся, домен 11 добавится пустым, итог не изменится») → `POST`.
- Чек-лист: домен вне итога в списке слева — чип «вне итога»; в заголовке домена — пояснение.
- Обзор: карточка уровня без изменений (при доменах вне итога — уже 6 колонок, рядом карточка «Контроль ИИ: X из 16» на 3 колонки: средний балл, заполненность, разница с прошлой оценкой или «нет в прошлой оценке»); «Готовность» — k из 28. Радар — 11 осей, подпись оси «11. Контроль ИИ» + «вне итога». Средний балл по доменам — чип «вне итога». Слабые места и План — с 11.x (чип «вне итога»).
- Презентация: первый слайд — строка «Контроль ИИ: X из 16 (вне итога)»; радар и план — с доменом 11.
- История → Сравнение: раздел, которого нет в первой оценке (`!inA`), — «нет в прошлой оценке» вместо разницы.
- `logic.ts`: `extraDomains(score)`, `domainShort(11)`, `isInTotal`.
