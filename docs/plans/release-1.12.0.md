# Релиз 1.12.0 — «Осведомлённость: макет письма, журнал отправок, выгрузка готового письма»

Задание — `docs/tasks/1.12.0-awareness.md`. Режим работы — `docs/tasks/README.md`: план без ожидания подтверждения, вопросы с разумным вариантом решаются по умолчанию (помечены **«выбрано по умолчанию»**). Поверх `v1.11.0`, ветка `release/1.12.0`. На прод в понедельник уходит 1.9.0 → 1.13.0 одним архивом (README).

ADR: **0044** «Макет письма в коде, содержимое в базе», **0045** «Выгрузка готового письма: .eml вместо .msg», **0046** «Файл письма .eml: тип message/rfc822 только от сервера».

## 1. Что меняется по зонам

| Зона | Что |
|---|---|

| backend | `export/layout.ts` (макет), `export/content.ts` (содержимое редактора → почтовый HTML), выгрузка с сохранением файла, предпросмотр, «Оформление писем», регистрация отправки, поля «Рассылок» seed'ом, `seed:demo` |
| frontend | Поля «Заголовок», «Метка», «Тема общая»; блок «Выделенный блок» в редакторе; «Предпросмотр как в почте»; «Скачать для Outlook (.eml)»; новый диалог «Отметить отправленным»; «Настройки → Оформление писем» (вместо вкладки «Подпись ИБ», подпись — внутри) |
| deploy | Только файлы выпуска: `deploy/prechecks/1.12.0.md`, `1.12.0-from-1.9.0.md`, проверки `smoke.sh` |

Права не меняются: письма, шаблоны, предпросмотр, выгрузка, отметка — `ib.work`; «Оформление писем» — `settings.manage` и `ib.work` (как «Подпись ИБ»); служебный администратор — 403 (модуль вне группы `config.service`).

## 2. Схема (миграция `awareness_layout`)

```sql
ALTER TABLE awareness_templates ADD COLUMN header_ru text NOT NULL DEFAULT '', ADD COLUMN header_tj text NOT NULL DEFAULT '',
  ADD COLUMN label_ru text NOT NULL DEFAULT '', ADD COLUMN label_tj text NOT NULL DEFAULT '', ADD COLUMN subject_both text NOT NULL DEFAULT '';
ALTER TABLE awareness_letter_versions — те же пять колонок;
CREATE TABLE awareness_layout (id smallint PK DEFAULT 1 CHECK (id = 1), dept_ru, dept_tj, email, closing_ru, closing_tj, footer_ru, footer_tj,
  label_urgent_ru, label_urgent_tj, label_planned_ru, label_planned_tj, tj_hint text NOT NULL, logo_file_id uuid NULL → files,
  version int, updated_by uuid NULL → users, updated_at);
CREATE TABLE awareness_letter_exports (id, letter_id → letters, version_id → versions, langs text CHECK IN ('both','ru','tj'),
  file_id → files, sha256, created_by → users, created_at) — только пополняется (триггер);
ALTER TABLE awareness_letter_events ADD COLUMN langs text NULL CHECK, ADD COLUMN recipients text NULL, ADD COLUMN export_id uuid NULL → exports;
CREATE OR REPLACE FUNCTION file_active_refs — + awareness_layout.logo_file_id, + awareness_letter_exports.file_id.
```

- Колонки, а не JSON в `app_settings`, у оформления (**выбрано по умолчанию**). Логотип — внешний ключ на `files`: его учитывает `file_active_refs()`, и часовая очистка непривязанных файлов его не тронет.
- **Влияние на данные:** колонки и пустые таблицы; строку `awareness_layout` с заглушками создаёт seed. Существующие письма, версии, события, шаблоны и записи «Рассылок» не меняются (0 строк). Триггеры «версии только пополняются» и «у замороженного письма меняются только archived_at, version, updated_at» не мешают: `ADD COLUMN … DEFAULT` строки не переписывает через триггеры.
- **Откат на 1.11.0 без отката базы:** 1.11.0 новые колонки и таблицы не читает; вставки 1.11.0 в версии и события проходят (у колонок есть значения по умолчанию или NULL). Новые поля «Рассылок» для 1.11.0 — обычные поля реестра. Файлы `.eml` (`message/rfc822`) 1.11.0 отдаёт так же, как любые: только `attachment`, предпросмотра нет. Проверяется на репетиции.

## 3. Макет (ADR-0044)

- `export/layout.ts` — чистая функция `renderMail(cards, opts)`: таблицы и inline-стили по эталону `docs/email/layout-reference.html`.
    - внешняя таблица 100% `#F1F5F9`; карточка 600 (`width="600"`, `max-width:600px`, `<!--[if mso]>` таблица);
    - `@media (max-width:620px)` в `<style>` головы — как в эталоне: единственный класс, `wrap`/`pad`, без него письмо остаётся рабочим;
    - шапка `#1E3A8A`: логотип 238 px с `alt` = название отдела, без логотипа — название отдела текстом; «Заголовок» 24 px белый жирный; «Метка» 12 px, заглавные, разрядка, `#BFDBFE`;
    - тело: Arial 15/23 `#0F172A`;
    - подпись: прощание, отдел жирным, адрес — `mailto:` с `white-space:nowrap`;
    - подвал: 12 px серый над тонкой линией; пустой — не выводится;
    - RU+TJ: две карточки через 24 px, над первой справа ссылка-подсказка на якорь `#tj`; один язык — одна карточка без подсказки;
    - логотип — один Content-ID `portal-logo` на обе карточки;
    - скрытый прехедер — первая фраза текста первой карточки.
- `export/content.ts` — «содержимое редактора → почтовый HTML», чистая функция без DOM. Делает так:
    - теги белого списка получают inline-стили макета;
    - `div[data-callout]` превращается в таблицу с полосой 4 px: info — `#EFF6FF`/`#2563EB`, warn — `#FEF2F2`/`#DC2626`;
    - ведущие `&nbsp;` и пробелы в начале абзаца вырезаются;
    - изображения — через Content-ID, как в 1.9.0.
- Отклонения от эталона (**выбрано по умолчанию**):
    - строки-распорки `&nbsp;` между блоками эталона заменены отступами `margin` / `padding` у таблиц: одинаково в Outlook и веб-почте;
    - плейсхолдеры `{{подпись: отдел}}`, `{{подпись: примечание внизу}}` — это поля «Оформления писем»;
    - в предпросмотре и «Скопировать с оформлением» изображения — `data:` (iframe и буфер не видят `cid:`); остальной HTML совпадает с `.eml` байт в байт.
- **Подпись.** Подпись макета выводится всегда. Исключения (**выбрано по умолчанию**), чтобы письма 1.9.0 не получили двойную подпись:
    - в тексте есть блок «Подпись ИБ» — блок подставляется как в 1.9.0, а подпись макета не выводится;
    - отправленная версия 1.9.0 (версия `sent` без снимка выгрузки) — подпись уже в тексте.
- **Снимок отправленного.** При отметке файл `.eml` сохраняется (п. 5). Повторная выгрузка отправленного письма на том же языке отдаёт сохранённый файл, на другом — собирается с текущим макетом.

## 4. Поля, редактор, предпросмотр, выгрузка

- `TemplateTexts` получает `headerRu`, `headerTj`, `labelRu`, `labelTj`, `subjectBoth` — простой текст, до 300 символов, без HTML (экранируется при выводе).
    - Переменные `{{…}}` в этих полях работают и проверяются как в теме: незаполненные — 400 `UNFILLED_VARIABLES`; `{{подпись}}` здесь — 400.
    - Пустые значения при выгрузке:
        - «Заголовок» — тема языка;
        - «Метка» — из настроек по типу письма;
        - «Тема общая» — `<тема RU> | <тема TJ>` (в 1.9.0 разделитель был « / »).
    - Новое письмо получает метки по типу из настроек; письмо из шаблона — значения шаблона.
- Редактор (TipTap): узел `callout` (`<div data-callout="info|warn">`, содержимое — абзацы), кнопка «Выделенный блок» с выбором вида; заголовок блока — первый абзац жирным.
- Санитайзер: `div` получает атрибут `data-callout` только со значениями `info` и `warn`, иное вырезается; остальной белый список прежний.
- Предпросмотр:
    - `POST /awareness/mail-preview` (`ib.work`) — содержимое из формы (несохранённые правки и шаблоны) проходит санитайзер и макет, ответ — HTML;
    - на frontend — `iframe sandbox=""` (без `allow-scripts`) с `srcdoc`; ширина «Компьютер 600 / Телефон 375», язык «RU+TJ / RU / TJ». Ссылка на портал — 400, как при сохранении.
- Выгрузка `GET …/export.eml?lang=`:
    - основная кнопка — «Скачать для Outlook (.eml)»;
    - `X-Unsent: 1`, `Content-Language`, Subject по RFC 2047, без From, To, Cc и Date;
    - `multipart/alternative` → `text/plain` и `multipart/related` (HTML, логотип, изображения);
    - имя файла `<Тема RU>_<RU-TJ|RU|TJ>_<ГГГГ-ММ-ДД>.eml`; запрещённые в Windows символы → «_»;
    - лимит размера («Параметры портала», 1.9.0) — по готовому `.eml`, 413;
    - каждая выгрузка сохраняется файлом (`files`, `message/rfc822`) и строкой `awareness_letter_exports`; в журнал пишется `exported` с языками и sha256; запись «Рассылок» не создаётся;
    - формирование детерминированное: разделители частей — из sha256 содержимого, поэтому одинаковые входные данные дают одинаковые байты.
- «Скопировать с оформлением» — HTML макета с `data:`-изображениями. Печать — как в 1.9.0.
- После скачивания — подсказка «Когда отправите, нажмите „Отметить отправленным“».

## 5. Регистрация отправки и «Рассылки»

- Диалог «Отметить отправленным»:
    - дата: не позже сегодня (`APP_TZ`) и не раньше утверждения письма (у утверждённых; иначе 400 `BAD_DATE`);
    - языки — из последней выгрузки текущей версии;
    - «Получатели» — по умолчанию из последней отметки любого письма;
    - аудитория — как в 1.9.0;
    - «Файл письма» — последняя выгрузка этой версии с этими языками; если выгрузки нет, портал собирает файл в момент отметки (той же функцией).
- Событие `sent`: `langs`, `recipients`, `export_id`.
- Новые поля «Рассылок» — seed `awareness.v3`: идемпотентно, в существующий системный реестр по `systemKey`.
    - Поля: «Шаблон» (текст, «измерение»), «Языки» (список RU+TJ / RU / TJ), «Получатели» (текст), «Файл письма» (тип «Файл»).
    - Если в реестре уже есть поле с таким названием без системного ключа, новое получает имя «<название> (системное)», в выводе seed появляется строка. Запрос до выкладки это показывает.
- Отметка заполняет запись:
    - «Шаблон» — название шаблона на момент отправки или «Без шаблона»;
    - «Языки», «Получатели»;
    - «Файл письма» — ссылка `register_record_files` на тот же файл в той же транзакции.
- Ручной ввод: у поля «Шаблон» системного реестра «Рассылки» — подсказки из названий шаблонов (`datalist`, **выбрано по умолчанию**: условие по системным ключам реестра и поля, без нового общего механизма).
- Excel: колонка «Файл» выгружается как «имя; sha256: …» у всех полей «Файл» всех реестров (**выбрано по умолчанию**: одна общая функция; для полей «Файл» DLP — тоже полезно). Содержимое файла в Excel не попадает.
- Дашборд и монитор — без изменений.

## 6. Файл .eml (ADR-0046)

Хранить файл, а не пересобирать по sha256. Почему:
- макет и настройки меняются, и пересборка не дала бы тех же байтов;
- доказательство — именно то, что отправили.

Тип `message/rfc822` создаёт только сервер (выгрузка, отметка). `POST /files` его по-прежнему не принимает: список разрешённых типов для загрузки не меняется.

Выдача — общий маршрут `/files/:id/content`:
- всегда `attachment`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`;
- доступ — по ссылкам: поле «Файл» записи реестра и выгрузка письма — `ib.work`;
- предпросмотра для этого типа нет (`previewKind` → none).

## 7. «Оформление писем»

«Настройки → Оформление писем» вместо «Подпись ИБ»; редактор подписи — внутри этой вкладки, `{{подпись}}` работает как раньше.
- Поля: логотип (PNG до 100 КБ, через `files`: проверка типа по содержимому и размера), название отдела RU/TJ, адрес ИБ, прощание RU/TJ, подвал RU/TJ, метки по умолчанию для срочного и планового RU/TJ, подсказка о таджикском тексте.
- `GET /awareness/layout` (`ib.work`), `PUT /awareness/layout` (`settings.manage` + `ib.work`, `version`, журнал).
- Seed — заглушки:
    - «Отдел информационной безопасности» / «Шуъбаи амнияти иттилоотӣ»;
    - `security@example.org`;
    - «С уважением,» / «Бо эҳтиром,»;
    - метки: срочное — «ВАЖНАЯ ИНФОРМАЦИЯ» / «МАЪЛУМОТИ МУҲИМ», плановое — «ПАМЯТКА» / «ЁДДОШТ»;
    - «Матни тоҷикӣ дар поён ↓»;
    - без логотипа и подвала.
