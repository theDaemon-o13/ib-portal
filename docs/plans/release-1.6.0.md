# План релиза 1.6.0: реестр активов

Спецификация — `docs/specs/assets.md` (согласована 02.11.2026). Задание владельца — `docs/plans/task-1.6.0-assets.md` (обезличенная копия, оригинал хранится вне репозитория). Порядок: 1.6.0 — реестр активов, цепочки задач — 1.7.0. Прототип не ждём: карточки — обычные экраны реестров, сверка — отдельная страница.

Миграций нет, коды прав не меняются. Новая прямая зависимость backend — `saxes` 5.0.1, решение владельца; в образе она уже была как зависимость exceljs. Сборка релиза — только при зелёных typecheck, lint, test, test:db, e2e.

## Решения владельца (02.11.2026)
1. **`saxes`** — прямая зависимость, версия как у exceljs (5.0.1). Разбор без DTD и внешних сущностей; тест на файл с `<!DOCTYPE` и сущностью — отклоняется.
2. **Новых видов вычисляемых полей нет:**
    - «Покрытие защиты» — служебный список, который пишет только адаптер KSC; вручную не меняется (служебные поля конструктор умеет).
    - «Пересмотр до» — существующий вычисляемый срок: «Дата классификации» + 183 дня. Постоянного числа дней правило не знает. Поэтому оно задано по списку категорий, 183 дня у каждой: без категории срока нет, это ловит сверка. У значимых продуктов категория есть всегда.
    - RTO и RPO — текст, в подсказке поля таблица по категориям. Для этого у поля появилась настройка «Подсказка», без миграции. В сверке — «значимый продукт без RTO/RPO» (2.3).
3. **Реестр сервисов — через адаптер**, служебное «Ключ компонента» = «компонент / продукт» без регистра и пробелов по краям. Вычисляет адаптер, вручную не правится.
4. **Таблица «команды → продукты» пуста по умолчанию.** Команда без соответствия — продукт с её именем, блок «Будут созданы продукты» с подсказкой про «Параметры портала». Импорт не блокируется.
5. **Задание** — обезличенная копия в репозитории, оригинал в `~/ib-portal-private/`. В git оригинала нет ни в одной ветке.

## Сделано (ветка `feature/assets`, без коммита, кроме копии задания)
- Профили сканирования VM, «Сменить тип узла», импорт с группы, регулярность сканирования (`docs/specs/vulnerabilities.md`, 2а).
- «Настройки → Параметры портала», только супер-администратор.
- Три реестра и seed v2. Первая редакция на dev доведена на месте, `check:integrity` в порядке.
- Разбор SpreadsheetML и `.xlsx` в один вид (`lib/spreadsheetml.ts`).
- Конвейер импорта расширен для адаптеров (ADR-0032): служебные поля адаптера, поля «только у новой записи», область «Нет в файле», новые значения списков, записи других реестров при применении, блоки предпросмотра со снятием.
- Адаптер KSC: тип отчёта, обрезанный отчёт, дубли, правила типа, поля по каждому отчёту, «Нет в файле» с областью «В KSC = Да».
- Адаптер реестра сервисов: заголовки в строке 6, перевод шкалы и «Класификации», IP:порт, нормализация ОС, продукты и хосты.
- Сверка — 30 проверок по разделам 1.2, 2.2, 2.3, 3.2, 5.2, 8.2, 9.2, 9.3 (спецификация, раздел 5).
- Интерфейс:
    - кнопки «Импорт реестра сервисов» и «Импорт отчёта KSC»;
    - блоки в окне предпросмотра;
    - подсказка поля в карточке и в конструкторе;
    - ссылки на три реестра на экране «Активы».
- Попутно исправлены ошибки:
    - применение импорта считало архивные поля изменившимися: импорт в реестр с архивным полем не проходил никогда (было и в 1.5.0);
    - красные тесты прошлого шага.
- Обезличены тестовые данные 1.5.0: имена хостов и адреса в фикстуре скана и прототипах, домен в примерах почты, авторы в свойствах файлов фикстур. В истории git прежние версии остаются; переписывать историю — решение владельца.

## Проверка
- **Unit:** SpreadsheetML (`ss:Index`, `ss:MergeAcross`, DateTime, отказ на `<!DOCTYPE` и `<!ENTITY`, лимит строк); тип отчёта, обрезанный отчёт, дубли, правила типа; перевод шкалы, IP:порт, нормализация ОС, ключ компонента.
- **DB:**
    - три отчёта KSC подряд обновляют каждый свои поля;
    - повторная загрузка ничего не меняет;
    - «Нет в файле» — только по развёртыванию и только «В KSC = Да»;
    - обрезанный и ненужный отчёт не создают предпросмотра;
    - реестр сервисов: продукты и хосты создаются только при применении, снятые хосты — нет, отмена ничего не оставляет, продукт после предпросмотра — `IMPORT_STALE`;
    - служебные поля — 409;
    - seed идемпотентен, доведение на месте не дублирует поля и сохраняет выбор значений;
    - каждая проверка сверки, включая «Нет данных»;
    - маршрут адаптера: права, чужой реестр, `skip`, применение без тела.
- **E2E:** импорт реестра сервисов со снятыми хостами, отчёт о развёртывании, обрезанный отчёт, сверка со ссылками, параметры портала.
- **Объём:** спецификация, раздел 9 — 5000 устройств: предпросмотр 1,3 с, применение 10 с.
