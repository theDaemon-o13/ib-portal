# План релиза 1.13.6 «Почта ответственных лиц и копирование полей»

Задание — `docs/tasks/1.13.6-responsible-email-copy.md`. Ветка `release/1.13.6` от тега `v1.13.5`. Режим — `docs/tasks/README.md`: вопросы закрываются вариантом по умолчанию (помечен «по умолчанию»).

## Хранение — без миграции

- **Справочник.** Записи лежат в `app_settings` `documents.partyDirectory`, схема значения — `z.strictObject`.
    - Если добавить `email` прямо в запись, backend 1.13.5 после отката прочитает лишний ключ как «справочник повреждён» (500) — откат сломается.
    - Поэтому почта хранится **отдельным ключом** `app_settings` `documents.partyDirectoryEmails`: `{ emails: { <id записи>: <почта> } }`. Пустая почта — ключа нет. Основное значение не меняет формат.
    - Откат на 1.13.5: второй ключ не читается, справочник работает. Если в 1.13.5 правили записи, почты сохраняются: они привязаны к id. После повторной выкладки 1.13.6 почты снова видны.
    - Запись под той же блокировкой (`pg_advisory_xact_lock`), одной транзакцией с журналом. `check-integrity` проверяет схему второго ключа и сообщает о почтах без записи (только отчёт).
- **Лицо в документе.** У `document_parties` уже есть колонка `email` (text NOT NULL DEFAULT ''). Её ввели до 1.4.0, она отдаётся в API, в карточке 1.13.5 показывается текстом.
    - 1.13.6 снова пишет в неё. Схема не меняется, `migrate` не нужен.
    - Откат: 1.13.5 почту не пишет, но показывает её у лица текстом (« · ivanov@example.com»).
- Строки «до 1.4.0» с почтой остаются как есть. Новых значений автоматически не появляется: из справочника в старые документы ничего не дописывается.

## Почта

- Необязательная. Обрезка пробелов, нижний регистр, не длиннее 254 символов, формат — как у адресов в «Получателях уведомлений» (`lib/email.ts`, общая проверка). Неверный адрес — 400 `BAD_EMAIL`.
- В справочнике та же почта у другого человека — предупреждение `sameEmail`, не запрет (как `sameName`).
- Правило «тот же человек» в документе не меняется: ФИО + должность, «ё» = «е». Почта в него не входит.
- **Дописать или исправить почту лицу вручную — да, по умолчанию.**
    - Делает автор, там же, где ведёт лиц: драфт и «Согласование».
    - `PATCH /documents/:id/parties/:partyId` с `email`; кнопка «Почта» у лица.
    - В журнал — `document.party_updated` с изменением «Почта» (было → стало).
    - Можно и у согласовавшего: почта — справочная, на согласование не влияет.

## API

- Справочник:
    - `GET` — `email` у записи;
    - `POST` — `email?`, в ответе `sameEmail`;
    - `PATCH` — `email?`.
- Документы:
    - `POST …/parties` и `POST …/parties/batch` — `email?` у человека;
    - `PATCH …/parties/:id` — `email?`.

## Frontend

- **Справочник:**
    - колонки ФИО, Подразделение или должность, Почта, Активно;
    - поле «Почта» в формах добавления и правки, предупреждение о повторной почте;
    - поиск по трём полям;
    - у каждого поля — кнопка копирования.
- **Мультивыбор лиц:**
    - вторая строка пункта — должность · почта;
    - поиск — и по почте;
    - ручная строка — ФИО, должность, почта.
- **Карточка документа:**
    - у ФИО, должности и почты каждого лица — кнопка «Копировать» (значок, всегда видна, `aria-label` «Копировать ФИО Иванов И.И.»);
    - над списком — «Копировать все ФИО / должности / почты»: по строке на значение в порядке списка, пустые пропускаются. Уведомление — «Скопировано» или «Скопировано: 3».
- **Буфер обмена (`lib/clipboard.ts`):**
    - сначала `navigator.clipboard.writeText`;
    - не вышло (нет защищённого контекста, отказ браузера) — временное `textarea` и `document.execCommand('copy')`;
    - оба не сработали — ошибка «Не удалось скопировать — выделите текст вручную».
    - Прод открывается только по HTTPS: nginx слушает `8443 ssl`, compose публикует только 443, страницы по другому адресу перенаправляются на `PORTAL_URL`. Запасной путь нужен на случай отказа браузера.
- **Чистый текст:** копируется только строка без пробелов по краям; HTML в буфер не кладётся.

## Тесты

- **DB:**
    - почта нормализуется и сохраняется;
    - неверная — 400;
    - `sameEmail`;
    - второй ключ, основное значение без `email` — его читает схема 1.13.5;
    - одно лицо и пачка с почтой из справочника и вручную;
    - правка почты в справочнике не меняет документы;
    - старые лица без почты читаются;
    - правка почты лица — журнал.
- **Unit frontend:** `clipboard.ts` (`writeText`, запасной путь, ошибка), `copyLines` (по строке, пустые пропущены, края обрезаны), поиск по почте, сборка пачки с почтой.
- **e2e:**
    - лицо с почтой в справочнике → добавить в документ → скопировать ФИО, почту и должность по отдельности, прочитать буфер;
    - «Копировать все ФИО» для трёх лиц.
    - Chrome через CDP: `Browser.grantPermissions` `clipboardReadWrite`, `clipboardSanitizedWrite` — аналог разрешения Playwright (Playwright в проекте не используется).
- Скриншоты справочника и карточки с кнопками копирования: обе темы, 1440 и 375 px.
