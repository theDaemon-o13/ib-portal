# План релиза 1.6.1

Два изменения: исправление ключа «Компонентов» (ошибка 1.6.0) и мягкое удаление с корзиной. Решения владельца — 02.11.2026.

Порядок работ: ключ компонентов → миграция и backend удаления → frontend → полный прогон → сборка `make-release.sh --from 1.6.0`.

## 1. Ключ компонентов (исправление 1.6.0)

**Ошибка.** На реальном реестре сервисов (451 строка) 371 строка отклонена как повтор «Ключа компонента». Строка файла — экземпляр компонента (развёртывание), а не компонент: один компонент продукта есть в Prod и Test на разных серверах (176 случаев) и в нескольких экземплярах в одной среде на разных IP (nginx, postgres).

**Исправление.**
- «Ключ компонента» = «Компонент / Продукт / Среда / IP:порт», части без регистра и пробелов по краям. Нет порта — только IP; нет IP — без адреса; нет среды — без среды; продукт входит всегда (как в 1.6.0). На реальном файле остаётся один настоящий повтор — его владелец удалит в файле.
- Заголовок записи «Компонентов» — новое служебное поле «Экземпляр»: «b2b-api · Prod · 10.0.0.5:8070». Заголовок у конструктора — одно поле, поэтому «Компонент» остаётся чистым именем (фильтр и группировка по нему), а «Экземпляр» показывается в списках, связях и сверке. Его пересчитывает портал при любой записи (форма, импорт) из «Компонента», «Среды», «IP-адреса» и «Порта»; вручную не правится (409). Для новой записи обязателен «Компонент».
- Seed, однократно (`system.register.assets.components_instance.v1`): поле «Экземпляр» становится заголовком, ключ и заголовок существующих записей пересчитываются (с записью в журнал, `user_id` пусто). Совпали новые ключи у неудалённых записей — записи не склеиваются: seed останавливается со списком, транзакция откатывается. На проде записей «Компонентов» нет; на dev пересчитано 12 из 12.
- Сверка: `components.env_address_clash` (9.3) — «На одном IP:порт нет компонентов разных сред». Только адреса с портом; нарушители — все компоненты такого адреса.

**Влияние на данные:** миграции нет; seed пересчитывает «Ключ компонента» и заполняет «Экземпляр» у существующих записей «Компонентов» (на проде — 0 строк). Откат на 1.6.0: поле «Экземпляр» остаётся заголовком (обычное текстовое поле), ключи нового вида; импорт 1.6.0 считал бы ключ по-старому — после отката реестр сервисов не загружать.

## 2. Мягкое удаление и корзина (ADR-0033)

Владелец не может убрать временную группу «Без группы» после переноса записей и удалить ненужные группы, узлы, записи и реестры.

### Модель
- Событие удаления — строка `deletions`: что (реестр, группа, узел, записи), кто, когда, причина, сколько скрыто (`counts`), снимок записей уязвимостей (`snapshot`: статус, открыта ли, итоговый срок, узел). Строка не удаляется; меняется один раз — при восстановлении (триггер).
- Всё скрытое удалением получает `deletion_id` и восстанавливается вместе с ним; удалённое раньше и отдельно остаётся удалённым.
- `deleted_at` + `deletion_id` у `registers`, `vuln_groups`, `vuln_nodes`; `deletion_id` у `register_records` и `register_automations`. Сканы не меняются (триггер) — скрыты вместе с узлом.
- Название удалённого не занято: уникальные индексы частичные (`WHERE deleted_at IS NULL`). Системные объекты не удаляются (CHECK).

### Права
- `data.delete` «Удаление данных» — реестры, группы, узлы и **записи уязвимостей**: удаление открытой записи убирает её из просрочек и эскалаций п. 7.4. Никому не выдаётся автоматически, назначается в матрице.
- `records.delete` — записи остальных реестров, как раньше. С `records.delete` без `data.delete` в реестре уязвимостей кнопок удаления нет, backend — 403.
- Корзина: просмотр — `ib.work` (только чтение), восстановление — системная роль «Супер-администратор».

### Правила
1. **«Без группы»** не удаляется. В дереве и на «Все группы» скрыта, если в ней нет неархивных записей; появляется, когда seed переносит туда записи. Сканы прежнего реестра — «Все группы» → «Архив сканов прежнего реестра».
2. **Группа** — «Удалить группу»: только без открытых записей (не закрытый статус: «В работе», «Просрочена», «Не передано ИКТ»), иначе 409 со списком узлов и числом открытых. Причина и ввод названия. Скрываются группа, узлы, записи, сканы; продления остаются в истории.
3. **Узел** — «Удалить тип из группы»: те же условия на уровне узла, без ввода названия.
4. **Запись уязвимости** — причина из списка: «Ошибочный импорт», «Ложное срабатывание», «Дубль», «Другое» (с текстом); массовое удаление с одной причиной. Удалённая не участвует в показателях, сроках, эскалациях, сверке. Ключ снова пришёл в скане узла — группа предпросмотра «Была удалена (причина)», по умолчанию не выбрана; выбор создаёт новую запись.
   - Прозрачность: на странице узла, группы и «Все группы» — «Удалено записей» за период по причинам со ссылкой на корзину. Сверка `vulns.deleted_open` (5.3): записи, удалённые открытыми, за 12 месяцев, со списком событий.
5. **Реестр** — «Удалить реестр»: только пользовательский (у системного кнопки нет, подсказка); на реестр ссылаются поля-связи других реестров — 409 со списком полей. Причина и ввод названия. Скрываются реестр, записи, автоматизации, плитки; задачи автоматизаций остаются с пометкой «реестр удалён».
6. **Записи остальных реестров** — удаление как было (зависимости → только архив), плюс причина (без «Ложного срабатывания») и событие в корзине.
7. **Восстановление** — целым событием; отказы: название занято (можно ввести новое), тип снова добавлен в группу, родитель удалён, ключ записи занят новой записью.
8. Удалённое до 1.6.1 в корзину не попадает (нет события); «Была удалена» для таких записей — «причина не указана».

### Миграция `20261102120130_soft_delete_trash`
**Влияние на данные:** новая пустая таблица `deletions`; новые колонки — NULL; существующие строки не меняются (0 строк). Уникальные индексы названий реестров и групп и «тип в группе» пересоздаются частичными — на текущих данных проверяют то же. Откат на 1.6.0: колонки и таблица не читаются; **удалённые в 1.6.1 реестры, группы и узлы после отката видны снова, пустые** (решение владельца: принимается; записано в prechecks и RELEASE.md).

## Проверка
- Unit: ключ (с портом, без порта, без IP), экземпляр.
- DB: импорт — компонент в Prod и Test и два экземпляра в Prod дают три записи, повторный импорт ничего не меняет; seed-пересчёт идемпотентен, совпадение — остановка; сверка 9.3. Удаление и восстановление каждого вида; отказ при открытых записях; «Без группы» скрывается и появляется; повторное обнаружение удалённой записи; отказ для системного реестра и реестра со ссылками; права; удалённое не в сроках, эскалациях и сверке; триггер `deletions`.
- e2e: удаление группы и восстановление из корзины.
- Полный прогон, `check:schema`, `check:integrity`, сборка `--from 1.6.0`, установка с нуля, обновление 1.6.0 → 1.6.1, откат.
