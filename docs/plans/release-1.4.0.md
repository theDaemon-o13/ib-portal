# Релиз 1.4.0 — замечания по тестированию 1.3.0 (план принят 30.10.2026)

Правила работы — как в 1.3.0: один коммит на шаг и push после каждого; перед каждым — typecheck, lint, test, test:db, e2e; для шагов с миграцией ещё `prisma migrate dev`, `check:schema`, `check:integrity`. Миграции только расширяют схему и совместимы с backend 1.3.0, у каждой — «Влияние на данные». Коды прав не меняются и не удаляются. Релиз не собирается до «ок» владельца.

## Решения владельца

| № | Вопрос | Решение |
|---|---|---|
| 0а | Стартовый набор роли «Начальник ИБ» | Набор 1.2.0 без `docs.approve.head`: `tasks.assign`, `tasks.review`, `tasks.status.override`, `tasks.report`, `docs.delete`, `history.view`, `audit.view`; без `ib.work`. Только для новой установки: существующая роль не перезаписывается |
| 0б | Отметка «Является начальником ИБ» | `users.is_ib_head`, уникальный частичный индекс; только активный пользователь с `ib.work`; передача с вопросом «Передать от <ФИО>?» и записью в журнал; отключение пользователя снимает отметку |
| 0б | Супер-администратор и отметка | 409 в обе стороны: отметку не ставим пользователю с ролью «Супер-администратор», эту роль не даём держателю отметки |
| 0в | `docs.approve.head` и `tasks.review` | «Расширить → перенести → сузить»: в 1.4.0 коды остаются в матрице с пометкой «не используется с 1.4.0», строки в БД не трогаются (нужны для отката на 1.3.0); убрать из матрицы — следующим релизом после согласия; удалить строки — ещё позже, отдельной миграцией |
| 0б | Кто «начальник ИБ» в документах | Все действия начальника ИБ (этапы 13, 14, 15 → 16, 16, возврат, блокеры, ответственные лица, переводы) — по отметке (рекомендация плана) |
| 0б | Свой документ начальника ИБ | Отметка одна, другого начальника ИБ не бывает: свой документ согласуется самим автором с отметкой «без независимого согласования» (рекомендация плана) |
| 1 | Индикаторы | Цифра — только то, что ждёт действия этого пользователя: «Задачи» — задачи на проверке у него; «Документы» — «ждут вас»; колокольчик — сумма. «Доказательства на проверке» не меняются |
| 2 | Проверяющий | Прямой руководитель исполнителя, отключённые пропускаются вверх по цепочке; нет руководителя — проверки нет («Завершить»). Фиксируется при отправке в `tasks.reviewer_id` и `task_transitions.reviewer_id` |
| 5 | Задачи, уже стоящие «На проверке» | Однократный идемпотентный шаг seed вычисляет проверяющего по текущей цепочке; без цепочки задача остаётся на старых правилах; в выводе — число строк и id, запись в журнал |
| 6 | Проверяющего отключили | Задачи переходят к следующему по цепочке, в истории «проверяющий заменён», уведомление новому |
| 7 | `tasks.status.override` | Запрещено перетаскивать из «В работе» в «Выполнено» задачи, у исполнителя которых есть руководитель; из «На проверке» — только проверяющий. Новое действие «Заменить проверяющего» для держателей override, с записью в журнал |
| 8 | Этап 12 | «Сейчас у» — автор; комментируют все с `ib.work`; руководитель автора получает уведомление, но не индикатор |
| 8 | Файлы драфта | Автор добавляет и заменяет файлы на этапах 11 и 12. Файл (pdf или docx) обязателен на переходе 12 → 13 (и для документов из старого маршрута); 13 → 14 — без загрузки, фиксируется файл автора (sha256, «версия при согласовании начальником ИБ»); несколько файлов — начальник ИБ выбирает один. Возврат: комментарий обязателен, файл по желанию |
| 9 | Переводчик | Имя переводчика — отдельное текстовое поле `translator_name`; обязательная `translator_id` в новых строках — тот, кто добавил строку (откат на 1.3.0 не ломается); срок остаётся |
| 10 | E-mail ответственного лица | Убрать из формы, колонку не трогать, старые значения показывать текстом |

## Шаги (коммиты)

1. **Роль «SOC».** Системная роль `soc` с правами «Сотрудника ИБ» по коду (`ib.work`, `records.edit`, `evidence.review`), seed создаёт её, если нет, никому не назначает. Без миграций.
2. **Отметка «Является начальником ИБ»** — миграция `users_ib_head`; API и интерфейс «Пользователи и роли»; журнал; документы переходят на отметку; стартовый набор роли «Начальник ИБ» для новой установки (в этом же шаге: пока документы проверяют `docs.approve.head`, роль без него сломала бы маршрут).
3. **Проверяющий по задаче** — миграция `task_reviewer`; процесс, override, «Заменить проверяющего», отключение проверяющего, уведомления, «Проверяет:», история; шаг seed для задач на проверке.
4. **Индикаторы** — `GET /me/attention`, меню и колокольчик.
5. **«Сейчас у»** и кто действует на этапах документа.
6. **Ответственные лица и переводы** — миграция `translation_translator_name`.
7. **Файлы начальника ИБ, возврат с файлом** — миграция `document_return_note`.
8. **Полноэкранный просмотр файлов** (pdf.js из сборки; .docx — сообщение, «Скачать», «Открыть в OnlyOffice»).

## Миграции (черновик)

1. `users_ib_head`: `ALTER TABLE users ADD COLUMN is_ib_head boolean NOT NULL DEFAULT false; CREATE UNIQUE INDEX users_ib_head_uq ON users (is_ib_head) WHERE is_ib_head;` — Влияние на данные: новая колонка, все строки `false`, 0 строк меняется; откат — 1.3.0 колонку не читает.
2. `task_reviewer`: `tasks.reviewer_id`, `task_transitions.reviewer_id` (uuid, NULL, FK на users), индекс — Влияние на данные: две пустые колонки, 0 строк; откат — 1.3.0 их не читает.
3. `translation_translator_name`: `document_translations.translator_name text NOT NULL DEFAULT ''` с ограничением длины — 0 строк.
4. `document_return_note`: расширение `document_files_kind_check` видом `return_note` — 0 строк.

## Новые e2e

settings (отметка, передача, роли в матрице), tasks («Проверяет:», кнопки только у проверяющего, «Завершить» без руководителя, история), notifications (цифры двух пользователей), documents («Сейчас у», форма лица без пользователя и e-mail, строки перевода, 13 → 14 без загрузки, возврат с файлом), просмотрщик (PDF, клавиши, .docx).
