# План релиза 1.10.0: сессии без повторного входа

**Статус: план принят владельцем 05.11.2026 (ответы — в разделе «Решения владельца»).** База — `v1.9.0` (`0799b72`), ветка `release/1.10.0`. Документы, механизмы контроля и автоматизации — отдельный релиз 1.11.0 поверх 1.10.0: `docs/plans/release-1.11.0-documents.md`.

Зачем: портал внутренний, им пользуется отдел ИБ, заходить нужно оперативно. Сейчас сессия завершается через 30 минут без действий и через 12 часов после входа — сотрудники входят заново несколько раз в день.

Ограничения: без новых npm-зависимостей и расширений PostgreSQL; `deploy/`, тома, `.env`, сертификаты не трогаются (на шаге выпуска разрешены только `deploy/prechecks/1.10.0.md`, проверки в `deploy/scripts/smoke.sh` и `deploy/verification/1.10.0.md`, diff — до коммита); ничего из раздела 3.1 CLAUDE.md. Коды прав RBAC не меняются.

## 1. Что действует сейчас (1.9.0)

| Что | Сейчас |
|---|---|
| Неактивность | 30 минут (`SESSION_IDLE_MS`); фоновые запросы (`X-Background: 1`) не продлевают; за 2 минуты — окно «Продолжить работу» (ADR-0023) |
| Общий срок | 12 часов от входа (`SESSION_MAX_AGE_MS`), даже при активности |
| Настенный монитор | без неактивности, 7 суток (`KIOSK_SESSION_MAX_AGE_MS`), только с `MONITOR_ALLOWED_IPS` |
| `last_seen_at` | не чаще раза в минуту (`SESSION_TOUCH_INTERVAL_MS`) |
| Cookie | сессионная (без `Max-Age`): закрыли браузер — вход заново |
| Закрываются | выход; своя смена пароля — остальные; сброс — все; отключение — все; администратор не с `ADMIN_ALLOWED_IPS` — сессия; монитор — снятие роли или права, чужой адрес |
| Снятие роли у обычного пользователя | сессии не закрываются; права перечитываются из БД на каждом запросе |
| Форма входа | `autocomplete="username"` и `"current-password"`, `type="password"`, `autocomplete="off"` нет; **нет `method="post"`**; галочка «Запомнить логин» (логин в `localStorage`) |

## 2. Решения владельца (05.11.2026)

1. Сессии — релиз **1.10.0**, коммит сессий первым, тег на нём. Документы и контроль — 1.11.0.
2. **Обычным пользователям** сессия бессрочная, как в задании. **Держателям `users.manage` и роли «Администратор портала» (`portal_admin`):** без «Запомнить меня», общий срок 12 часов, параметр в «Параметрах портала». В ADR-0023 — сознательное отступление от инструкции банка (30 минут) с компенсирующими мерами: блокировка экрана по GPO, «Мои сессии», завершение сессий администратором, журнал. ADR-0001 — ссылка на это решение.
3. При снятии роли у любого пользователя закрываются все его сессии.
4. Вопросы о сессиях без галочки на сервере, о галочке «Запомнить логин» и об очистке старых сессий владелец пришлёт отдельно. До ответа — буквально по заданию и без удаления данных (раздел 3, «До ответа владельца»); переделка — без миграции.

## 3. Поведение

- **Галочка «Запомнить меня»** на форме входа, по умолчанию включена.
  - **С галочкой:** без неактивности и без общего срока. Cookie постоянная, `Max-Age` 400 дней (больше Chrome не хранит); при обновлении активности cookie выдаётся заново, поэтому 400 дней отсчитываются от последнего действия, а не от входа. `HttpOnly`, `Secure`, `SameSite=Strict`, подпись — как сейчас.
  - **Без галочки:** cookie без `Max-Age` (до закрытия браузера), без неактивности.
- **Параметр срока** — «Параметры портала» → «Сессии» (`app_settings` `auth.session`, только супер-администратор, как остальные параметры):
  - `maxDays` — максимальный срок сессии в днях, **0 — бессрочно** (по умолчанию 0), 0–3650;
  - `adminMaxHours` — срок сессии администраторов в часах, по умолчанию **12**, 1–720.
  - Оба проверяются на каждом запросе от `created_at`: изменение действует и на уже открытые сессии.
- **Администраторы** — держатели `users.manage` (в том числе «Супер-администратор») и роль `portal_admin`: галочка не действует (на сервере `remember = false`, cookie без `Max-Age`), общий срок — `adminMaxHours`, неактивности нет. Кто администратор — по текущим правам на каждом запросе: выданное посреди сессии право сразу ограничивает её срок. На форме входа под галочкой — «Для администраторов портала сессия — до 12 часов» (число — из параметра, приходит с ответом входа и в «Моих сессиях»). `ADMIN_ALLOWED_IPS` (ADR-0015) — без изменений.
- **Настенный монитор** — общие правила: отдельные 7 суток убираются (галочка на форме — как у всех, по умолчанию включена). Вход и каждый запрос — только с `MONITOR_ALLOWED_IPS`; закрытие при смене пароля, снятии роли или права — как сейчас.
- **Последняя активность** — не чаще раза в **5 минут** (сейчас — минута); фоновые запросы её не обновляют: в «Моих сессиях» — время действий человека.
- Окно «Продолжить работу» и заголовок `X-Session-Idle-Ms` убираются. При 401 — вход с возвратом на ту же страницу (как сейчас); текст на форме входа — «Сессия завершена. Войдите снова — откроем ту же страницу».
- **До ответа владельца** (решение 4): сессия без галочки на сервере тоже без срока (кроме `maxDays`) и видна в «Моих сессиях», пока её не завершат; галочка «Запомнить логин» остаётся рядом с новой; старые закрытые строки `sessions` не удаляются.

## 4. Закрытие сессий и контроль

- Закрываются **все сессии пользователя**: смена пароля (кроме текущей), сброс, отключение — как сейчас; **снятие роли у пользователя** и **снятие права с роли** (у всех держателей роли) — новое для всех, не только для монитора. В журнале действия с ролями — «сессии закрыты: N».
- **«Мои сессии»** — новая страница «Профиль» (`/profile`, ссылка — имя пользователя внизу меню): устройство (браузер и ОС из User-Agent), IP, вход, последняя активность, «Запомнить меня», до какого времени (у администраторов), текущая отмечена; «Завершить» у каждой и «Завершить все, кроме текущей». Служебной учётной записи страница доступна (маршрут в группе `config.service`); настенному монитору — нет.
- **Администратор `users.manage`:** в «Настройки → Пользователи и роли» → пользователь — блок «Сессии»: активные сессии, «Завершить» и «Завершить все».
- **API** (`/api/v1`): `GET /auth/sessions`, `POST /auth/sessions/:id/revoke`, `POST /auth/sessions/revoke-others`; `GET /users/:id/sessions`, `POST /users/:id/sessions/:sessionId/revoke`, `POST /users/:id/sessions/revoke-all` (`requirePerm('users.manage')`). Сессия в API — по новому `public_id` (UUID); `sessions.id` = sha256(токен) наружу не отдаётся. Чужая сессия по «моему» маршруту — 404.
- **Журнал:** вход, выход, неудачные попытки — как сейчас; новые `auth.session_revoked` (своя), `auth.sessions_revoked_others`, `user.sessions_revoked` (администратор: чьи, сколько). Истёкшая по сроку — `auth.session_expired` (как сейчас), причина `max_age` или `admin_max_age`.
- **Форма входа:** добавить `method="post"`, остальное уже соответствует менеджеру паролей браузера (одна форма, `autocomplete`, `type="password"`).
- Требования к паролю (12 символов, 3 класса, блокировка после 5 попыток на 15 минут, история 5, срок 90 дней, смена при первом входе и после сброса) — без изменений.

## 5. Миграция `sessions_remember`

```sql
-- Влияние на данные: две колонки в sessions. remember = false у всех существующих строк (dev: 15 135), public_id —
-- новый UUID у каждой (ADD COLUMN с gen_random_uuid() переписывает таблицу; на dev — доли секунды). Ни одна сессия не
-- закрывается и не продлевается: открытые до выкладки доживают прежний expires_at (вход + 12 часов). Откат на 1.9.0
-- без отката базы: колонки не читаются; сессии 1.10.0 для 1.9.0 — обычные (30 минут, 12 часов от created_at).
ALTER TABLE "sessions" ADD COLUMN "remember" BOOLEAN NOT NULL DEFAULT false,
                       ADD COLUMN "public_id" UUID NOT NULL DEFAULT gen_random_uuid();
CREATE UNIQUE INDEX "sessions_public_id_key" ON "sessions" ("public_id");
CREATE INDEX "sessions_user_active_idx" ON "sessions" ("user_id") WHERE "revoked_at" IS NULL;
```

`expires_at` остаётся `NOT NULL`: у новых сессий — вход + 100 лет (1.9.0 читает его как дату; `'infinity'` JavaScript не прочтёт). Действующие пределы — параметры `auth.session` от `created_at`; у сессий до 1.10.0 — ещё и их `expires_at`.

## 6. Где меняются «30 минут» и 7 суток

- CLAUDE.md, раздел 5: сессия, монитор (`monitor.kiosk`), пароли (компенсирующая мера ADR-0015 дополняется сроком администраторов).
- ADR-0023 — раздел «Изменено в 1.10.0»: сознательное отступление от инструкции банка (30 минут без действий) по решению владельца; компенсирующие меры — блокировка экрана по GPO, «Мои сессии», завершение сессий администратором, журнал, 12 часов у администраторов, закрытие сессий при снятии ролей и прав.
- ADR-0001 — 30 минут и 12 часов заменены ссылкой на ADR-0023 (1.10.0); хэш токена и закрытие при смене пароля — без изменений.
- ADR-0012 — монитор: 7 суток убраны, общие правила.
- `docs/user-guide.md` (вход, «Мои сессии»), `docs/concept.md` (доступ), CHANGELOG «Не выпущено».
- Код: `lib/session-token.ts`, `auth/service.ts`, `plugins/auth.ts`, `frontend/src/auth/session.ts`, `SessionWatch.tsx`, `guards.tsx`, `main.tsx`, `LoginPage.tsx`; тесты `auth.test.ts`, `kiosk.test.ts`, `kiosk-session.db.test.ts`.
- Шаблон формы «Подтверждение соответствия требованиям парольной защиты» не меняется: поля о сессии в нём нет.

## 7. Шаги (один коммит, перед ним — полный прогон)

1. Миграция (`--create-only`, чтение SQL, применение на dev), `schema.prisma`.
2. Backend: правила срока, cookie, `last_seen_at` раз в 5 минут, параметр `auth.session`, закрытие при снятии ролей и прав, маршруты сессий, журнал; `openapi.json`.
3. Frontend: типы из OpenAPI, галочка и `method="post"`, «Профиль» → «Мои сессии», блок «Сессии» у пользователя, параметр в «Параметрах портала»; убрать окно «Продолжить работу».
4. Документация (раздел 6), CHANGELOG.
5. Проверки: backend `typecheck`, `lint`, `test`, `test:db`; frontend `typecheck`, `lint`, `test`, `build`, полный `test:e2e`; `prisma migrate dev`, `check:schema`, `check:integrity`.

Затем — репетиция 1.9.0 → 1.10.0 → откат кодом → снова 1.10.0; выпуск — по «ок» владельца.

## 8. Тесты

- «Запомнить меня»: сессия жива через 30 дней без активности и после «перезапуска браузера» (тот же токен, cookie с `Max-Age`); без галочки — без таймаута неактивности, cookie без `Max-Age`;
- `maxDays > 0` закрывает сессию старше N дней, в том числе открытую до изменения параметра; 0 — без срока;
- администратор (`users.manage`) и `portal_admin`: галочка игнорируется, через 12 часов — закрыта; `adminMaxHours` меняет срок; право выдано посреди сессии — срок от входа;
- смена пароля, сброс, отключение, снятие роли, снятие права с роли закрывают все сессии пользователя (и всех держателей роли);
- «Завершить все, кроме текущей»; «Завершить» своей; чужая через «мои» маршруты — 404; администратор завершает сессии другого, служебная учётная запись — тоже; без `users.manage` — 403;
- `last_seen_at` не чаще раза в 5 минут, фоновые запросы его не трогают; cookie выдаётся заново при обновлении;
- монитор: без 7 суток, с чужого адреса — по-прежнему закрывается;
- журнал: `auth.session_revoked`, `auth.sessions_revoked_others`, `user.sessions_revoked`; `public_id`, не хэш токена, в ответах;
- сессия до 1.10.0 (`expires_at` = вход + 12 часов) закрывается по своему сроку;
- e2e: форма входа — `method="post"`, `autocomplete`, галочка включена по умолчанию; «Мои сессии» и «Завершить все, кроме текущей»; администратор завершает сессии пользователя.
