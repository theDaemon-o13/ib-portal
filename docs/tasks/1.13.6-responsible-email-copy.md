# Задание 1.13.6 «Почта ответственных лиц и копирование полей»

Релиз 1.13.6 «Почта ответственных лиц и копирование полей». От v1.13.5 (если тега v1.13.5 ещё нет — остановись и напиши). Без новых npm-зависимостей. Режим как в docs/tasks/README.md: план в docs/plans/release-1.13.6.md и сразу продолжай, вопросы — по умолчанию с отметкой в отчёте; стоп только при необратимом. Положи этот текст в docs/tasks/1.13.6-responsible-email-copy.md первым коммитом.

Зачем. На титульный лист документа вносятся ФИО, должность и почта согласующих. Сейчас почты в портале нет, а ФИО и должность приходится выделять мышью из карточки. Нужно хранить почту и копировать каждое поле отдельно одним нажатием, чтобы вставлять в документ в OnlyOffice.

0. Данные банка в репозиторий не попадают: репозиторий публичный. В seed, тестах, скриншотах и документации только вымышленные люди и адреса на example.com («Иванов И.И.», ivanov@example.com). Домен банка нигде в коде не зашивать.

1. Почта в справочнике «Ответственные лица»
   - Новое поле «Почта», необязательное: проверка формата, приведение к нижнему регистру, обрезка пробелов.
   - В таблице справочника: колонки ФИО, Подразделение или должность, Почта, Активно. Поиск по всем трём полям.
   - Если такая почта уже есть у другого человека — предупреждение, но не запрет (как с ФИО в 1.6.1). Правило дублей при добавлении в документ не меняется: ФИО + должность, «ё» = «е».
   - Изменения — в audit_log, как сейчас.

2. Почта у ответственного лица в документе
   - При выборе из справочника (в том числе пачкой из 1.13.5) почта копируется в документ текстом вместе с ФИО и должностью, ссылку на справочник по-прежнему не храним.
   - При ручном вводе — поле «Почта» в строке, необязательное.
   - В мультивыборе поиск ищет и по почте, в строке списка почта видна под ФИО.
   - Уже добавленные лица в существующих документах остаются без почты; автоматически из справочника не заполнять. Предложи в плане, можно ли автору дописать почту лицу на этапах 1–2 вручную (с записью в историю).

3. Копирование полей
   - В карточке документа у каждого ответственного лица у ФИО, Почты и Должности — кнопка «Копировать» (значок). Копируется только значение, чистым текстом, без пробелов по краям и без форматирования, чтобы при вставке в OnlyOffice/Word не тянулись стили. После копирования — короткое «Скопировано».
   - Над списком лиц — «Копировать все ФИО», «Копировать все должности», «Копировать все почты»: значения по одному на строку, в порядке списка в документе. Пустые почты пропускаются, в «Скопировано» видно, сколько значений скопировано.
   - Такие же кнопки у полей в таблице справочника.
   - Кнопки видны и на сенсорном экране (не только при наведении), доступны с клавиатуры, с подписью для экранного диктора («Копировать ФИО Иванов И.И.»).
   - Буфер обмена: navigator.clipboard работает только в защищённом контексте (HTTPS или localhost). Проверь, как портал открывается на проде по конфигурации deploy/; если возможен HTTP — запасной вариант через временное поле и document.execCommand('copy'), и сообщение об ошибке, если не удалось оба.

4. Хранение
   - Если справочник лежит в JSON (app_settings или catalog_items) и записи лиц в документе тоже позволяют добавить поле без изменения схемы — делай без миграции.
   - Если для почты у лица в документе нужна колонка — допускается одна аддитивная миграция только вперёд: новая nullable колонка, без изменения и удаления существующих данных. Откат на v1.13.5 без отката базы должен работать (старая версия колонку не видит), проверь это. «Влияние на данные» с числом затронутых строк (ожидается 0 изменённых). Тогда в инструкции DevOps появляется шаг migrate — напиши это явно.
   - Любое другое изменение схемы — стоп и отчёт до кода.

5. Тесты
   - Unit/DB: почта сохраняется и нормализуется; неверный формат отклоняется; предупреждение о повторной почте; почта копируется в документ при выборе одного и пачкой; ручной ввод с почтой; правка почты в справочнике не меняет уже созданные документы; старые лица без почты читаются.
   - Unit frontend: кнопки копирования кладут в буфер ровно значение; «Копировать все…» — по строке на значение, пустые пропущены; запасной вариант копирования.
   - e2e: завести лицо с почтой → добавить в документ → скопировать ФИО, почту и должность по отдельности и проверить буфер (разрешение clipboard в контексте Playwright) → «Копировать все ФИО» для трёх лиц.
   - Если есть миграция — тест отката на v1.13.5 без отката базы.
   - Быстрые проверки перед коммитом, полный e2e на ibportal_e2e перед тегом.
   - Скриншоты справочника и карточки документа с кнопками копирования в обеих темах, 1440 и 375 px.
