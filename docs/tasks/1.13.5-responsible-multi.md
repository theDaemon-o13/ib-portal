# Задание 1.13.5 «Несколько ответственных лиц с общим сроком»

Релиз 1.13.5 «Несколько ответственных лиц с общим сроком». От v1.13.4 (если тега v1.13.4 ещё нет — остановись и напиши, не начинай от 1.13.3). Без миграции и без новых npm-зависимостей. Режим как в docs/tasks/README.md: план в docs/plans/release-1.13.5.md и сразу продолжай, вопросы — по умолчанию с отметкой в отчёте; стоп только при необратимом. Положи этот текст в docs/tasks/1.13.5-responsible-multi.md первым коммитом.

Зачем. На этапе 2 «Согласование» документ обычно уходит сразу нескольким людям из разных департаментов с одним сроком. Сейчас каждого приходится добавлять отдельно и каждый раз вводить «Срок ответа». Нужно добавлять нескольких за один раз с одним сроком для всех.

0. Данные банка в репозиторий не попадают. В тестах, скриншотах и документации только вымышленные люди и документы («Иванов И.И.», «Технический директор», «Политика тестовая»).

1. Форма «Добавить ответственных лиц» (этап 2, ведёт автор — права как сейчас)
   - Множественный выбор из справочника «Ответственные лица» (1.6.1): список с чекбоксами и поиском по ФИО и должности, выбранные показываются чипами над списком, чип можно снять. «Выбрать всех найденных» по текущему фильтру — предложи, нужно ли.
   - Отключённые в справочнике в списке не показываются (как сейчас). Люди, уже добавленные в этот документ, видны, но недоступны для выбора с пометкой «уже добавлен».
   - Ручной ввод сохраняется: «+ Добавить вручную» добавляет строку ФИО + «Подразделение или должность»; таких строк может быть несколько в одной форме, каждую можно удалить.
   - Одно поле «Срок ответа» на всю форму — применяется ко всем выбранным и введённым. Валидация срока та же, что сейчас для одного лица. Если сейчас у лица есть другие поля (комментарий и т. п.) — общие для всех или пропускаются, предложи в плане.
   - Кнопка «Добавить (N)» с числом людей; неактивна, пока нет ни одного человека или срока.
   - Добавление одного человека — частный случай той же формы, отдельной старой формы не остаётся.
   - Компонент мультивыбора — на базе Select из 1.13.4 (те же токены, стекло, обе темы), listbox с aria-multiselectable, клавиатура: стрелки, пробел — отметить, Enter — подтвердить, Esc — закрыть. Работает на 375 px и внутри модального окна.

2. После добавления каждый человек — отдельная запись, как сейчас
   - Свой срок у каждого: перенос срока одного лица (с комментарием и историей), отметка согласования, напоминания и просрочка — по каждому отдельно, без изменений. Общий срок задаётся только в момент добавления, группы как сущности нет.
   - История документа: запись на каждого добавленного (кто, когда, кого, срок), чтобы история читалась так же, как раньше. В audit_log — как сейчас для одного лица.
   - Уведомления и задачи по срокам — по каждому лицу, как сейчас; проверь, что пакетное добавление не создаёт дублей уведомлений.

3. Backend
   - Пакетное добавление одной транзакцией: либо добавляются все, либо никто, с понятной ошибкой, какая строка не прошла (дубль, пустое ФИО, срок). Через новый endpoint или расширение существующего — выбери и обоснуй в плане; старый вызов для одного лица, если остаётся, должен работать.
   - Проверка дублей и на сервере: с уже добавленными в документ и внутри самой пачки (выбран из справочника и тот же введён вручную). Правило сравнения — то же, что сейчас для одного лица; если оно только по ФИО или только по точному совпадению — напиши в отчёте.
   - Ограничение размера пачки (предложи, например 50), добавление только на этапе 2 и только тем, кто может сейчас, — прямой запрос к API на другом этапе отклоняется.
   - ФИО и должность копируются в документ текстом, ссылку на справочник не храним (как в 1.6.1).

4. Хранение: без миграции. Схема БД не меняется, выкладка — замена образов backend и frontend без шага migrate. Если без миграции не обойтись — остановись и напиши почему, до кода.

5. Тесты
   - Unit/DB: пачка из справочника + вручную создаёт N записей с одним сроком; дубль с уже добавленным и дубль внутри пачки отклоняют всю пачку, ничего не записывается; отключённые не попадают в выбор; после добавления перенос срока одного лица не меняет сроки остальных; история — запись на каждого; добавление на этапе ≠ 2 отклоняется; лимит пачки.
   - Unit на мультивыбор: клавиатура, снятие чипа, «уже добавлен» недоступен.
   - e2e: завести трёх человек в справочнике → выбрать двоих + одного вручную с одним сроком → в карточке три лица с одинаковым сроком → перенести срок одному → отметить согласование всем → кнопки этапа 2 становятся активны.
   - Быстрые проверки перед коммитом (typecheck, lint, test, check:integrity), полный e2e на ibportal_e2e перед тегом.
   - Скриншоты формы в обеих темах, 1440 и 375 px, в docs/design/ocean/screens/.
