Режим как в docs/tasks/README.md: план в docs/plans/release-<версия>.md и сразу продолжай, вопросы — по умолчанию с отметкой в отчёте; стоп только при необратимом. Положи этот текст в docs/tasks/<версия>-vuln-import-timeout.md первым коммитом.

Зачем. Импорт скана в узел «Уязвимостей» падает на подтверждении. Файл: 3390 находок, 1 хост, все 3390 — новые записи. Предпросмотр проходит, «Загрузить» даёт «Внутренняя ошибка сервера. Попробуйте ещё раз». В логе backend:
P2028 Transaction API error: … expired transaction. The timeout for this transaction was 15000 ms
— в scan-import.service.js:467 (registerRecord.create) и :471 (auditLog.create), вызов из section.routes.js:318. Лимит 15 000 мс задан в backend/src/lib/db.ts. Четыре попытки, все откатились, данных не записано. Импорт пишет по записи и по строке журнала на каждую находку в цикле внутри одной транзакции: на образце в 90 строк это незаметно, на 3390 не укладывается в 15 с. Отчёты Linux-серверов такого размера — норма, дальше будут и больше.

0. Данные банка в репозиторий не попадают: репозиторий публичный. Реальный файл в репозиторий и тесты не кладём. Для тестов — генератор синтетического отчёта той же структуры, что у реального:
   - лист «Хост»: заголовок «Имя хоста | IP-адрес | ОС» в первой строке, без строки-названия над ним, один хост test-host.example.com, 192.0.2.10, Debian 12;
   - лист «Все уязвимости»: колонки «Пакет | CVE | Уровень | CVSS | Эксплойт | Вектор | Обновить до версии | Задача № | Описание (из CVE, англ.)»;
   - вымышленные пакеты (pkg-0001…), идентификаторы CVE-2099-NNNNN; одна CVE у нескольких пакетов; около 38% строк без CVSS и без вектора с Уровнем «Нет оценки»; Эксплойт «Нет данных» / «Есть» / «Есть, эксплуатируется»; описания до 300 символов;
   - размеры 3390 и 10 000 строк.

1. План: подтверди причину цифрами
   - Что выполняется на каждую находку внутри транзакции импорта: запись реестра, audit_log, история записи, находка в снимке скана, значения списков, автоматизации и уведомления (в том числе по «Системе» владельцу системы) — полный список.
   - Число SQL-запросов и время на dev для образца на 90 строк и для синтетики на 3390 — до исправления и после.

2. Исправление записи импорта
   - Атомарность прежняя: одна транзакция, всё или ничего. Частичный импорт недопустим.
   - Число запросов растёт с числом пачек, а не записей. Вставки — пачками (createMany) с размером пачки, посчитанным от числа колонок под лимит параметров PostgreSQL (не больше 1000 строк). Существующие записи узла — одним запросом по ключам, не по записи. Если для истории и журнала нужны id созданных записей: сверь версию Prisma и способ генерации id — createManyAndReturn, если версия позволяет, иначе id генерируются в приложении до вставки. Выбор — в плане.
   - audit_log и история записей по содержанию не меняются: те же строки, те же поля, та же детализация (по строке на запись). Меняется только способ вставки.
   - Всё, что имеет внешний эффект (письма, уведомления, автоматизации с отправкой), — после фиксации транзакции, не внутри неё. Если сейчас при импорте создаётся уведомление на каждую новую запись — на 3390 записей это 3390 уведомлений владельцу системы: по умолчанию сделай одно сводное на импорт («В узле <узел> новых уязвимостей: N»), отметь в отчёте.
   - Глобальный лимит 15 с в db.ts не трогай. Для импорта скана (и операций из п. 3) — явные { timeout, maxWait } в вызове, одна константа с комментарием почему, 120 с. Это запас, а не решение: цель — 3390 строк меньше 10 с, 10 000 меньше 30 с на dev. Фактическое время — в отчёт.
   - Параллельный импорт в один узел: блокировка pg_advisory_xact_lock по id узла в начале транзакции; второй импорт в тот же узел — 409 «В этот узел уже идёт импорт».
   - Проверь proxy_read_timeout в конфигурации nginx в deploy/ (не меняй, только сообщи значение). Если импорт 10 000 строк может приблизиться к нему — напиши в отчёте.

3. Другие массовые операции раздела «Уязвимости»
   Найди операции с тем же устройством (цикл по записям внутри транзакции) и перечисли в плане с временем на 3390 записях узла: передача ИКТ (срок, «Уведомлено ДИКТ»), «Обновить сроки» / продление и его отмена, обратный импорт по ID, «Перенести выбранные», отметка «Пропали → Устранена», а также общий конвейер импорта конструктора, если код общий. Что не укладывается или близко к лимиту — исправь тем же способом в этом же релизе. Следующий шаг после этого импорта — передача ИКТ скана на 3390 записей, она не должна упасть так же.

4. Сообщения об ошибке
   - Таймаут транзакции (P2028) и другие ошибки импорта — не «Внутренняя ошибка сервера. Попробуйте ещё раз»: повтор не поможет. Текст: «Импорт не завершён, ничего не записано. Сообщите администратору номер запроса <id>».
   - В логе — уровень error: узел, число строк, на каком шаге, длительность, id запроса.
   - Frontend: кнопка «Загрузить» неактивна, пока идёт запрос, на ней «Загружается…». Двойное нажатие не отправляет второй запрос.

5. Колонки отчёта Linux (Debian)
   В этом файле портал не узнал две колонки — в предпросмотре «нет колонок „Сетевой вектор“, „Краткое описание“, „Обнаружений“». Вектор и описание есть, но названы иначе; если загрузить как есть, у 2111 записей пропадёт вектор, у 3376 — описание, а после будущего исправления все они уйдут в «Изменились».
   - «Вектор» принимать как «Сетевой вектор». Заголовок, начинающийся с «Описание» (например, «Описание (из CVE, англ.)»), — как «Краткое описание». Правило — в одном месте рядом с остальными синонимами колонок.
   - Значения вектора в файле: Сеть, Локально, Смежная сеть, Физический. Сверь с уже существующими значениями списка «Сетевой вектор» (из отчётов Windows). Если написания расходятся — приведи к существующим, таблицу соответствия — в отчёт.
   - «Задача №» не используется; в предпросмотре — «Колонка „Задача №“ не используется», без жёлтого предупреждения.
   - Предупреждение о реально отсутствующих колонках («Обнаружений») остаётся.
   - Разбор образца backend/test/fixtures/vuln-windows-2026-10-15.xlsx не меняется — тест.

6. Тесты
   - Синтетика 3390: импорт в пустой узел проходит, 3390 записей, 3390 строк audit_log и истории; число SQL-запросов ограничено сверху (счётчик через события запросов Prisma, порог зависит от числа пачек, а не записей).
   - Синтетика 10 000: проходит в пределах лимита.
   - Ошибка на середине импорта (подставная) — откат целиком, в узле 0 записей, скана нет.
