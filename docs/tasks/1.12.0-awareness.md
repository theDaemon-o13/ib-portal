Релиз 1.12.0 «Осведомлённость: макет письма, журнал отправок, выгрузка готового письма». Поверх v1.11.0. Руководство по почтовым клиентам из 1.9.1 переезжает сюда. Сначала план docs/plans/release-1.12.0.md и обновление docs/specs/awareness.md. У тебя нет доступа к проду и его данным, работай только с кодом и dev-данными. Ограничения: без новых npm-зависимостей без моего согласия, без расширений PostgreSQL, deploy/, тома, .env и сертификаты не трогать (кроме файлов выпуска, как в 1.11.0), ничего из раздела 3.1 CLAUDE.md без моего подтверждения, коды прав RBAC не меняются. Номера ADR — следующие свободные на момент начала работы.

Мы рассылаем одно письмо на двух языках: сначала русская часть, затем таджикская, у каждой своя шапка (тёмно-синяя плашка с логотипом, заголовок, метка «ВАЖНАЯ ИНФОРМАЦИЯ»), обращение, абзацы, выделенный блок с синей полосой слева, подпись. Сейчас письмо собирается вручную в Outlook (Word-вёрстка: фиксированная ширина 802 px, отступы из пробелов, логотип вложен дважды, адрес ИБ без ссылки, пустая строка-подвал). Экспорт 1.9.0 даёт «сначала RU, затем TJ с разделителем» без нашего оформления.

Нужно: (1) системный макет письма, чтобы выгруженный .eml выглядел как наша рассылка и открывался в Outlook готовым к отправке — остаётся вставить адреса; (2) регистрация факта отправки с датой и шаблоном, по которому сделано письмо.

Эталон вёрстки — `docs/email/layout-reference.html` (лежит в репозитории; содержимое вымышленное, логотипа банка в нём нет, alt логотипа — переменная). Верстай по нему, отклонения перечисли в плане.

## 0. Данные банка в репозиторий не попадают

- Логотип, адрес ИБ, тексты подписи и подвала, реальные письма и шаблоны — только на проде, через интерфейс.
- Seed: настройки оформления с заглушками («Отдел информационной безопасности», адрес `security@example.org`, без логотипа). Без логотипа шапка выводит название отдела текстом.
- seed:demo (только dev): 2 вымышленных шаблона — «Срочное предупреждение» и «Плановая памятка» — с выделенными блоками обоих видов.

## 1. Макет письма (оформление)

- Макет — код backend (модуль awareness-letters, отдельный файл layout), а не HTML в базе. Письмо и шаблон хранят только содержимое; оформление накладывается при предпросмотре и выгрузке. Смена макета в будущих релизах меняет вид только неотправленных писем; у отправленного хранится снимок (п. 4).
- Вёрстка для почтовых клиентов: только таблицы и inline-стили; внешняя таблица 100% с фоном #F1F5F9; карточка 600 px (`width="600"` + `max-width:600px` + условная таблица `<!--[if mso]>` для Outlook); на ширине до 620 px карточка тянется на всю ширину. Шрифт Arial, 15/23 px, текст #0F172A. Никаких div-раскладок, flex, grid, классов вместо inline-стилей, веб-шрифтов и внешних ресурсов.
- Шапка: фон #1E3A8A; логотип (по центру, с alt-текстом = название отдела); «Заголовок» 24 px жирный белый; «Метка» 12 px заглавными с разрядкой, цвет #BFDBFE.
- Тело: обращение жирным, абзацы с отступом 14 px снизу, без отступов первой строки из пробелов (при вставке из Word вырезай ведущие `&nbsp;`).
- Выделенный блок: таблица с полосой 4 px слева; вид «Просьба» — фон #EFF6FF, полоса #2563EB; вид «Предупреждение» — фон #FEF2F2, полоса #DC2626. Заголовок блока жирным, затем текст.
- Подпись: «С уважением,» / название отдела жирным / адрес ИБ ссылкой `mailto:` с `white-space:nowrap`.
- Подвал карточки: серый текст 12 px над тонкой линией (например: «Отдел ИБ никогда не запрашивает пароли, коды из SMS и данные карт…»). Пустой подвал не выводится.
- RU+TJ: две карточки подряд с промежутком 24 px; над первой справа — ссылка-подсказка «Матни тоҷикӣ дар поён ↓» на якорь таджикской карточки. При выгрузке одного языка — одна карточка без подсказки.
- Логотип вкладывается один раз (один Content-ID) и используется в обеих карточках.
- Скрытый прехедер (первая фраза письма) — для превью в списке писем.

### Настройки «Оформление писем»

Раздел в настройках модуля. Права: settings.manage и ib.work, как у «Подписи ИБ». «Подпись ИБ» из 1.9.0 переезжает сюда же, переменная `{{подпись}}` продолжает работать.

| Поле | Примечание |
|---|---|
| Логотип | PNG, до 100 КБ; хранится через files с проверкой типа и размера; показывается в шапке на ширине 238 px |
| Название отдела RU / TJ | для подписи, alt логотипа и шапки без логотипа |
| Адрес ИБ | для подписи и ссылок `mailto:` |
| Прощание RU / TJ | по умолчанию «С уважением,» / «Бо эҳтиром,» |
| Подвал RU / TJ | необязательно |
| Метка по умолчанию для типа | Срочное и Плановое, RU и TJ; подставляется в новое письмо, в письме можно изменить |
| Подсказка о таджикском тексте | по умолчанию «Матни тоҷикӣ дар поён ↓» |

## 2. Поля письма и шаблона, редактор

- Письму и шаблону добавляются поля для каждого языка: «Заголовок» (по умолчанию — тема этого языка) и «Метка» (по умолчанию — из настроек по типу). Переменные `{{…}}` в них работают, как в теме и тексте.
- Тема при выгрузке RU+TJ: отдельное поле «Тема общая», по умолчанию «<тема RU> | <тема TJ>», можно изменить.
- Редактор: новый блок «Выделенный блок» с выбором вида (Просьба / Предупреждение) и заголовком. Хранится как `<div data-callout="info|warn"><p><strong>…</strong></p><p>…</p></div>`. Санитайзер: добавить в белый список только `div[data-callout]` со значениями info и warn; остальной белый список не расширять.
- Обращение, абзацы, списки, ссылки, жирный, курсив, таблицы и изображения из 1.9.0 остаются. При выгрузке их HTML переводится в inline-стили макета: отдельная чистая функция «содержимое редактора → почтовый HTML», без DOM в браузере.
- «Предпросмотр как в почте»: iframe с `sandbox` (без allow-scripts) и `srcdoc` = ровно тот HTML, что уйдёт в .eml; переключатель ширины «Компьютер 600 / Телефон 375»; переключатель RU+TJ / RU / TJ. Ссылок на портал в письме по-прежнему быть не должно.
- Письма и шаблоны 1.9.0 не переписываются: пустые «Заголовок» и «Метка» при выгрузке берутся из темы и настроек. Миграция только добавляет колонки.

## 3. Выгрузка «Готовое письмо»

- Основная кнопка в карточке письма — «Скачать для Outlook (.eml)», выбор языков RU+TJ / RU / TJ (по умолчанию RU+TJ; для планового письма доступно, только если заполнены оба языка — правило 1.9.0).
- Структура: `multipart/alternative` → text/plain (текст обеих частей с разделителем) и `multipart/related` → text/html + логотип `image/png` inline с Content-ID; изображения из текста письма — так же через Content-ID. Subject по RFC 2047, `X-Unsent: 1`, `Content-Language`, без From, To и Cc: Outlook открывает файл как новое письмо, отправитель — учётная запись, выбранная в Outlook.
- Имя файла: `<Тема RU>_<RU-TJ|RU|TJ>_<ГГГГ-ММ-ДД>.eml`, запрещённые в Windows символы заменить на «_».
- Проверка размера: лимит письма из «Параметров портала» (1.9.0) считается по готовому .eml.
- Формат .msg не делаем: его запись требует отдельной библиотеки, а .eml с X-Unsent даёт в Outlook тот же результат. Опиши это в руководстве одной фразой («после открытия можно сохранить как .msg средствами Outlook»).
- «Скопировать с оформлением» (для WorldClient) остаётся. Изображения в буфер — как data: URI; в руководстве отметить, что WorldClient может убрать логотип, и как это проверить.
- Выгрузка пишется в audit_log (кто, когда, языки, sha256 файла), но отправкой не считается. После скачивания — подсказка «Когда отправите, нажмите „Отметить отправленным“».

## 4. Регистрация отправки

- «Отметить отправленным» (1.9.0) — диалог:
  - Дата отправки — по умолчанию сегодня (по времени портала, +05); будущая дата запрещена; прошедшая — не раньше даты утверждения письма.
  - Языки — RU+TJ / RU / TJ, по умолчанию из последней выгрузки.
  - Получатели — текст (например, адрес общей рассылки), по умолчанию — значение из прошлой отправки.
  - Аудитория — как в 1.9.0.
  - Файл письма — выгрузка, которую отправили: по умолчанию последняя выгрузка с этими языками; если выгрузки не было, портал собирает её в момент отметки.
- Запись в реестре «Рассылки» получает новые поля (добавить seed'ом, идемпотентно; у существующих записей значения пустые):

| Поле | Тип |
|---|---|
| Шаблон | текст, роль аналитики «измерение»; название шаблона на момент отправки, «Без шаблона», если письмо создано не из шаблона |
| Языки | список: RU+TJ, RU, TJ |
| Получатели | текст |
| Файл письма | файл .eml (см. ниже) |

- Снимок шаблона: в письме хранится id шаблона, в «Рассылках» — его название на момент отправки. Переименование или архив шаблона старые записи не меняет.
- Файл письма как доказательство: отправленный .eml сохраняется через files (sha256, кто, когда) и привязывается к записи. Сейчас .eml нет в списке разрешённых типов (CLAUDE.md, 3.7). Предложи в плане: добавить `message/rfc822` только для этого поля, выдавать только как вложение (`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`), никогда не показывать inline. Если считаешь, что достаточно хранить sha256 и пересобирать файл из замороженного письма, — обоснуй.
- Ручной ввод и импорт Excel в «Рассылки» остаются (история прошлых писем): поле «Шаблон» при ручном вводе — текст с подсказками из названий шаблонов.
- Выгрузка «Рассылок» в Excel — с новыми колонками; файл письма в Excel не выгружается, только его имя и sha256.
- Счётчики дашборда 1.9.0 не меняются; разрез «по шаблону» доступен в аналитике реестра через роль «измерение». Новых виджетов не добавлять.

## 5. Схема и права

- Миграция: новые колонки у писем, шаблонов и версий писем (заголовок и метка RU/TJ, тема общая, языки и id файла выгрузки у отправки), таблица или ключи настроек оформления. «Влияние на данные: добавляются колонки и настройки, существующие письма, шаблоны и записи „Рассылок“ не меняются». Проверь откат на 1.11.0 без отката базы.
- Поля «Рассылок» — seed'ом через конструктор, как в 1.9.0; если на проде уже есть поле с таким именем — запрос до выкладки.
- Права: письма, шаблоны, выгрузка, отметка — ib.work; «Оформление писем» — settings.manage и ib.work; служебный администратор раздел не видит.

## 7. Проверка

- Перед коммитом: typecheck, lint, test и test:db затронутого модуля. Полный e2e на ibportal_e2e — один раз перед тегом.
- Unit: «содержимое → почтовый HTML» на вымышленном письме (снимок результата); выделенный блок обоих видов; ведущие `&nbsp;` вырезаются; один Content-ID логотипа на две карточки; без логотипа шапка с текстом; RU+TJ — две карточки и подсказка, один язык — одна карточка без подсказки; Subject RFC 2047 с кириллицей и таджикскими буквами (ҳ, ӯ, ҷ, ғ, қ, ӣ); X-Unsent есть, From/To нет; text/plain присутствует; имя файла без запрещённых символов; лимит размера по готовому .eml; санитайзер пропускает `data-callout` только со значениями info и warn.
- DB: отметка создаёт запись «Рассылок» с шаблоном, языками, получателями и файлом; переименование шаблона не меняет старые записи; будущая дата отправки отклоняется; выгрузка не создаёт записи в «Рассылках»; .eml отдаётся только как вложение и только с ib.work; служебный пользователь получает 403.
- e2e: письмо из шаблона → предпросмотр как в почте → выгрузка .eml → «Отметить отправленным» → запись в «Рассылках» с шаблоном и файлом → письмо заморожено.
