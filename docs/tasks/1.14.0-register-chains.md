Зачем. Автоматизации реестров создают по задаче на каждую запись: «Напоминание: За 3 дн. до «Срок устранения» — #15 CVE-2024-30040», категория «Реестр», метки «авто» и «не назначен». В реестре уязвимостей таких задач десятки за раз: сейчас в Backlog 52 карточки, почти все — напоминания с одним сроком. Ручные задачи среди них теряются. Нужно, чтобы система сама собирала такие задачи в цепочки (механизм цепочек 1.7.0): по реестру, а в разделе «Уязвимости» — по группе (сервис или подразделение), в которой находится запись. На доске вместо 52 карточек — по одной свёрнутой карточке на цепочку.

Это сознательное исключение из правила 1.7.0 «автоматически ничего не склеивается». Оно касается только задач, созданных автоматизациями реестров. Ручные задачи, подсказки по заголовку и ручные цепочки работают как раньше.

0. Данные банка в репозиторий не попадают: репозиторий публичный. В seed, тестах, скриншотах и документации — только вымышленные группы, реестры, CVE (CVE-2099-NNNNN) и люди («Иванов И.И.»).

1. Сначала разберись и напиши в плане

Полный список; по каждому — где создаётся задача, какие ссылки она хранит (запись реестра, реестр, правило автоматизации, узел), чем помечена как «авто».
   - Как по задаче однозначно определить источник: реестр, а для уязвимостей — запись → узел → группа. Если у части старых задач связи нет — сколько таких на dev и как их найти. Разбор заголовка задачи для этого не используем.
   - Как устроены цепочки 1.7.0 в текущем коде: таблица и статусы, отображение на доске (в том числе цепочка с задачами в разных колонках), фильтр «Цепочка», видимость, кнопка «Найти цепочки среди старых задач». Расхождения с этим заданием и свои предложения.
   - Какие ещё системные задачи есть (пересмотр документов, автоматизации документов, рассылки осведомлённости) — только список, в этот релиз они не входят.

2. Правило группировки
   - Задача, созданная автоматизацией реестра, при создании сразу привязывается к системной цепочке своего источника:
     - запись раздела «Уязвимости» → цепочка группы, в которой находится узел записи: «Уязвимости · <группа>»; записи «Без группы» → «Уязвимости · Без группы»;
     - запись любого другого реестра конструктора → цепочка реестра: «Реестр · <название реестра>».
   - Одна системная цепочка на источник. Если её нет — создаётся при первой задаче. Два одновременных создания не дают дубль (уникальный индекс и повторное чтение при конфликте).
   - Название следует за источником: переименовали группу или реестр — у цепочки на экране новое название. Цепочка хранит ссылку на источник; как держать название (вычислять или обновлять при переименовании) — в плане.
   - Привязка — в той же транзакции, что и создание задачи. В audit_log и в истории задачи — «Добавлена в цепочку „…“ автоматически».
   - Все виды автозадач одного источника (напоминания, просрочки, эскалации) — в одной цепочке. Если считаешь, что эскалации нужно держать отдельно, предложи в плане; по умолчанию — вместе.

3. Модель данных (только добавление, мягкое удаление как принято)
   - У цепочки: вид manual | system, тип источника register | vuln_group, id источника. У существующих цепочек — manual, источник пустой.
   - Частичный уникальный индекс: одна неудалённая системная цепочка на пару (тип источника, id источника).
   - Черновик SQL и «Влияние на данные» в плане: существующие строки не меняются, новые поля пустые или со значением по умолчанию. Проверь, что откат на предыдущую версию без отката базы безопасен: старый код видит системные цепочки как обычные и ничего не ломается.
   - Особый формат нормализованного ключа вместо полей источника не используем.

4. Поведение системной цепочки
   - Создаёт и наполняет только система. Вручную в неё не добавить задачу, её не создать, не переименовать, не закрыть и не удалить — ни в интерфейсе, ни через API (ответ с понятным текстом, например «Системную цепочку ведёт портал»).
   - Задачу из системной цепочки можно отвязать или перенести в ручную цепочку — тот, кто может редактировать задачу. Отвязанную вручную задачу система обратно не цепляет: ни при следующем прогоне, ни при сборке старых задач.
   - Статус — всегда открыта. Пока в ней нет активных задач, на доске она не показывается, в списке цепочек — с отметкой «Нет активных задач». Новая автозадача — цепочка снова на доске. Закрытий и повторных открытий на каждый прогон нет.
   - Перенос записи уязвимости в узел другой группы («Перенести», «Перенести выбранные» из «Без группы»): её незавершённые задачи переходят в цепочку новой группы, выполненные остаются в прежней. Каждый переход — в audit_log.
   - Подсказки по заголовку (1.7.0, п. 3): системные цепочки и задачи в них не предлагаются и в расчёте не участвуют.
   - Видимость — по правилам 1.7.0, п. 4: счётчики и состав только по задачам, доступным пользователю; цепочка без видимых ему задач ему не показывается.
   - Проверка задачи, REVIEW_REQUIRED, «Завершить», индикаторы /me/attention и уведомления работают для каждой задачи как сейчас. Цепочка их не объединяет и не меняет.

5. Интерфейс (обе темы портала, стиль проекта)
   - Доска. Задачи системной цепочки не показываются отдельными карточками. В каждой колонке, где есть её задачи, — одна свёрнутая карточка цепочки: название, «N задач» в этой колонке, сколько из них не назначено, ближайший срок, число просроченных красным, метки «Реестр» и «авто». В колонке сортируется по ближайшему сроку, как обычная задача.
   - По клику карточка раскрывается: задачи колонки по сроку (при большом числе — с подзаголовками по дате срока), у каждой «Взять себе» и переход в карточку задачи. Взятая задача уходит в «В работе» и там оказывается в карточке той же цепочки.
   - «Взять себе все» на карточке цепочки — для не назначенных задач этой колонки, с подтверждением «Взять N задач?». Для каждой задачи — те же правила и та же запись в audit_log, что у обычного «Взять себе».
   - Ручные цепочки на доске — как сейчас.
   - Список задач: «Группировать по цепочкам» включает системные цепочки; без группировки задачи видны по одной, как сейчас.
   - Панель цепочки для системной: источник со ссылкой (страница группы «Уязвимостей» или реестр), задачи по сроку с фильтром «Активные / Выполненные / Все», без кнопок правки, закрытия и удаления.
   - Карточка задачи: блок «Цепочка» показывает системную цепочку со ссылкой на источник и действие «Отвязать».
   - Страница группы «Уязвимостей» и страница реестра: ссылка «Задачи: N активных», открывает панель цепочки.

10. Тесты (минимум)
   - Напоминания на записях двух групп → две цепочки «Уязвимости · A» и «Уязвимости · B», задачи в своих; повторный прогон автоматизации новых цепочек не создаёт.
   - Запись «Без группы» → «Уязвимости · Без группы»; перенос записи в узел группы A → незавершённые задачи в цепочке A, выполненные остались.
   - Реестр конструктора → «Реестр · <название>»; переименование реестра и группы → новое название цепочки.
   - Одновременное создание двух задач одного источника → одна цепочка.
   - Ручная задача не попадает в системную цепочку ни при создании, ни через API привязки; системную цепочку нельзя закрыть, удалить, переименовать через API.
   - Отвязанная вручную задача не возвращается ни при прогоне, ни при сборке старых.
   - Системные цепочки не появляются в подсказках по заголовку.
   - Два пользователя с разной видимостью задач видят разные счётчики; цепочка без видимых задач не видна.
   - Доска: 52 синтетических напоминания по двум группам → в Backlog две карточки цепочек; «Взять себе» на одной задаче → в «В работе» карточка той же цепочки с одной задачей; «Взять себе все» назначает все не назначенные задачи колонки.
   - Цепочка без активных задач не на доске; новая автозадача — снова видна.
   - Сборка старых: результат применения совпадает с предпросмотром; повторный запуск ничего не меняет; задачи без определимого источника перечислены и не тронуты.
   - Откат: предыдущая версия на новой схеме открывает доску и цепочки без ошибок.
   - Скриншоты доски до и после на синтетике в обеих темах, 1440 и 375 px.
   - Быстрые проверки перед коммитом, полный e2e на ibportal_e2e перед тегом.
