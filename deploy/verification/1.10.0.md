## Для DevOps

Выкладка 1.10.0 — обязательно с `migrate`. Миграция одна: `20261105103617_sessions_remember`.
**Влияние на данные:** в `sessions` две новые колонки — `remember` (false у всех строк) и `public_id` (новый UUID у каждой строки) и частичный индекс; ни одна сессия не закрывается и не продлевается, открытые доживают прежний срок (вход + 12 часов). Новых переменных `.env` и зависимостей нет.

1. **Сборка образов из репозитория** (машина сборки, `docs/runbook/build.md`):
   ```bash
   git fetch --tags && git checkout v1.10.0
   cat VERSION                              # 1.10.0
   ./deploy/scripts/make-release.sh         # → dist/ibportal-1.10.0.tar.gz и .sha256
   ```
   В `RELEASE.md` архива: «Предыдущая версия» — 1.9.0, у миграции есть «Влияние на данные». На сервер — только архив и `.sha256`.
2. **До выкладки, на работающей 1.9.0:** запросы из раздела «Проверки по порядку выполнения» (строки в `sessions`, открытые сессии, администраторы с пределом 12 часов) — числа в журнал выкладок.
3. **На сервере:**
   ```bash
   cd /srv/ibportal/releases && sha256sum -c ibportal-1.10.0.tar.gz.sha256
   tar -xzf ibportal-1.10.0.tar.gz && cd ibportal-1.10.0 && sha256sum -c SHA256SUMS
   docker load -i ibportal-images-1.10.0.tar.gz
   cd /srv/ibportal/deploy
   ./scripts/smoke.sh --before
   ./scripts/backup.sh                      # резервная копия БД и тома файлов — ОБЯЗАТЕЛЬНО; нет копии — стоп
   ```
