**1.14.0 — меняются образы backend и frontend, шаг `migrate` обязателен:** одна миграция `20261113090000_task_chain_system` и шаг seed `system.portal_user.v1_14_0`. Миграция добавляет три колонки, ограничение и индекс в `task_chains`; строки не меняются. Seed добавляет одну отключённую служебную учётную запись «Портал» (`portal-system`) без ролей. Новых переменных `.env`, прав и зависимостей нет. `backup.sh` перед выкладкой обязателен, как всегда.

### Что меняется для пользователей

- Задачи автоматизаций реестров собираются в системные цепочки: «Уязвимости · <группа>» и «Реестр · <название>». На доске — одна карточка цепочки на колонку, «Взять себе все».
- Задачи, созданные до обновления, сами в цепочки не попадают. Их собирает сотрудник ИБ из интерфейса: «Задачи → Цепочки → Найти цепочки среди старых задач → Системные цепочки реестров». **В выкладку этот шаг не входит.**

### Данные

- 0 изменённых и 0 удалённых строк. У существующих цепочек `kind = 'manual'` значением по умолчанию, задачи не меняются.
- +1 строка в `users`: «Портал», отключена, без ролей. Если логин `portal-system` уже занят, `migrate` остановится на seed с просьбой переименовать пользователя — стоп, сообщить разработчику.

### До выкладки (на работающей 1.13.12, до `backup.sh`)

```sql
SELECT (SELECT count(*) FROM tasks) AS tasks,
       (SELECT count(*) FROM tasks WHERE chain_id IS NOT NULL) AS tasks_in_chains,
       (SELECT count(*) FROM task_chains) AS chains,
       (SELECT count(*) FROM users) AS users,
       (SELECT count(*) FROM users WHERE login = 'portal-system') AS portal_login;
```

`portal_login` должен быть 0. Если 1 — стоп, сообщить разработчику до выкладки.

### После `migrate`

1. Вывод `migrate`: «Applying migration `20261113090000_task_chain_system`», затем «Seed выполнен: …», без ошибок.
2. Тот же запрос: `tasks`, `tasks_in_chains`, `chains` — те же числа; `users` — на 1 больше; `portal_login` — 1.
3. `docker compose ps` — backend `healthy`, frontend `Up`. **`./scripts/smoke.sh --after`** — «Smoke-проверка пройдена».
4. **Вручную:** «Задачи» открываются, «Цепочки» открываются. Ничего не собирать: старые автозадачи собирает сотрудник ИБ сам.

### Откат на 1.13.12

Образы backend и frontend: `sed -i 's/^VERSION=.*/VERSION=1.13.12/' .env` и `docker compose up -d backend frontend`. База не откатывается: миграция только добавила колонки. На 1.13.12 системные цепочки видны как обычные (создатель — «Портал»), «Портал» — как отключённый пользователь; доска и цепочки работают (проверено разработчиком). После повторной выкладки 1.14.0 всё вернётся как было.
