### Задачи: перенос в колонку «Поставленные» (этап Б)

Шаг `migrate` перенесёт задачи из колонки «Новые» с исполнителем в новую колонку «Поставленные» (и архивные тоже), «Новые» станет «Backlog», «Готово» — «Выполнено» (если администратор не переименовал их сам). Удалённые задачи не меняются.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT s.value AS колонка, s.system_key AS ключ,
       t.assignee_id IS NOT NULL AS есть_исполнитель,
       t.archived_at IS NOT NULL AS в_архиве,
       count(*) AS задач
FROM tasks t JOIN catalog_items s ON s.id = t.status_id
WHERE t.deleted_at IS NULL
GROUP BY 1, 2, 3, 4 ORDER BY 2, 3, 4;"'
```

- Строки с ключом `new` и `есть_исполнитель = t` — столько задач перейдёт в «Поставленные» (сумма по архиву и не архиву).
- После `migrate` в выводе seed: «Задачи 1.2.0: … в „Поставленные“ перенесено N» — N должно совпасть с этой суммой.

### Задачи: кто ставит и принимает задачи (этап Б)

Супер-администратор не получает права процесса задач; тем, кто ставит и принимает задачи, нужна роль «Начальник ИБ» или роль с `tasks.assign` и `tasks.review`.

После выкладки права `tasks.assign`, `tasks.review`, `tasks.status.override`, `tasks.report` есть только у роли «Начальник ИБ». Кто из активных пользователей сможет ставить задачи другим и принимать их (запрос только читает базу; выполнить после `migrate`):

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT u.login, u.full_name AS фио,
       string_agg(DISTINCT r.name, \$\$, \$\$) AS роли,
       bool_or(rp.permission_code = \$\$tasks.assign\$\$) AS ставит_другим,
       bool_or(rp.permission_code = \$\$tasks.review\$\$) AS принимает
FROM users u
JOIN user_roles ur ON ur.user_id = u.id JOIN roles r ON r.id = ur.role_id
LEFT JOIN role_permissions rp ON rp.role_id = r.id
WHERE u.is_active
GROUP BY 1, 2 ORDER BY 4 DESC, 5 DESC, 1;"'
```

Если у руководителей групп в столбцах `ставит_другим` и `принимает` стоит `f`, администратор портала добавляет им роль «Начальник ИБ» или свою роль с `tasks.assign` и `tasks.review` («Настройки → Роли и права»). Результат — в журнал выкладок.

### Уведомления: первый часовой прогон (этап В)

После выкладки первый часовой прогон пришлёт уведомление «Задача просрочена» по каждой уже просроченной открытой задаче — исполнителю и автору, по одному на задачу. Сколько их будет (только чтение, до выкладки):

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT count(*) AS просроченных_задач,
       count(*) FILTER (WHERE assignee_id IS NOT NULL) AS с_исполнителем,
       count(*) FILTER (WHERE created_by IS NOT NULL AND created_by IS DISTINCT FROM assignee_id) AS ещё_автору
FROM tasks
WHERE deleted_at IS NULL AND archived_at IS NULL AND completed_at IS NULL AND due_date < current_date;"'
```

Уведомлений придёт около `с_исполнителем + ещё_автору` (отключённым пользователям — нет). Если число большое, предупредить отдел заранее.
