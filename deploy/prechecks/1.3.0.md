### Самооценка: что сделает шаг `migrate` (этап Д)

- Одна миграция `20261030044021_assessments`: четыре новые пустые таблицы (`assessment_methodologies`, `assessments`, `assessment_answers`, `assessment_links`), триггер «ответы меняются только в черновике», у роли `ibportal_app` отзываются `DELETE` и `TRUNCATE` на трёх из них. Существующие таблицы и строки не меняются (0 строк).
- Seed: код права `assessment.manage` («Самооценка»), системная роль «Самооценка» **без пользователей**, методика `cyber-express-v1` версии 1, строка подписи презентации `app_settings.presentation.signature` («И. Машарипов · Отдел информационной безопасности») — один раз, изменённую потом не перезаписывает.
- Новых переменных `.env` нет, `docker-compose.yml` не менялся.

### Самооценка: нет ли уже роли с таким названием (до выкладки)

Название роли в портале уникально. Если администратор уже завёл свою роль «Самооценка», seed не сможет создать системную роль и `migrate` завершится ошибкой. Запрос только читает базу:

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT name AS роль, code AS код, is_system AS системная,
       (SELECT count(*) FROM user_roles ur WHERE ur.role_id = r.id) AS пользователей
FROM roles r WHERE name = \$\$Самооценка\$\$ OR code = \$\$assessment\$\$;"'
```

- Ожидается **0 строк**. Если строка есть — до `migrate` переименуйте эту роль в «Настройки → Роли и права» (например, «Самооценка (старая)») и запишите это в журнал выкладок.

### Самооценка: после `migrate`

- В выводе seed: «Самооценка: методика cyber-express-v1 v1 загружена» (при повторном `migrate` строки нет).
- Проверка целостности (в `smoke.sh` не входит, запуск — отдельной командой):

```bash
docker compose run --rm -T --no-deps backend node dist/scripts/check-integrity.js
```

  В выводе — «Целостность в порядке» и среди строк: «право „Самооценка“ есть только у системной роли „Самооценка“», «методика самооценки загружена», «ibportal_app: нет DELETE и TRUNCATE на оценках самооценки».
- Запрос (только чтение) — у роли «Самооценка» одно право и нет пользователей:

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT r.name AS роль, string_agg(rp.permission_code, \$\$, \$\$) AS права,
       (SELECT count(*) FROM user_roles ur WHERE ur.role_id = r.id) AS пользователей
FROM roles r LEFT JOIN role_permissions rp ON rp.role_id = r.id
WHERE r.code = \$\$assessment\$\$ GROUP BY r.id, r.name;"'
```

Ожидается: `Самооценка | assessment.manage | 0`.

### Самооценка: проверка владельцем после выкладки

Выполняет владелец проекта, результат — в журнал выкладок.

1. «Настройки → Пользователи и роли»: назначить роль «Самооценка» **одному** сотруднику (подсказка у роли: «Обычно назначается одному сотруднику»). Изменение попадёт в журнал аудита.
2. Войти этим пользователем → пункт меню «Самооценка» над «Настройками» → «Новая оценка» → название «Экспресс-оценка 2025», «Пустого чек-листа» → «Создать». Затем «Импорт Excel» → выбрать исходный файл «Чек-лист оценки уровня кибербезопасности» (тот же, что `backend/test/fixtures/cyber-checklist-2025.xlsx`). Предпросмотр должен показать: **«Найдено разделов: 24 из 24»**, итог после импорта **34 из 96, «Цифровая гигиена»**, «Скрытые строки пропущены», ошибок нет. «Применить» → на «Обзоре» 34 из 96, домены в «Чек-листе»: 5 / 4 / 5 / 2 / 3 / 5 / 1 / 2 / 6 / 1.
3. Под администратором с правом «Настройки»: «Настройки → Презентация» — строка «Спроектировано» («И. Машарипов · Отдел информационной безопасности»). Под владельцем раздела: «Презентация» — справа внизу на каждом слайде две строки: «Спроектировано: …» и «Подготовил: <ФИО владельца>»; ← → листают 6 слайдов, Esc — выход.
4. Под любым другим пользователем (в том числе «Супер-администратор» и «Начальник ИБ»): пункта «Самооценка» в меню нет; адрес `/assessment` в строке браузера ведёт на главную страницу пользователя.

### Самооценка: откат на 1.2.0

Без отката базы: вернуть `VERSION=1.2.0` в `.env` и `docker compose up -d backend frontend`. Backend 1.2.0 новые таблицы не читает, незнакомый код права `assessment.manage` в сумме прав не учитывает, роль «Самооценка» для него — роль без прав. Оценки, ответы и подпись остаются в базе и снова видны после повторной выкладки 1.3.0. Задачи, поставленные из самооценки, — обычные задачи доски, 1.2.0 работает с ними как с любыми другими.
