Сервер работает на **1.13.4** (или на 1.13.3 — тогда сначала 1.13.4 по его архиву). Если там версия старше, архив собирается с `make-release.sh --from <версия>` и своими предпроверками.

**1.13.5 — меняются образы backend и frontend:** миграций, новых переменных `.env`, прав, seed и данных нет; образ db по содержимому тот же, что в 1.13.4 (`deploy/verification/1.13.5.md`). **Шаг `migrate` не нужен.** Если его всё же выполнили по общей инструкции, он ничего не применяет: «No pending migrations to apply», «Seed выполнен: …». `backup.sh` перед выкладкой обязателен, как всегда.

### Что меняется для пользователей

- «Документы» → ответственные лица: «Добавить ответственных лиц» — несколько человек за раз с одним сроком. Людей выбирают из справочника (список с отметками и поиском, чипы) или вводят вручную строками. Дальше у каждого свой срок, как раньше.

### До выкладки (на работающей 1.13.4, до `backup.sh`)

Изменений данных при выкладке нет. Для сверки после — число неснятых ответственных лиц:

```sql
SELECT count(*) FROM document_parties WHERE removed_at IS NULL;
```

### После выкладки

1. `docker compose ps` — backend `healthy`, frontend `Up`.
2. **`./scripts/smoke.sh --after`** — «Smoke-проверка пройдена», число записей не изменилось.
3. Тот же запрос — то же число (если за время выкладки никто не добавлял лиц).
4. **Вручную (Chrome и Edge на Windows):** документ на этапе «Согласование», под автором — «Добавить ответственных лиц» → «Выбрать из справочника». Список открывается панелью в цветах темы, пробел отмечает, выбранные — чипами. Сама проверка ничего не добавляет: «Отмена».

### Откат на 1.13.4

Образы backend и frontend: `sed -i 's/^VERSION=.*/VERSION=1.13.4/' .env` и `docker compose up -d backend frontend`. Данные и база не меняются. Лица, добавленные пачкой, остаются обычными строками и видны в 1.13.4.
