Сервер работает на **1.11.0**. Если там версия старше, архив собирается с `make-release.sh --from <версия>` и своими предпроверками (`deploy/prechecks/1.12.0-from-<версия>.md`).

**Выкладка — обязательно с `backup.sh` и `migrate`** (шаги 3 и 5 инструкции ниже). Миграций две:
- `20261106130408_awareness_layout` — колонки шапки письма у шаблонов и версий, отметка «Отправлено» с языками, получателями и файлом, таблицы «Оформления писем» и выгрузок;
- `20261106130700_awareness_eml_mime` — тип файла `message/rfc822` (файл `.eml` создаёт только сервер).

Существующие строки миграции не меняют. Строку «Оформления писем» и поля «Рассылок» создаёт seed `awareness.v3` того же `migrate`. Повторный запуск `migrate` безопасен.

### Что меняется для пользователей

- **Учебное письмо — по макету.** Карточка на каждый язык: шапка с логотипом, заголовок и метка, выделенные блоки «Просьба» и «Предупреждение», подпись с адресом ИБ, подвал. RU+TJ — две карточки подряд.
- **«Предпросмотр как в почте»** в письме, шаблоне и на вкладке «Экспорт».
- **«Скачать для Outlook (.eml)»** — письмо открывается в Outlook готовым к отправке, остаётся вставить адреса.
- **«Отметить отправленным»** — с языками, получателями и файлом письма; в «Рассылках» новые поля «Шаблон», «Языки», «Получатели», «Файл письма».
- **«Настройки → Оформление писем»** вместо «Подпись ИБ»: логотип, отдел, адрес ИБ, прощание, подвал, метки; «Подпись ИБ» — там же.

### До выкладки (на работающей 1.11.0, до `backup.sh`)

Запросы только читают базу. Результаты запишите в журнал выкладок.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT (SELECT count(*) FROM awareness_letters) AS писем,
       (SELECT count(*) FROM awareness_letters WHERE frozen) AS отправленных,
       (SELECT count(*) FROM awareness_templates) AS шаблонов,
       (SELECT count(*) FROM awareness_letter_events WHERE action = \$\$sent\$\$) AS отметок_отправлено;
SELECT r.name AS реестр, count(rr.id) FILTER (WHERE rr.deleted_at IS NULL) AS записей
FROM registers r LEFT JOIN register_records rr ON rr.register_id = r.id
WHERE r.system_key = \$\$awareness_mailings\$\$ GROUP BY r.name;
SELECT f.label AS поле_уже_есть FROM register_fields f JOIN registers r ON r.id = f.register_id
WHERE r.system_key = \$\$awareness_mailings\$\$ AND f.deleted_at IS NULL AND f.system_key IS NULL
  AND lower(f.label) IN (\$\$шаблон\$\$, \$\$языки\$\$, \$\$получатели\$\$, \$\$файл письма\$\$);"'
```

- **Писем, отправленных, шаблонов, отметок** — не меняются: миграции добавляют колонки с пустыми значениями. Не стоп.
- **Записей «Рассылок»** — не меняются, у них появятся пустые поля «Шаблон», «Языки», «Получатели», «Файл письма». Реестра нет (удалён) — новые поля не создаются, в выводе `migrate` строка об этом. Не стоп.
- **Поле уже есть** (строки в последнем запросе) — администратор завёл поле с таким названием. Его seed не трогает, новое системное поле получит название «… (системное)». Не стоп; после выкладки можно переименовать или архивировать своё поле.

### После `migrate`

1. **Вывод `migrate`.**
    - применены `20261106130408_awareness_layout` и `20261106130700_awareness_eml_mime`;
    - строка «Учебные письма 1.12.0: «Оформление писем» (заглушки); поля «Рассылки»: «Шаблон», «Языки», «Получатели», «Файл письма»». Если название поля было занято — «… (системное)»; реестра нет — «реестра «Рассылки» нет — новые поля не созданы».
    - «Seed выполнен: …».
2. **`./scripts/smoke.sh --after`.** Строки «✓ учебные письма 1.12.0: …», «✓ «Оформление писем» на месте», «✓ тип файла message/rfc822 допустим», «✓ поля «Рассылок» 1.12.0 … (4)», затем «Smoke-проверка пройдена».
3. **Проверка целостности.** `docker compose run --rm -T --no-deps backend node dist/scripts/check-integrity.js` → «Целостность в порядке» (строки «учебные письма: «Оформление писем» на месте», «файл отметки «Отправлено» — выгрузка этого письма»).
4. **Повтор запросов «До выкладки»** — писем, шаблонов, отметок и записей «Рассылок» столько же.
5. **Вручную:**
    - «Настройки → Оформление писем»: загрузить логотип, указать название отдела, адрес ИБ, подвал. Это данные банка — только на проде, через интерфейс.
    - «Осведомлённость → Письма» → любое письмо → «Экспорт»: предпросмотр как в почте открывается, «Скачать для Outlook (.eml)» скачивает файл.

### Откат на 1.11.0

Только код: `sed -i 's/^VERSION=.*/VERSION=1.11.0/' .env` и `docker compose up -d backend frontend`. База не восстанавливается.
- **Учебные письма 1.12.0 после отката:**
    - новые колонки и таблицы прежняя версия не читает;
    - письма открываются, экспорт — прежнего вида (без макета);
    - поля «Шаблон», «Языки», «Получатели», «Файл письма» в «Рассылках» остаются обычными полями реестра, сохранённые `.eml` скачиваются вложением.
