Сервер работает на **1.13.1** (выложена 09.11.2026 с 1.9.0; 1.13.2 туда не выкладывалась — её изменения входят в 1.13.3). Если там версия старше, архив собирается с `make-release.sh --from <версия>` и своими предпроверками.

**Выкладка — обязательно с `backup.sh` и `migrate`.** Миграция одна: `20261109120000_awareness_letter_deleted` — колонка `deleted_at` у учебных писем. **Влияние на данные:** одна новая колонка (NULL у всех), существующие письма не меняются (0 строк). Шаг seed `rbac.permissions.v1_13_3` один раз выдаёт новое право «Осведомлённость: удаление писем» (`awareness.delete`) системным ролям «Супер-администратор» и «Начальник ИБ» (запись в журнале). Новых переменных `.env` и зависимостей нет. Откат на 1.13.1 — только код.

### Что меняется для пользователей

- **Удаление учебных писем:** письмо в архиве, ни разу не отмеченное отправленным, можно удалить (карточка → «Удалить» → подтверждение) — право есть у начальника ИБ и супер-администратора. Отправленное удалить нельзя.
- **Задачи:** карточки на доске без наложения (1.13.2), значок комментариев крупнее, число читается.
- **Кнопки справа внизу** на дашборде и страницах-списках: «Обновить», «В самый верх», «В самый низ»; колонка доски больше не «держит» прокрутку страницы.
- **«Новое письмо»** — с выбором шаблона; нет шаблонов — «Шаблонов пока нет» и «Создать шаблон» (1.13.2).

### До выкладки (на работающей 1.13.1, до `backup.sh`)

Запросы только читают базу. Результаты запишите в журнал выкладок.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT count(*) AS писем, count(*) FILTER (WHERE archived_at IS NOT NULL) AS в_архиве,
       count(*) FILTER (WHERE frozen) AS отправленных,
       count(*) FILTER (WHERE archived_at IS NOT NULL AND NOT frozen) AS можно_будет_удалить
FROM awareness_letters;
SELECT count(*) AS колонка_уже_есть FROM information_schema.columns
WHERE table_name = \$\$awareness_letters\$\$ AND column_name = \$\$deleted_at\$\$;
SELECT r.name AS роль, count(rp.permission_code) AS прав FROM roles r LEFT JOIN role_permissions rp ON rp.role_id = r.id
WHERE r.code IN (\$\$super_admin\$\$, \$\$ib_head\$\$) GROUP BY r.name ORDER BY r.name;"'
```

- **Писем, в архиве, отправленных** — не меняются. Не стоп.
- **Колонка уже есть** — ожидается 0 (миграция ещё не применялась). Не стоп, если 1: `migrate` сообщит «No pending migrations».
- **Прав у ролей** — после `migrate` у каждой из двух ролей станет на одно больше (если администратор не правил роли раньше). Не стоп.

### После `migrate`

1. **Вывод `migrate`.** Применена миграция `20261109120000_awareness_letter_deleted`; «Seed выполнен: прав 22, …».
2. **`./scripts/smoke.sh --after`** — «Smoke-проверка пройдена».
3. **Проверка целостности.** `docker compose run --rm -T --no-deps backend node dist/scripts/check-integrity.js` → «✓ учебные письма: удалены только архивные и неотправленные», «Целостность в порядке».
4. **Повтор запросов.** Писем, в архиве, отправленных — столько же; «колонка_уже_есть» — 1; прав у «Супер-администратора» и «Начальника ИБ» — на одно больше.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT count(*) FILTER (WHERE deleted_at IS NOT NULL) AS удалённых FROM awareness_letters;
SELECT r.name AS роль FROM roles r JOIN role_permissions rp ON rp.role_id = r.id
WHERE rp.permission_code = \$\$awareness.delete\$\$ ORDER BY r.name;"'
```

Ожидается: удалённых — 0; роли с правом — «Начальник ИБ» и «Супер-администратор».

5. **Вручную.** Вход; «Задачи» — у карточек виден счётчик комментариев, справа внизу «Обновить» и «В самый низ»; «Осведомлённость → Письма» → «Архив» → неотправленное письмо → «Удалить» видна у начальника ИБ.
