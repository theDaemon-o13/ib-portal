### Что сделает шаг `migrate`

1. **Миграция `20261103105246_document_stage_tasks`**: новая колонка `tasks.document_state` (NULL у всех строк), проверка `tasks_document_check` принимает причину задачи `stage`. Существующие строки не меняются.
2. **Seed — задачи этапов для документов, которые уже на маршруте**: тот, кто сейчас действует на этапе («Сейчас у»), получает задачу категории «Документы»; документы на «Проверке сотрудниками» — ещё всем активным сотрудникам ИБ, кроме автора. В выводе: «Документы: задачи этапов маршрута — документов в работе N, создано задач M» (строки нет, если создавать нечего). Повторный `migrate` задач не дублирует.
3. Остальной seed — как в 1.6.1: «Seed выполнен: прав 21, …».

Новых переменных `.env` нет, `docker-compose.yml` и скрипты не менялись.

### До выкладки (на работающей версии, до `backup.sh`)

**Сколько задач создаст seed** — документы на маршруте по этапам и активные сотрудники ИБ (запрос только читает базу):

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT v.stage AS этап, count(*) AS документов
FROM documents d JOIN document_versions v ON v.id = d.working_version_id
WHERE d.deleted_at IS NULL AND d.archived_at IS NULL AND v.cancelled_at IS NULL GROUP BY v.stage ORDER BY v.stage;" -c "
SELECT count(DISTINCT u.id) AS сотрудников_ИБ FROM users u JOIN user_roles ur ON ur.user_id = u.id
JOIN role_permissions rp ON rp.role_id = ur.role_id WHERE u.is_active AND rp.permission_code = \$\$ib.work\$\$;"'
```

Ожидание: задач ≈ документы на этапах 13–16 (по одной, на 15 — по одной на начальника ИБ и каждого старшего над автором) + документы на этапе 12 × число сотрудников ИБ. Этап 11 задач не даёт (только новые документы, заведённые за другого владельца). Числа — в журнал выкладок.

### После `migrate`

1. **Вывод seed** — строка «Документы: задачи этапов маршрута …» сходится с числами выше.
2. **Проверка целостности** (`docker compose run --rm -T --no-deps backend node dist/scripts/check-integrity.js`) — «Целостность в порядке».
3. **В интерфейсе:**
   - «Задачи», категория «Документы» — задачи этапов с описанием «Документ / Тип / Этап / Что требуется», в карточке — «этап маршрута» и ссылка на документ;
   - «Настройки → Параметры портала» (супер-администратор) — «Документы: сроки этапов»: 5 / 3 / 3 / 3 / 5 рабочих дней; поменять при необходимости.

### Откат на 1.6.1

**Способ 2 (только код)** — с одним запросом **перед** сменой версии: backend 1.6.1 не знает причины задачи `stage`, без запроса список задач отвечает ошибкой.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
UPDATE tasks SET document_reason = \$\$returned\$\$, document_state = NULL WHERE document_reason = \$\$stage\$\$;"'
sed -i 's/^VERSION=.*/VERSION=1.6.1/' .env
docker compose up -d backend frontend
./scripts/smoke.sh
```

Задачи этапов остаются и видны в 1.6.1 как «доработка после возврата» (решение владельца 03.11.2026). Колонка `document_state` и расширенная проверка 1.6.1 не мешают. Повторная выкладка 1.6.3: seed снова создаст задачи текущих этапов.

**Способ 1** (резервная копия перед `migrate`, образы 1.6.1) — состояние до обновления полностью; данные после обновления теряются.
