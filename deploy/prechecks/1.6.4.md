Сервер работает на **1.6.3**. Если там ещё 1.6.1 или 1.6.2, сначала выложите 1.6.3 по его RELEASE.md, затем 1.6.4.

### Что сделает шаг `migrate`

1. **Миграция `20261103123203_task_candidates`**: новая пустая таблица `task_candidates` — кто может взять общую задачу. Существующие строки не меняются.
2. **Seed, один раз (`docs.stage_tasks.group.v1`)**: задачи «Проверить документ» из 1.6.3, по одной на каждого сотрудника ИБ, уходят в архив. Открытые перед этим закрываются системой. Задачи автора («Учесть комментарии») и задачи других этапов не трогаются. Архив мягкий: задачи остаются в «Задачи → Архив». В выводе: «Документы: задачи проверки сотрудниками по одной на сотрудника — в архив N (открытых M)».
3. **Seed, при каждом запуске**: документы на «Проверке сотрудниками» получают одну общую задачу «Проверить документ» со списком «Могут взять». В выводе: «Документы: задачи этапов маршрута — документов в работе K, создано задач L».
4. Остальной seed — как в 1.6.3: «Seed выполнен: прав 21, …».

Новых переменных `.env` нет, `docker-compose.yml` и скрипты не менялись.

### До выкладки (на работающей 1.6.3, до `backup.sh`)

**Сколько задач «Проверить» уйдёт в архив** (только чтение; числа — в журнал выкладок):

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT count(*) AS всего, count(*) FILTER (WHERE t.completed_at IS NULL) AS открытых
FROM tasks t JOIN documents d ON d.id = t.document_id
WHERE t.document_reason = \$\$stage\$\$ AND t.document_state LIKE \$\$%:12\$\$
  AND t.assignee_id IS DISTINCT FROM d.owner_id AND t.archived_at IS NULL AND t.deleted_at IS NULL;"'
```

Числа должны совпасть со строкой seed из пункта 2.

### После `migrate`

1. **Вывод seed** — строки из пунктов 2–3 сходятся с числами выше.
2. **Проверка целостности** — `docker compose run --rm -T --no-deps backend node dist/scripts/check-integrity.js` → «Целостность в порядке».
3. **Действие владельца — роль проверки.** «Настройки → Параметры портала → Документы: роль проверки сотрудниками» (супер-администратор): выбрать роль, например «Стар. сотрудник ИБ». Пока роль не выбрана, в списке «Могут взять» все сотрудники ИБ, но задача одна. Списки уже открытых задач обновятся при следующем действии с документом.
4. **В интерфейсе:**
   - на доске задач нет задач «Проверить» на каждого; у общей задачи на карточке — «могут взять: …»;
   - «Задачи → Отчёт» (право «Задачи: отчёт») — цифры, иллюстрации и список выполненных задач;
   - «Импорт отчёта KSC» в реестре «Хосты» открывает окно «Как загружать отчёты KSC»;
   - щелчок по версии внизу меню — окно с версией и автором.

### Откат на 1.6.3

**Способ 2 (только код)** совместим: 1.6.3 не читает `task_candidates`. При первом действии с документом на проверке 1.6.3 закроет общую задачу и снова раздаст «Проверить» каждому сотруднику ИБ. Задачи, ушедшие в архив, останутся в архиве.

**Способ 1** (резервная копия перед `migrate`, образы 1.6.3) — состояние до обновления полностью; данные после обновления теряются.
