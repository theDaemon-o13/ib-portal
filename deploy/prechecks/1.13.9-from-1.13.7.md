Сервер на **1.13.7**. На проде пока 1.13.6: сначала выложить 1.13.7 по её архиву и `1.13.7-devops.txt`, затем этот. Если сервер старше, архив собирается с `make-release.sh --from <версия>` и своими предпроверками.

**1.13.9 — меняются образы backend и frontend:** миграций, новых переменных `.env`, прав и seed нет. Образ db по содержимому тот же, что в 1.13.7 (`deploy/verification/1.13.9.md`). **Шаг `migrate` не нужен.** Если его всё же выполнили по общей инструкции, он ничего не применит: «No pending migrations to apply», «Seed выполнен: …». `backup.sh` перед выкладкой обязателен, как всегда.

### Что меняется для пользователей

- «Уязвимости», импорт скана: большие отчёты (тысячи находок, сервер Linux) загружаются. Раньше «Загрузить» отвечал «Внутренняя ошибка сервера».
- Отчёт Linux: «Вектор» и «Описание (из CVE, англ.)» распознаются; «Задача №» — серой строкой «не используется».
- На кнопке «Загрузить» во время загрузки — «Загружается…». Второй импорт в тот же тип систем, пока идёт первый, — «В этот узел уже идёт импорт».
- Сбой импорта: «Импорт не завершён, ничего не записано. Сообщите администратору номер запроса <номер>». По номеру строка ищется в `docker compose logs backend | grep <номер>`.
- Вкладки, открытые до выкладки, работают. Новая надпись на кнопке появится после обновления страницы (F5).

### Данные

- Схема не меняется, существующие строки не меняются.

### До выкладки (на работающей 1.13.7, до `backup.sh`)

```sql
SELECT count(*) AS vuln_records FROM vuln_records;
SELECT count(*) AS scans FROM vuln_scans;
SELECT count(*) AS vector_values FROM register_field_options o JOIN register_fields f ON f.id = o.field_id
  JOIN registers r ON r.id = f.register_id WHERE r.system_key = 'vulns' AND f.label = 'Сетевой вектор';
```

### После выкладки

1. `docker compose ps` — backend `healthy`, frontend `Up`.
2. **`./scripts/smoke.sh --after`** — «Smoke-проверка пройдена», число записей не изменилось.
3. Те же запросы — те же числа: выкладка данные не меняет.
4. **Вручную:** «Уязвимости» → любой тип систем → «Импорт скана» → выбрать отчёт → предпросмотр открывается. Нажать «Отмена»: ничего не записывается.
5. Отчёт на 3390 находок, который раньше падал, загружает сотрудник ИБ в рабочем порядке. Ожидаемо — секунды. Число новых записей — как в предпросмотре.

### Откат на 1.13.7

Образы backend и frontend: `sed -i 's/^VERSION=.*/VERSION=1.13.7/' .env` и `docker compose up -d backend frontend`. База не меняется. Сканы, загруженные на 1.13.9, на 1.13.7 видны как обычно: строки те же. Большой отчёт на 1.13.7 снова не загрузится.
