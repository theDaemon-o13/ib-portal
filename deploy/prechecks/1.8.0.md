Сервер работает на **1.7.0**. Если там версия старше, сначала выложите 1.7.0 по его RELEASE.md, затем 1.8.0.

**Выкладка — обязательно с `migrate`** (шаг 5 инструкции ниже). Без него у 1.8.0 не будет реестров «Осведомлённости» и служебной роли: импорт INDIGO, виджеты и «Администратор портала» не заработают, а `smoke.sh` и `check-integrity` покажут ошибку. `migrate` — одна команда: сначала миграции, затем seed одной транзакцией. Если команда завершилась ошибкой, seed не применился целиком. Тогда не поднимайте backend, а устраните причину из сообщения и повторите `migrate`. Повторный запуск безопасен: однократные шаги отмечены и второй раз не выполняются.

### Что сделает шаг `migrate`

1. **Миграция `20261104180702_text_dimension`.** Ограничение `register_fields_analytics_check` пересоздаётся с более широким условием: текстовое поле может быть «измерением». Строки не меняются.
2. **Seed: роль «Администратор портала»** (код `portal_admin`, права «Справочники» и «Пользователи и роли»). Никому не назначается. В выводе: «Создана роль «Администратор портала»».
3. **Seed, один раз (`awareness.v1`):**
    - пустые системные реестры «Сотрудники» (полей 9) и «Результаты INDIGO» (полей 16);
    - пороги оценки `awareness.grades`: «Отлично» от 90 %, «Хорошо» от 70 %, «Удовлетворительно» от 50 %, пересдача ниже 50 %.

   В выводе: «Осведомлённость: реестры «Сотрудники» (полей 9) и «Результаты INDIGO» (полей 16), пороги оценки». Если свой реестр «Сотрудники» уже был — «Сотрудники (системный)».
4. Остальной seed — как в 1.7.0: «Seed выполнен: прав 21, системных ролей 8, …».

Новых переменных `.env` нет. `docker-compose.yml` не менялся. В `scripts/smoke.sh` добавлена проверка системных объектов: роли и двух реестров по коду, порогов оценки.

### До выкладки (на работающей 1.7.0, до `backup.sh`)

Запросы только читают базу. Результаты запишите в журнал выкладок.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT \$\$роль с названием «Администратор портала»\$\$ AS что, count(*) FROM roles WHERE lower(name) = lower(\$\$Администратор портала\$\$)
UNION ALL SELECT \$\$реестр «Сотрудники» или «Результаты INDIGO»\$\$, count(*) FROM registers
  WHERE archived_at IS NULL AND lower(name) IN (lower(\$\$Сотрудники\$\$), lower(\$\$Результаты INDIGO\$\$));"'
```

- **Роль: больше 0 — стоп.** Это своя роль с названием новой системной. Переименуйте её в «Настройки → Пользователи и роли», затем выкладывайте. Иначе `migrate` остановится с сообщением «уже есть роль …: переименуйте её …», ничего не применив.
- **Реестр: больше 0 — не стоп.** Свой реестр не трогается, а системный получит название «Сотрудники (системный)» или «Результаты INDIGO (системный)». Переименовать любой из них можно после выкладки.

### После `migrate`

1. **Вывод `migrate`.** Миграция `..._text_dimension` применена, есть строки из пунктов 2–4 выше, команда завершилась без ошибки.
2. **`./scripts/smoke.sh --after`.** Строки «✓ роль «Администратор портала» …», «✓ реестр «Сотрудники» …», «✓ реестр «Результаты INDIGO» …» и «✓ пороги оценки …», затем «Smoke-проверка пройдена». Если вместо «✓» стоит «✗ … найдено 0», значит `migrate` не выполнен или прерван: повторите шаг 5.
3. **Проверка целостности.** `docker compose run --rm -T --no-deps backend node dist/scripts/check-integrity.js` → «Целостность в порядке».
4. **В интерфейсе:**
    - в «Реестрах» есть «Сотрудники» и «Результаты INDIGO»; в «Результатах INDIGO» — кнопки «Импорт отчёта INDIGO» и «Обновить по сотрудникам…»;
    - на дашборде — виджет «На пересдачу» (0);
    - «Настройки → Параметры портала → Осведомлённость: пороги оценки» — 90, 70, 50 и пересдача ниже 50;
    - в «Роли и права» — роль «Администратор портала».
5. **Действие владельца, по желанию.** Завести служебного администратора: новый пользователь только с ролью «Администратор портала». Вход — с адресов `ADMIN_ALLOWED_IPS`. Порядок загрузки данных: сначала выгрузка HR в «Сотрудники», затем отчёты INDIGO (`docs/user-guide.md`, «Осведомлённость»).

### Откат на 1.7.0

**Сначала отключите служебных пользователей**, при любом способе отката. 1.7.0 о роли «Администратор портала» не знает:
- её держатель увидит подписанные документы, как пользователь без доступа к разделам ИБ;
- в 1.7.0 роль можно совместить с другой и переименовать.

Кто это (запрос только читает базу):

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d ibportal -c "
SELECT u.login, u.full_name, u.is_active FROM users u JOIN user_roles ur ON ur.user_id = u.id JOIN roles r ON r.id = ur.role_id
WHERE r.code = \$\$portal_admin\$\$ ORDER BY u.login;"'
```

Для каждого с `is_active = t`: «Настройки → Пользователи и роли» → пользователь → «Отключить». Роль и её строки в базе остаются, удалять их не нужно. После повторной выкладки 1.8.0 включите этих пользователей снова, пароль сохраняется.

**Способ 2 (только код)** совместим: база остаётся от 1.8.0.
- 1.7.0 видит «Сотрудников» и «Результаты INDIGO» как обычные реестры, без импорта INDIGO и системных виджетов.
- Текстовое поле с ролью «измерение» показывается пустым распределением; снять роль можно.
- `smoke.sh` при `VERSION=1.7.0` системные объекты 1.8.0 не проверяет.

При повторной выкладке 1.8.0 seed реестры заново не создаёт: отметка `awareness.v1` уже стоит.

**Способ 1** (резервная копия перед `migrate`, образы 1.7.0) возвращает состояние до обновления полностью. Данные, внесённые после обновления, теряются.
