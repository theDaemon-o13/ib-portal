Значения записей не меняются. Откат: снять признак в настройках поля; backend 1.0.1 признак не читает и работает с лимитом 4000.

### Изменено
- Импорт отчёта сканера (правило 6 CLAUDE.md): дубли — по «CVE + пакет + отдел»; отчёт одного отдела не сливается с записями другого и не меняет их «Обнаружений». «Обнаружений» у совпавшей записи — из нового отчёта (14 → 3 — обновление; пусто — прежнее значение), по максимуму — только дубли внутри одного файла. Записи без отдела в дублях не участвуют. Отчёт без отдела в A1 загружается только после выбора отдела в окне импорта (известный или новый) — повторная загрузка такого отчёта дублей не создаёт.
- Удаление правила автоматизации, по которому уже были события, больше не запрещено: удаление мягкое (`deleted_at`), события и задачи сохраняют ссылку на правило. Системные правила по-прежнему не удаляются.
- Удаление записи реестра стало строже: запись с открытыми задачами или со ссылками из других записей (поле «Связь с записью», например разрешение DLP → устройство) удалить нельзя — только в архив, как запись с решениями или доказательствами. Раньше такая запись удалялась. При попытке удалить портал отвечает с причиной; чтобы удалить запись, сначала закройте или удалите её задачи. Правило одно для одиночного и массового удаления.
- Логи backend: пароли (`password`, `currentPassword`, `newPassword`, `temporaryPassword`) вырезаются, даже если тело запроса попадёт в лог; тесты проверяют, что пароль не попадает в логи, журнал аудита и тексты ошибок.

### Исправлено
- e2e «Документы»: дата пересмотра считается по часовому поясу банка, как на backend; на машине в UTC тест падал с 19:00 до 24:00 UTC.
- RELEASE.md: на шаге `migrate` контейнер db перезапускается с образом новой версии (тег образа db меняется с версией) — раньше было написано «db не перезапускается». Данные — в томе, перерыв — несколько секунд.
- e2e «Устройства DLP»: кнопка «Отвязать» ожидается, а не проверяется сразу после загрузки файла (нестабильное падение).

## [1.0.0] — 2026-10-28

Первая версия для рабочего контура банка. Портал ИБ работает на закрытом хосте без интернета и внешних интеграций: конструктор реестров (уязвимости с импортом отчёта сканера и сроками по п. 7.1–7.4, риски ИБ с решениями ОУР, устройства DLP, разрешения на доступ с PDF, инциденты, свои реестры), импорт и экспорт Excel, автоматизации «условие → действие» с задачами, доска задач и «Почта → задача» вставкой текста, документы с маршрутом согласования и итоговым PDF, доказательная база с формами по шаблонам и просмотром файлов, глобальный поиск (в том числе по тексту PDF), дашборд и экран настенного монитора, пользователи и роли (RBAC), журнал аудита.

**Установка — с нуля** по `docs/deploy.md` в архиве. Обязательные переменные `.env`: пароли БД, `SESSION_SECRET`, **`PORTAL_URL`** (адрес портала; без него backend не стартует), подсети `FRONT_SUBNET`/`BACK_SUBNET`, согласованные с сетевым отделом. Рекомендуется задать `ADMIN_ALLOWED_IPS` (рабочие места администраторов — вместо MFA, ADR-0015), для настенных мониторов — `MONITOR_ALLOWED_IPS`, для документов — `ONLYOFFICE_URL_PREFIX`.

**Проверено перед выпуском:** e2e (51 сценарий) на образах релиза через nginx; заголовки безопасности и TLS 1.2/1.3; образы без исходников и dev-зависимостей, процессы не от root; резервная копия, ротация и восстановление в отдельном проекте; нагрузка — 20 000 уязвимостей, 5 000 задач, 2 000 устройств, 1 000 разрешений с PDF: экраны и поиск до 0,5 с, zip-выгрузка — около 1 с.

**Известные ограничения:** выгрузка Excel 20 000 записей — 5–6 с (ускорение в 1.0.1); 4 уязвимости high во вспомогательных зависимостях Prisma CLI не эксплуатируются, риск принят, обновление в 1.0.1 (ADR-0014); MFA не делается (ADR-0006 отклонён).

### Подготовка к первой выкладке (28.10.2026)

### Добавлено
- Вход администраторов только с рабочих мест: пользователь с правами «Настройки» или «Пользователи, роли и права» входит только с адресов из новой переменной `ADMIN_ALLOWED_IPS` (IP и подсети через запятую; пусто — без ограничения). С другого адреса — «Неверный логин или пароль», причина в журнале аудита; уже открытая сессия с чужого адреса закрывается, в том числе если права выдали после входа. `create-admin` из консоли сервера работает без ограничения (ADR-0015).

### Изменено
- Prisma 7.10.0 вместо 6.16.2 (ADR-0014): клиент через драйвер-адаптер `@prisma/adapter-pg` и `pg` 8.23.1, генерируется в `backend/src/generated/prisma` (в git не попадает), адрес БД — в `backend/prisma.config.ts`. Схема и миграции не менялись (`check:schema` без расхождений).
- Ссылка на файл документа в OnlyOffice принимается, только если начинается с адреса сервера OnlyOffice банка — новая переменная `ONLYOFFICE_URL_PREFIX` (тот же протокол, сервер и порт, путь с указанного; пусто — любая ссылка http(s), как раньше). Уже сохранённые ссылки не проверяются (ADR-0010).
- Утвердить версию документа без итогового PDF нельзя и в БД — триггер `document_versions_require_pdf` (сервис проверяет это с этапа 7, ADR-0011).
- Правило автоматизации ссылается на метку получателя только по id; название берётся из справочника. Правило с меткой по названию API больше не принимает (интерфейс всегда присылал id) — «сужение» после ADR-0009.
- MFA (TOTP) для привилегированных учётных записей не делается: ADR-0006 отклонён 28.10.2026 (портал работает только во внутренней сети). Компенсирующая мера — `ADMIN_ALLOWED_IPS` (ADR-0015). Шаблон формы «Парольная защита» не менялся.
- **Новая обязательная переменная `PORTAL_URL`** — адрес портала, как его открывают пользователи (`https://имя[:порт]`). Изменяющий запрос из браузера принимается, только если его `Origin` совпадает с этим адресом (раньше — с заголовком `Host`, который присылает сам клиент). Без `PORTAL_URL` backend не стартует и пишет в журнал, что задать; `http://` — только вне production. Портал, открытый по другому адресу (по IP, по другому имени), не даст сохранить изменения (ADR-0001).
- Заголовки безопасности (HSTS, `nosniff`, `X-Frame-Options`, `Referrer-Policy`, CSP) — у всех ответов nginx, в том числе у файлов сборки `/assets/` (раньше там был только `nosniff`); общий набор — в одном файле, подключается в каждый location. 404 из `/assets/` не кешируется на год.
- Страница портала, открытая по другому адресу (по IP, по другому имени), перенаправляется (301) на `PORTAL_URL`: nginx получает переменную и строит правило при старте контейнера; `/api` и `/assets` не перенаправляются.
- После входа портал возвращает только на внутреннюю страницу портала: путь вида `//сайт` или с `\` из ссылки игнорируется (смягчение уязвимости react-router 6 GHSA-wrjc-x8rr-h8h6, moderate; исправление — только в react-router 7).
- Образ backend меньше на ~150 МБ (833 → 677 МБ): без сред выполнения клиента Prisma для других СУБД, source map и типов TypeScript; без исходников seed и инструментов разработки (`test-db`, `check-schema`, `export-openapi`). `make-release.sh` проверяет содержимое образов (нет исходников, `.env`, dev-зависимостей и source map; процессы не от root) и печатает их размеры.
