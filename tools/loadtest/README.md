# Нагрузочная проверка (этап 5 подготовки к 1.0.0)

Только на машине разработчика, на проверочном стенде `ibportal-releasetest` (релизные образы, свои тома). На сервер не передаётся.

```bash
tools/loadtest/fill.sh <каталог deploy стенда>      # данные «за 3 года» прямо SQL: ~20 с
NODE_EXTRA_CA_CERTS=<certs/portal.crt стенда> E2E_LOGIN=… E2E_PASSWORD=… node tools/loadtest/measure.mjs
```

Объём: уязвимости 20 000, задачи 5 000, устройства DLP 2 000, разрешения на доступ 1 000 с PDF (текст PDF — в `file_texts`, как после извлечения).

Порог для оптимизации в 1.0.0 — 5 с (решение владельца проекта). Всё, кроме выгрузки Excel, — до 1,2 с.

**Выгрузка Excel 20 000 уязвимостей — 5,2–5,7 с.** Профиль: ~60% — объектная модель exceljs и сжатие zip на JS (pako); чтение и расчёт записей — меньше секунды. Сжатие «уровень 1» даёт −0,4 с при +30% к размеру файла — не принято. Предложение на 1.0.1: потоковая запись (`ExcelJS.stream.xlsx.WorkbookWriter`, сжатие нативным zlib) — ожидается в 2–3 раза быстрее и без пика памяти; проверить, что сохраняются скрытый лист `_поля`, заметки в заголовке и закрепление строки.
